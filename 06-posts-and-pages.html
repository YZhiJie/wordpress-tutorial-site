第 6 章 文章与页面 🟢 ​

一句话导览：文章（Post）与页面（Page）是 WordPress 的两类核心内容，本章带你从数据库表结构理解它们的本质差异，并彻底吃透编辑器外围的发布、状态、修订、摘要等全部功能。

学完第 5 章，你已经熟悉了后台的整体布局。从本章开始，我们正式进入「内容生产」环节。很多新手建站半年后仍会纠结：这个内容到底该发成文章还是页面？定时发布为什么不生效？修订版本为什么有几十条？本章会把这些问题一次性讲透。

学习目标 ​

  • 从 wp_posts 表的视角理解 WordPress 的统一内容模型，说清文章、页面、修订版本、附件之间的关系。
  • 能用决策树判断任意一块内容应该使用「文章」还是「页面」，并能规划企业站的页面树。
  • 完整掌握文章编辑器外围功能：状态与可见性、定时发布、草稿、预览、别名、修订版本、自动保存。
  • 理解摘要（Excerpt）、<!--more--> 与「阅读更多」区块的区别，会使用置顶文章。
  • 熟练使用全部文章列表的筛选、快速编辑、批量编辑与回收站，并了解 Trackback、文章形式等历史功能的现状。
  • 能写出 SEO 友好的固定链接别名，并独立排查定时发布失败、修订过多等常见问题。

6.1 从数据库理解内容模型 ​

原理说明：万物皆 post ​

WordPress 有一个让初学者意外、但让开发者赞叹的设计：系统里几乎所有内容都存在同一张数据库表 wp_posts 中。一篇博客文章、一个「关于我们」页面、一张图片的附件记录、甚至每次保存产生的修订版本，本质上都是 wp_posts 表里的一行记录，区别只在于 post_type（内容类型）字段的值不同。

wp_posts 表的简化结构如下（实际还有更多字段）：

字段含义典型值
ID内容唯一编号1、128
post_author作者用户 ID1
post_date发布时间2026-10-04 09:30:00
post_content正文（区块编辑器里是含 wp: 注释标记的 HTML）长文本
post_title标题公司简介
post_excerpt手动摘要短文本
post_status状态publish、draft
comment_status是否允许评论open、closed
ping_status是否允许 pingbackopen、closed
post_password访问密码（为空表示无密码）空或密码哈希
post_name别名（slug，用于 URL）about-us
post_type内容类型post、page、attachment、revision
post_parent父级内容 ID（页面层级、附件归属都靠它）0 表示无父级
menu_order排序序号（页面常用）0、5

post_status（状态）的常见取值：

状态值中文含义谁能看到
publish已发布所有人
draft草稿仅有权限的登录用户
pending待审核编辑、管理员可见，等待审核
private私密仅登录且有权限的用户（编辑以上角色）
future定时（未来发布）到时间后由系统转为 publish
trash回收站后台可见，到期自动删除
inherit继承修订版本、附件使用，跟随父内容状态
auto-draft自动草稿新建文章时系统预生成的空白记录

内置的几种 post_type：

post_type对应后台功能说明
post文章按时间流组织的常规内容
page页面层级化的常青内容
attachment媒体附件上传的每个文件在表里都有一条记录，详见第 8 章
revision修订版本每次保存的历史快照，post_parent 指向正文
nav_menu_item菜单项外观 → 菜单里的每一项（存在专门的分类体系中）
custom_css自定义 CSS定制器中编写的附加 CSS

这个统一模型的好处是：插件可以注册自己的内容类型（自定义文章类型，CPT），比如商品、课程、房源，它们与文章共享同一套保存、编辑、权限机制。这就是第 27 章「自定义文章类型与分类法」的基础——你现在理解了 post_type 字段，将来学习 CPT 时只需一句话：注册一个新的 post_type 值而已。

操作方法：直观感受「万物皆 post」 ​

  1. 打开本地站点的数据库管理工具（如 phpMyAdmin 或 TablePlus），进入 WordPress 数据库。
  2. 找到 wp_posts 表（表前缀以你安装时设置的为准，不一定是 wp_），点击浏览。
  3. 观察表中记录：后台示例的「隐私政策示例页面」post_type 为 page；你写的第一篇文章为 post。
  4. 上传一张图片后回到此表刷新，能看到一条 post_type 为 attachment 的记录——注意，图片文件本身不在这里，这里只有文件的路径、标题、替代文本等「引用信息」。
  5. 编辑一篇文章并保存两次，会出现 post_type 为 revision 的记录，其 post_parent 等于正文的 ID。

常见问题 ​

  • 问：直接改数据库里的 post_status 安全吗？ 答：学习理解可以，日常操作请务必走后台。数据库中还有序列化数据、对象缓存等关联因素，直接改库容易造成不一致。
  • 问：文章 ID 为什么不连续？ 答：自动草稿、修订版本、附件、菜单都会占用自增 ID，回收站清空后 ID 也不会复用，属于正常现象。

6.2 文章与页面：系统对比与选择 ​

原理说明 ​

文章（Post）与页面（Page）都是 wp_posts 里的行，字段完全相同，但使用场景与前台行为被设计成两种性格：

对比维度文章（Post）页面（Page）
组织方式按发布时间倒序排列，像「时间流」层级结构，可设父级/子级，像「树」
分类与标签有分类目录、标签没有分类和标签
博客首页/Feed默认出现在「文章页」和 RSS Feed 中默认不出现在文章流和 Feed 中
时效性时效性内容：新闻、教程、动态常青内容：关于、联系方式、服务介绍
URL 结构（常见固定链接）/?p=123 或 /2026/10/hello//about-us/、/products/wordpress-hosting/
作者与日期通常显示作者、发布日期通常不显示作者与日期
评论默认开放评论默认关闭评论（仍可手动开）
模板能力由 single.php/区块模板统一控制可逐页选择「页面模板」（见第 24 章）
典型数量几十到几千篇通常几个到几十个
典型例子《WordPress 定时发布失败怎么办》关于我们、联系方式、服务条款、隐私政策

一句话记忆：会过期、需要被持续更新流推送的内容用文章；长期有效、属于站点骨架的内容用页面。

选择决策树 ​

拿到一块内容不知道怎么选时，按顺序回答：

  1. 它是你希望访客「此刻知道的新消息」吗？是 → 文章。
  2. 它是网站基本信息，半年后仍然有效吗？是 → 页面。
  3. 它需要归属到某个分类、出现在博客列表里吗？是 → 文章。
  4. 它需要挂在某个页面下面形成「关于 → 发展历程」的层级吗？是 → 页面。
  5. 仍然纠结？问自己：「它出现在 RSS 订阅里合理吗？」合理 → 文章；不合理 → 页面。

注意：页面也不是「更高级的文章」。页面之间没有时间顺序，前台也没有「最新页面」流，滥用页面承载博客内容会让老内容永远沉底、无法归档。

操作方法：新建一篇文章与一个页面 ​

  1. 后台左侧菜单点击「文章 → 写文章」（Posts → Add New Post），进入区块编辑器。
  2. 在标题区输入标题，在正文区点击「+」或直接输入文字开始写作（区块编辑器的完整用法见第 7 章）。
  3. 新建页面则点击「页面 → 新建页面」（Pages → Add New Page），界面几乎一样，区别只在右侧设置面板：文章有「分类」「标签」面板，页面有「页面属性」面板。

常见问题 ​

  • 问：发错类型了，文章能转成页面吗？ 答：核心没有一键转换功能。可借助「Post Type Switcher」类插件转换，转换后分类标签会丢失归属（页面无此概念），请先规划。
  • 问：企业官网不写博客，还需要文章吗？ 答：需要。新闻动态、行业案例、技术问答都适合文章，持续更新的内容也是 SEO 的重要信号；纯静态站长期不更新对搜索引擎不友好。

6.3 文章编辑器外围界面全解析 ​

写作在画布中完成，而一篇内容以什么状态、什么时间、什么网址、对谁可见，全部由编辑器外围界面控制。这是本章的重点。

图 06-1：区块编辑器全景，标注了顶部栏、右侧文档设置面板、状态与可见性、摘要等关键区域

6.3.1 顶部栏：保存、预览、发布的总控 ​

顶部栏从左到右的主要控件：

控件作用
「W」图标 / 管理栏返回后台文章列表
列表视图图标以大纲方式查看所有区块（第 7 章详解）
切换文档/区块设置齿轮控制右侧面板显示「文档设置」还是「区块设置」
选项（三点）偏好设置、编辑器模式、查看修订版本、复制所有内容等
预览（Preview）在新浏览器标签页打开预览，未发布内容也能查看效果
保存草稿（Save Draft）手动保存为草稿，右侧会出现「已保存」提示
发布/更新（Publish / Update）草稿时显示「发布」，已发布后显示「更新」

6.3.2 状态与可见性 ​

点击右侧「概要」（Summary）面板（旧版称「状态与可见性」），有三组关键选项：

文章状态：

状态中文官方译名说明
Draft草稿只有你和高权限用户可见，前台完全不可见
Pending review待审核作者提交后等待编辑/管理员审核，适合多作者站点
Published已发布所有人可见

可见性：

可见性中文官方译名前台效果
Public公开任何人可访问，出现在列表与 Feed 中
Private私密仅登录且具有编辑以上权限的用户可见，不出现在公开列表
Password protected密码保护访客看到密码输入框，输入正确密码后显示内容

操作方法：发布一篇密码保护文章 ​

  1. 在编辑界面右侧「概要」面板点击「可见性：公开」。
  2. 在弹出的选项中选择「密码保护」。
  3. 输入访问密码（如 2026-vip），点击空白处确认。
  4. 点击顶部「发布」，再次确认发布。
  5. 打开无痕窗口访问该文章地址，验证需要输入密码才能阅读。

注意：密码保护只保护正文，标题和特色图片仍可能出现在列表中；密码以明文链接形式分享即可，不要用它保护真正敏感的数据（如合同、内部资料）。

6.3.3 立即发布与定时发布 ​

默认状态下，发布时间为「立即发布」（Immediately）。WordPress 允许把文章安排在未来任意时间自动发布。

操作方法：设置定时发布 ​

  1. 在「概要」面板点击「立即发布」对应的日期时间区域。
  2. 在弹出的日历中选择日期，在时间框中输入时分（按站点时区执行，时区在「设置 → 常规」中配置，见第 5 章）。
  3. 顶部按钮文字从「发布」变为「定时发布…」（Schedule…），点击它。
  4. 确认后文章状态变为「已计划」（Scheduled，数据库中为 future），到点自动转为已发布。

图 06-2：点击「发布」后的发布前确认弹窗，可最后检查可见性、定时时间与永久链接别名

6.3.4 保存草稿、预览与自动保存 ​

  • 保存草稿：手动保存当前内容，可随时离开，稍后回来继续。
  • 预览：点击「预览」会在新标签打开真实前台效果；草稿、待审核文章都可以预览。
  • 自动保存：编辑过程中 WordPress 默认每 60 秒自动保存一次（可由 AUTOSAVE_INTERVAL 调整），意外关闭浏览器后重新打开会提示恢复。
  • 浏览器本地缓存：编辑器还会把内容暂存在浏览器本地存储（localStorage）中。即使网络瞬断、保存请求失败，你也不会丢失刚输入的文字，刷新后会提示「有未保存的本地版本」。

6.3.5 永久链接与别名编辑 ​

每篇文章都有一个人类可读的网址，其中的关键部分叫别名（slug，post_name 字段）。

  • 在「概要」面板找到「链接」（URL）一项，点击别名文字即可直接修改。
  • 中文标题会自动生成中文别名，前台 URL 中表现为百分号编码（见 6.11 节的利弊分析）。
  • 别名只允许小写字母、数字、连字符，空格会被转为连字符。

6.3.6 修订版本：历史快照与对比恢复 ​

每次点击「更新」（以及定时自动保存之外的正式保存），WordPress 都会把上一版内容存为一条 revision 记录。修订版本界面提供左右两栏对比，并清晰标出新增（绿色）与删除（红色）的内容。

操作方法：对比并恢复历史版本 ​

  1. 在右侧「概要」面板中找到「修订版本」（Revisions）入口（若文章刚建可能还没有修订，先更新一两次）；也可以通过顶部「选项（三点）」或按 Ctrl/Cmd + K 打开命令面板搜索「修订版本」进入。
  2. 进入修订界面：上方是时间轴滑块，左右两栏分别显示两个版本。
  3. 拖动滑块逐版对比，勾选右上角「比较任意两个版本」（Compare any two revisions）可自由选择两个不相邻版本。
  4. 找到正确版本后点击「恢复此修订版本」（Restore This Revision），当前正文即被替换；被恢复前的内容本身也不会丢，它又成为一个新修订。

图 06-3：修订对比界面，绿色为新增、红色为删除，顶部滑块可在多个历史版本间切换

6.3.7 常见问题 ​

  • 问：定时发布到了时间却没有发布，文章一直显示「已计划」？ 答：99% 是 WP-Cron 无人触发导致的。WordPress 的定时任务不是系统级定时任务，而是靠访客（或后台访问）访问站点时「顺带」执行。低流量站点到点无人访问，任务就会延后。解决方案见本章 6.12 节。
  • 问：草稿预览链接发给别人，打开是 404？ 答：草稿预览链接带有一次性签名参数，且要求对方有查看权限或链接未过期。把草稿正式发布或设为密码保护后再分享；不要直接复制地址栏里的 ?preview=true 链接。
  • 问：私密文章会被搜索引擎收录吗？ 答：不会被公开抓取——私密内容对未登录访客返回的是「找不到内容」，搜索引擎看不到正文。但前提是内容确实处于 private 状态；仅靠「不放进菜单」不等于私密。
  • 问：自动保存会不会产生很多修订版本？ 答：自动保存是特殊的临时修订（同一篇文章只保留最新一条自动草稿），不会无限累积；真正累积的是每次手动「更新」产生的修订。

6.4 摘要与「阅读更多」 ​

原理说明 ​

在博客列表页、分类页、RSS 订阅中，主题通常不展示全文，而是展示内容的摘要（Excerpt）。这里有三个容易混淆的概念：

概念是什么由谁决定
手动摘要（Excerpt）wp_posts.post_excerpt 字段，作者在右侧「摘要」面板手写的 1-2 句话作者
自动摘要调用 the_excerpt() 但无手动摘要时，系统自动截取正文前 55 个英文单词（中文主题常由主题/插件优化截取），去除所有 HTML 格式WordPress
the_content() + 阅读更多主题直接输出全文，用「阅读更多」区块在指定位置截断，截断点之前的内容与格式原样保留作者

区别本质：the_excerpt() 是「纯文本提要」，没有图片和排版；「阅读更多」是「正文前半段 + 跳转链接」，格式完整。

经典编辑器时代常用的 <!--more--> 快标签（Quicktag），在区块编辑器中的等价物就是 「阅读更多」（More）区块——一条可视化的分隔线。

操作方法：设置手动摘要 ​

  1. 若右侧看不到「摘要」面板，点击顶部「选项（三点）→ 偏好设置 → 面板」，勾选「摘要」。
  2. 在「摘要」面板输入 50-120 字的内容提要，这是列表页和搜索结果中最希望读者看到的话。
  3. 更新文章，在博客列表页查看效果（具体是否显示取决于主题，默认主题会优先使用手动摘要）。

操作方法：插入「阅读更多」分隔 ​

  1. 在正文中希望截断的位置新建一个空段落。
  2. 点击「+」插入区块，搜索并插入「阅读更多」（More）区块。
  3. 分隔线上方的内容会显示在列表中，下方出现「阅读更多」链接，点击进入全文。
  4. 在区块设置中可自定义链接文字（如「继续阅读 →」）。

常见问题 ​

  • 问：我写了手动摘要，前台为什么还是显示全文？ 答：摘要只在主题调用 the_excerpt() 的位置（归档、搜索、RSS）生效。若首页模板用的是 the_content()，则按「阅读更多」或全文显示，这是主题逻辑，详见第 23 章。
  • 问：摘要里可以放图片和链接吗？ 答：手动摘要框是纯文本区域，HTML 标签会在输出时被过滤。要保留格式请用「阅读更多」区块。
  • 问：自动摘要对中文为什么有时截取很怪？ 答：核心按英文「单词」计数，中文没有空格分词，截取长度不理想。中文站点推荐坚持手写摘要，或依赖主题/SEO 插件的优化。

6.5 置顶文章 ​

原理说明 ​

博客首页默认按时间倒序排列，新文章永远把老文章挤下去。置顶文章（Sticky Post） 是官方提供的「插队」机制：被置顶的文章固定在博客文章页顶部，常用于公告、征文、重要通知。

置顶是一个很小的功能，本质上是把文章 ID 记入站点选项（sticky_posts），主查询发现它后把它提前。

操作方法 ​

  1. 打开目标文章，在右侧「概要」面板找到「置顶文章」（Sticky post）选项。
  2. 勾选「置于博客文章页顶部」并更新文章。
  3. 访问「设置 → 阅读」中指定的文章页（博客首页），该文章出现在最前，并通常带「置顶」样式。
  4. 取消勾选即可取消置顶；置顶文章过期后记得及时取消，避免首页长期被旧内容占据。

常见问题 ​

  • 问：可以置顶多篇文章吗？ 答：可以，多篇置顶文章之间仍按发布时间排序，整体位于普通文章之前。但建议同一时间只置顶 1 篇。
  • 问：置顶对分类页、首页页面生效吗？ 答：置顶主要影响「文章页」（posts page）。若首页是静态页面、文章在其他归档页，置顶行为由主题模板与查询参数决定，很多主题不会在分类页特殊展示。

6.6 引用通告：Trackback 与 Pingback ​

原理说明 ​

这是 Web 1.0/2.0 时代的「跨站引用通知」机制：

  • Pingback：你在文章 A 中链接了另一篇支持 pingback 的 WordPress 文章 B，发布时 WordPress 自动通知 B；B 站审核通过后，会在 B 的评论区出现一条「A 引用了本文」的记录。它是自动的。
  • Trackback：原理类似，但需要你手动把对方提供的 Trackback 地址填入文章的「引用通告」发送框。

二者在数据库里都是 wp_comments 表中特殊类型的评论（comment_type 为 pingback/trackback），这也是为什么它们出现在评论管理列表中。

现代为什么基本关闭它？

  1. 社交网络普及后，跨站通告几乎没有真实用户使用。
  2. Pingback 长期被滥用于垃圾外链与 DDoS 放大攻击（攻击者伪造大量来源站向你的站点发起 pingback 请求）。
  3. 现代 SEO 中这类链接默认带 nofollow，没有外链价值。

因此，新建站点的主流建议是：在「设置 → 讨论」中关闭文章的 pingback 开关（详见第 10 章）。

操作方法 ​

  1. 「引用通告」面板默认隐藏：点击编辑器顶部「选项（三点）→ 偏好设置 → 面板」，勾选「引用通告」。
  2. 面板中可填入对方站点提供的 Trackback 地址（多个用空格或换行分隔）。
  3. 若只是关闭该功能，无需动编辑器，直接到「设置 → 讨论」取消勾选「尝试通知文章中链接的博客」「允许其他博客发送链接通知」两项。

常见问题 ​

  • 问：评论列表里出现大量「某网站引用了本文」的奇怪条目？ 答：那就是 pingback 垃圾。批量移至回收站并到讨论设置关闭相关开关即可，已有历史记录可在评论列表用批量操作清理。

6.7 文章形式（Post Formats） ​

原理说明 ​

文章形式是一组主题可选支持的排版标记：标准（Standard）、图像（Image）、画廊（Gallery）、视频（Video）、音频（Audio）、引用（Quote）、链接（Link）、状态（Status）、aside、chat 等。主题声明 add_theme_support( 'post-formats' ) 后，编辑侧栏才会出现「文章形式」选项，主题可以为不同形式设计不同前台样式（例如「图像」形式只显示一张大图）。

它的命运类似 Trackback：随着区块编辑器能让每篇文章自由排版，文章形式已明显边缘化，WordPress 官方默认主题的支持也越来越克制。新手只需认识它，不必主动使用；老站维护时看到侧栏有该选项不要困惑——那是当前主题声明了支持。

页面有三个文章没有的属性，集中在编辑界面右侧的「页面属性」（Page Attributes）面板：

属性中文官方译名作用

Order排序数字序号，部分主题与 wp_list_pages() 按此排序（数字越小越靠前）

操作方法：搭建三层页面树 ​

  1. 新建「产品中心」页面并发布（暂不设父级）。
  2. 新建「WordPress 主机」页面，在「页面属性 → 父级页面」下拉中选择「产品中心」，发布。
  3. 观察地址变化：子页面 URL 变为 /products/wordpress-hosting/（别名以实际为准）。
  4. 再为子页面设置下级，形成「产品中心 → 主机产品 → 企业型主机」不超过 3 层的结构。
  5. 在「排序」中填数字（如产品中心下三个页面分别填 1、2、3），部分主题的页面列表/面包屑会按此输出。

常见问题 ​

  • 问：页面模板下拉里什么都没有？ 答：页面模板由主题或插件提供。默认区块主题主要靠全站编辑器组织模板，经典主题才常提供 PHP 页面模板，详见第 24 章「自定义模板与 WP_Query」。
  • 问：页面层级做多深合适？ 答：建议不超过 3 层。层级越深 URL 越长、维护越难，扁平结构对访客和 SEO 都更友好。

6.9 列表管理：筛选、搜索、快速编辑与批量编辑 ​

日常内容运营 80% 的时间在「文章 → 所有文章」（All Posts）列表页，而不是编辑器。

原理说明 ​

列表页提供四类高效操作：

功能能做什么
筛选按日期（月份下拉）、按分类筛选；按状态查看全部/已发布/草稿/待审核/回收站/我的文章
搜索按关键词搜索标题与内容
快速编辑（Quick Edit）不进编辑器直接修改标题、别名、日期、作者、分类、标签、状态、允许评论/引用、置顶、密码
批量编辑（Bulk Edit）一次对多篇文章修改分类、作者、状态、评论开关、置顶、页面模板（页面列表）

图 06-4：所有文章列表的筛选区、批量操作下拉，以及展开后的快速编辑行内面板

操作方法：快速编辑单篇文章 ​

  1. 在「所有文章」列表中把鼠标悬停在某篇文章标题上，下方出现操作链接。
  2. 点击「快速编辑」（Quick Edit），该行原地展开编辑面板。
  3. 修改别名、分类或关闭评论后点击「更新」，全程不离开列表页。

操作方法：批量给 10 篇文章增加分类 ​

  1. 勾选列表左侧的多篇文章复选框（或勾选标题行的全选框）。
  2. 上方批量操作下拉选择「编辑」，点击「应用」（Apply）。
  3. 在展开的批量编辑面板中，在「分类」框勾选要追加的分类——注意批量编辑是「追加」勾选关系，无法批量移除某个分类，也不能批量修改正文、特色图片、摘要。
  4. 点击「更新」完成；选择「移至回收站」则批量删除。

回收站机制 ​

  • 删除文章先进入回收站（Trash），相当于系统垃圾桶，可「还原」（Restore）。
  • 回收站内容默认保留 30 天后自动永久删除，天数由 wp-config.php 中的常量控制：
php
// 回收站保留天数：默认 30；设为 0 则删除时直接永久删除（谨慎）；
// 设为 false（不带引号）可彻底禁用回收站功能。
define( 'EMPTY_TRASH_DAYS', 30 );

常见问题 ​

  • 问：批量编辑能批量改发布时间或正文吗？ 答：不能。批量编辑只支持有限字段；批量改正文属于危险操作，核心不提供，请借助 WP-CLI 或专业插件。
  • 问：回收站清空后还能找回吗？ 答：清空或超过 30 天后数据库记录被删除，只能从备份恢复（第 34 章「备份策略与工具」）。删除前三思。

6.10 写作效率：模式、快捷键与文档大纲 ​

编辑器内置一批提升写作专注度的功能：

功能入口作用
全屏模式选项（三点）→ 全屏隐藏后台侧栏，只留画布
聚焦模式（Spotlight）选项 → 聚焦模式除当前区块外其他内容变淡
顶部工具栏偏好设置区块工具栏固定在顶部，不再跟随区块浮动

6.11 SEO 友好的 URL 与别名 ​

原理说明 ​

「设置 → 固定链接」决定全站 URL 结构（第 5 章已配置过推荐的「文章名」结构）。单篇内容的 URL 是否友好，主要看别名（slug）：

做法示例 URL评价
英文短横线语义化别名/wordpress-scheduled-posts-fail/✅ 推荐：简短、含关键词、跨平台稳定
默认数字 ID/?p=128❌ 无语义，点击率与 SEO 均不友好
中文别名/WordPress定时发布失败/（地址栏显示为 %E5%AE%9A%E6%97%B6...）⚠️ 可用但有取舍

中文别名的利弊：

  • 利：在中文搜索结果中关键词直观；对中文站点 SEO 没有证据表明有负面影响。
  • 弊：复制到微信、QQ、邮件等场景会变成一长串 %E4%B8%AD... 编码，又丑又容易复制不完整；部分老旧缓存/统计工具对编码 URL 处理不佳；跨语言团队协作不便。

建议：面向中文用户的博客用中文别名也无妨，但企业站、产品页、技术文档优先使用英文连字符别名；一旦确定不要轻易修改。

操作方法：修改别名 ​

  1. 在文章「概要」面板的「链接」处点击别名直接编辑，或在列表页「快速编辑」中改「别名」字段。
  2. 已被收录的旧别名修改后会 404，需安装重定向插件（Redirection 等）或配置服务器 301 规则，把旧地址永久跳转到新地址。

常见问题 ​

  • 问：别名重复了怎么办？ 答：WordPress 会自动给重复别名追加数字后缀（如 about-us-2），不会冲突，但建议手动改成更有区分度的词。

6.12 高频问题速查（发布运维向） ​

6.12.1 定时发布失败：用系统级定时任务替代 WP-Cron ​

原理回顾：WP-Cron 是「访问触发」机制，无人访问就不执行。两种真实 cron 方案：

方案一：服务器 crontab 调用 WP-CLI（推荐，命令行环境）

bash
# 编辑当前用户的定时任务
crontab -e

# 每 5 分钟执行一次到期的 WordPress 定时任务（路径换成你的实际路径）
*/5 * * * * cd /var/www/example.com/htdocs && /usr/local/bin/wp cron event run --due-now > /dev/null 2>&1

方案二：服务器 crontab 直接请求 wp-cron.php

bash
*/5 * * * * curl -s https://www.example.com/wp-cron.php?doing_wp_cron > /dev/null 2>&1

同时在 wp-config.php 中关闭页面访问触发，避免重复执行：

php
// 使用系统级 cron 后，禁用访客访问时触发的伪定时任务。
define( 'DISABLE_WP_CRON', true );

本地学习环境（XAMPP/Local/Docker）关机时当然也不会发布，这是正常现象，不代表配置错误。

6.12.2 修订版本太多拖慢站点 ​

一篇频繁修改的文章可能积累上百条修订，让 wp_posts 表膨胀、备份变大。在 wp-config.php 中限制：

php
// 每篇文章最多保留 10 个修订版本（按实际需要调小）。
define( 'WP_POST_REVISIONS', 10 );

// 也可以设为 false 完全关闭修订（不推荐，会失去回溯能力）。
// define( 'WP_POST_REVISIONS', false );

// 自动保存间隔（秒），默认 60。
define( 'AUTOSAVE_INTERVAL', 120 );

已经产生的大量旧修订可由 WP-Optimize 等数据库清理插件或 WP-CLI 清理（运维操作见第 37 章），操作前先备份。

6.12.3 从 Word/网页粘贴带来「脏 HTML」 ​

从 Word、公众号后台或其他网页直接复制粘贴，常会带入内联样式、多余的 <span>、不可见字体设置，导致排版错乱、前台样式冲突。

  • 粘贴时使用快捷键：Windows Ctrl + Shift + V、macOS Cmd + Shift + V 以纯文本粘贴。
  • 或在粘贴后选中异常区块，用区块工具栏「清除格式」，再用标题/列表区块重新结构化。
  • 最佳实践：先「纯文本粘贴」，再用区块重新定义格式。

6.12.4 其他发布小问题 ​

现象原因与处理
预览显示 404 或要求登录分享的是草稿预览签名链接；请发布或用密码保护后再分享正式链接
私密文章担心泄露私密文章必须登录且有权限才能看；但标题、特色图可能在列表暴露，敏感内容不要放
更新后前台看不到新内容缓存插件/CDN/浏览器缓存未刷新，清理缓存并用无痕窗口验证（见第 19 章）
定时发布时间差了 8 小时站点时区未设置，到「设置 → 常规 → 时区」选择 UTC+8 或对应城市
密码文章在 Feed 里泄露正文核心会对 Feed 中的密码文章输出提示而非正文；若仍异常检查内容抓取插件设置

本章总结 ​

  1. WordPress 采用统一内容模型：文章、页面、附件、修订版本都是 wp_posts 表的一行，靠 post_type 与 post_status 区分——这是理解后续 CPT 的基石。
  2. 文章是「时间流 + 分类标签 + Feed」，适合时效性内容；页面是「层级树 + 常青内容 + 页面模板」，适合站点骨架；用决策树选型，企业站通常是少量页面加一批文章。
  3. 编辑器外围要完全掌握：公开/私密/密码保护三种可见性，立即/定时两种发布方式，草稿、待审核、自动保存与浏览器本地缓存，别名编辑与修订对比恢复。
  4. 摘要是纯文本提要（the_excerpt()），「阅读更多」区块是保留格式的正文截断（等价于经典时代的 <!--more-->）；置顶文章固定在文章页顶部；Trackback/Pingback 与文章形式是历史功能，现代站点建议关闭 pingback、了解文章形式即可。
  5. 列表运营靠筛选、搜索、快速编辑与批量编辑；删除先进回收站（默认 30 天，常量 EMPTY_TRASH_DAYS）；用 WP_POST_REVISIONS 控制修订数量；定时发布失败时用真实 cron 替代 WP-Cron。

动手练习 ​

练-06-01：规划一个企业站的信息架构 为一家虚构的「云栖科技」公司设计站点结构：（1）画出一棵不超过 3 层的页面树，至少包含「关于我们」（含发展历程、团队介绍两个子页面）、「产品中心」（含 2 个产品子页面）、「联系我们」；（2）规划 10 篇文章的标题，并为它们设计 3-5 个分类。把规划写成一页 Markdown 笔记，标注每个内容为什么是文章或页面。

练-06-02：发布一篇体验完整发布链路的文章 新建一篇不少于 300 字的文章，要求同时满足：设置一篇为定时发布（时间设为 2 小时后，观察状态变为「已计划」）；在写作过程中故意修改并更新至少 5 次，然后进入修订版本界面完成一次任意两版本对比并恢复；在「摘要」面板手写一段 80 字以内的手动摘要；在正文第二段后插入「阅读更多」区块。

练-06-03：体验密码文章与私密页面 新建一篇「会员专享：优惠券代码」文章，设为密码保护并用无痕窗口验证访问；再新建一个「内部通讯录」页面设为私密，分别用未登录访客和管理员账号访问，记录两种状态的差异，用自己的话解释为什么私密内容不等于「不放进菜单」。

练-06-04：列表运维实操与配置加固 在「所有文章」中练习：用月份和分类两个维度组合筛选；对 3 篇文章做快速编辑（改别名、关闭评论）；对 3 篇文章做批量编辑（统一追加一个分类）；删除一篇测试文章并在回收站中还原。最后在本地环境的 wp-config.php 中加入 WP_POST_REVISIONS 与 EMPTY_TRASH_DAYS 常量（参考配套代码 examples/config/wp-config.snippet.php），刷新后台确认配置生效。
