第 1 章 WordPress 平台概述 ​

🟢 入门难度 ｜ 一句话导览：本章不写一行代码，带你认识 WordPress 的前世今生、两种「WordPress」的区别、它能做什么、不能做什么，并给出整本教程的学习路线图。

学习目标 ​

  • 能用自己的话说清楚 WordPress 是什么、由哪些技术组成、遵循什么开源协议
  • 记住 WordPress 发展史上的 5 个关键节点，理解插件与主题两大扩展机制的由来
  • 了解 WordPress 的版本号规则与发布节奏，建立「持续小步升级」的维护观念
  • 能准确区分 WordPress.org 与 WordPress.com，并根据自身需求做出选择
  • 对文章、页面、主题、插件、用户角色、钩子、固定链接等核心术语有初步印象
  • 梳理自己的建站需求，明确后续章节的学习重点

1.1 WordPress 是什么 ​

1.1.1 一句话定义 ​

WordPress 是一套使用 PHP 语言编写、以 MySQL（或 MariaDB）数据库存储内容、基于 GPLv2 协议开源的网站构建与内容管理系统（CMS，Content Management System）。

拆开来看这句话：

  • PHP 编写：WordPress 的程序文件是 .php 文本文件，需要安装了 PHP 的 Web 服务器才能运行。它不是一个双击就能打开的桌面软件。
  • MySQL 存储：文章、页面、用户、设置等结构化数据保存在数据库里；图片、附件等文件则保存在服务器磁盘的 wp-content/uploads/ 目录中。
  • GPLv2 开源：任何人都可以免费下载、使用、修改甚至二次分发，详见本章 1.7 节。
  • CMS：它的核心价值是让不会编程的人，通过浏览器后台就能完成内容的发布、修改与管理。

据 W3Techs 统计，WordPress 长期占据全球 CMS 市场约六成份额，是目前使用最广泛的 CMS。这个数字会随统计时间小幅波动，但「每不到两个 CMS 网站中就有一个用 WordPress」的量级长期成立。官方介绍页面见 https://wordpress.org/about/。

1.1.2 WordPress 的技术构成 ​

一个可运行的 WordPress 站点，至少包含以下部分：

组成作用类比
Web 服务器（Apache / Nginx 等）接收浏览器请求，把 PHP 程序的执行结果返回给访客餐厅的前台接待
PHP 运行时解释执行 WordPress 的 .php 代码，生成 HTML 页面后厨的厨师
MySQL / MariaDB 数据库存储文章、设置、用户等全部结构化数据仓库与账本
WordPress 核心程序实现内容管理、后台界面、扩展机制等通用能力餐厅的标准运营体系
主题（Theme）决定前台长什么样、内容如何排版装修风格与摆盘
插件（Plugin）给网站增加功能，如电商、表单、SEO、缓存按需增设的外卖、会员等业务

💡 核心程序 + 主题 + 插件的分层设计，是 WordPress 生态繁荣的根本原因：官方维护「内核」，外观和功能交给生态扩展，三者互不耦合。

1.1.3 从博客工具到网站构建平台 ​

WordPress 的定位经历了三次跃迁：

  1. 博客引擎时代（2003–2007）：最初只是一个博客发布工具，强项是「写文章、发评论、RSS 订阅」。
  2. 通用 CMS 时代（2008–2017）：自定义文章类型、自定义字段、自定义分类法陆续引入，WordPress 开始能承载企业官网、新闻门户、电商等任意内容结构。
  3. 网站构建平台时代（2018 至今）：2018 年的 5.0 版本内置区块编辑器（Gutenberg），把「排版」也可视化了；6.x 系列又引入全站编辑（Full Site Editing，FSE），主题的页眉、页脚、侧边栏都能在后台拖拽搭建。今天的 WordPress 更接近一个「可视化建站操作系统」。

理解这条演进线很重要：WordPress 里同时存在「经典主题 / 经典编辑器」与「区块主题 / 区块编辑器」两套范式，它们分别代表了第二个和第三个时代，本教程会以 7.x 默认的区块编辑器为主线，并在第 07、11、23 章说明经典体系。

1.1.4 动态网站与静态网站：为什么 WordPress 需要服务器 ​

为了让零基础读者彻底明白「为什么不能双击打开 WordPress」，这里先建立动态网站的概念。

对比静态网页（如早期 HTML 个人主页）WordPress 动态网站
文件内容.html 文件写死了内容，浏览器直接渲染.php 文件是程序，内容存放在数据库里
更新方式用编辑器改 HTML，再上传覆盖文件登录后台写文章点发布，数据库更新，页面自动变
访客看到页面的过程服务器直接把文件发给浏览器服务器先运行 PHP、查询数据库，临时拼出 HTML 再发给浏览器
能否交互几乎不能评论、登录、搜索、下单、不同用户看到不同内容
需要什么环境一个能放文件的空间即可Web 服务器 + PHP + MySQL 三件套

一次最简化的访问流程是：

1.1.5 初识 WordPress 的目录结构 ​

安装好之后（安装过程是第 04 章的内容），WordPress 在网站根目录下大体是这个样子：

text
网站根目录/
├── wp-admin/             # 后台管理界面的程序文件（不用动）
├── wp-includes/          # 核心类库与公共文件（不用动）
├── wp-content/           # 👉 你的所有「资产」都在这里
│   ├── themes/           # 主题目录，每个主题一个子文件夹
│   ├── plugins/          # 插件目录，每个插件一个子文件夹
│   ├── uploads/          # 上传的图片与附件，按 年/月 分文件夹存放
│   └── languages/        # 语言包（后台装中文后出现）
├── wp-config.php         # 数据库与密钥等核心配置（安装时生成，极其敏感）
├── index.php             # 单入口文件：所有请求的起点
└── .htaccess             # Apache 的重写规则（保存固定链接后生成）

现在只需建立三个安全直觉，第 22、32 章会反复强化：

  1. wp-admin/、wp-includes/ 永远不要手改。升级时官方会整体覆盖它们，改了也会丢。
  2. 你的自定义内容只应出现在 wp-content/（主题、插件、上传文件），这保证了「核心随便升级，资产不受影响」。
  3. wp-config.php 里全是数据库密码与密钥，它绝不能被提交到公开的 Git 仓库，也不能通过浏览器直接访问到。

1.1.6 CMS、建站套件与 Web 框架的区别 ​

初学者常把 WordPress 与 Wix、Squarespace、Laravel 等名词混在一起，一张表理清定位：

类型代表形态自由度典型用户
开源 CMSWordPress、Drupal、Joomla自行部署的程序高，源码与数据完全自有想兼顾效率与掌控的人
闭源建站 SaaSWix、Squarespace、WordPress.com注册即用的在线服务受限于平台功能与套餐追求零运维的快速上线者
编程语言 / Web 框架Laravel（PHP）、Django（Python）从零写应用的工具库极高，但一切自己造专业开发者
静态站点生成器Hugo、Astro、VitePress构建出纯静态页面高，无后台动态能力文档站、内容固定的站点

WordPress 占据的位置是：比 SaaS 自由，比框架省心。当框架需要你从零实现登录、后台、富文本、媒体管理时，这些在 WordPress 里都是现成的；而当 SaaS 不允许你导出代码、定制底层时，WordPress 毫无限制。

1.2 发展简史：关键时间线 ​

WordPress 诞生于一个「前人项目停更」的真实故事。2003 年，法国开发者 Michel Valdrighi 开发的博客系统 b2/cafelog 停止维护，当时 19 岁的 Matt Mullenweg 在自己的博客上撰文倡议在 b2 的基础上另起分支（fork），英国开发者 Mike Little 留言响应——两人共同创建了 WordPress。2003 年 5 月 27 日，WordPress 0.7 发布。

两个名字还需要认识一下：

  • Matt Mullenweg：联合创始人，Automattic 公司 CEO，WordPress 项目的精神领袖与发版负责人。
  • Automattic：2005 年成立的商业公司，运营 WordPress.com、WooCommerce、Akismet、Jetpack 等产品。注意：Automattic 不等于 WordPress。WordPress 是由开源社区通过 WordPress.org 与 WordPress Foundation（基金会）共同治理的项目，Automattic 只是生态中最大的贡献者之一。

1.2.1 历史给我们的三点启示 ​

  1. 插件架构（2004）决定了生态上限。WordPress 核心刻意保持精简，把扩展性做成底层机制，这让全世界的开发者不用维护一个「分叉版本」就能贡献功能。今天官方插件目录收录的插件数以万计，根源都在 1.2 的这次决策。
  2. 主题系统（2005）让「设计」与「内容」分离。换主题不影响文章，写文章不碰代码，内容资产可以沉淀二十年——很多 2005 年的 WordPress 博客至今仍在持续更新，内容数据可以一路升级到 7.1。
  3. 编辑器范式切换（2018）是最大的一次学习断层。Gutenberg 发布初期争议极大，但它把 WordPress 从「文章表单」推向「页面构建」。老教程里大量基于经典编辑器的截图与操作已过时，这也是本教程坚持以 7.x 为基线的原因。

另外有个浪漫的传统：从 3.0 的 Twenty Ten 开始，官方每年发布一款以年份命名的默认主题（Twenty Twenty-Four、Twenty Twenty-Five……），它们是学习主题开发最好的范例代码。

1.3 版本号与发布节奏 ​

1.3.1 版本号怎么读 ​

WordPress 采用「主版本.次版本.修订号」三段式版本号，并为每个大版本取一个爵士乐手的名字作为代号（内部昵称，不影响使用）：

text
   7    .    1    .    2
   │         │         └─ 修订版本：安全补丁与缺陷修复，后台通常自动更新
   │         └─────────── 次版本：新功能与体验改进（约每年 2–4 个）
   └───────────────────── 主版本：阶段性里程碑
  • 大版本（7.0、7.1……）：带来可见的新功能，需要管理员在后台点击更新（也可配置自动更新）。
  • 小版本（7.1.1、7.1.2……）：以安全修复与严重缺陷修复为主，默认启用自动后台更新，无需人工干预。
  • 数据库结构升级：部分大版本会附带数据库升级流程，更新后首次访问后台会自动执行。

1.3.2 发布节奏：「刻钟式」迭代，没有官方 LTS ​

WordPress 保持高频发布：通常每年发布多个大版本（近年约 2–4 个），安全补丁随时发布。WordPress 官方从不提供 LTS（长期支持版）——这与 Ubuntu、Java 等软件的节奏完全不同，也是新手最容易忽视的一点。

这意味着：

  • 「我装一个稳定版然后三年不更新」在 WordPress 里不是一个安全选项。停留在旧版本意味着公开漏洞无人修补。
  • 正确的应对策略是：小版本保持自动更新，大版本定期跟进，更新前先备份、先在 staging（预发布）环境验证。这些内容会在第 34 章备份、第 37 章维护中系统讲解。

怎么知道自己的站点是哪个版本？三种方式：

  1. 后台「仪表盘 → 更新」页面会直接显示「当前版本」；
  2. 后台右下角任意页面通常标注版本号（仅管理员可见）；
  3. 命令行用 WP-CLI 执行 wp core version（第 04 章会装这个工具）。

小版本自动更新由后台的「后台更新（Background Updates）」机制完成：WordPress 会定期向 WordPress.org 查询新版本，在满足条件时自动下载并切换核心文件。你可以在 wp-config.php 中用常量控制其行为（先有印象即可，第 32、37 章会实操）：

php
// 是否完全关闭所有自动更新（生产环境不建议关闭）
define( 'AUTOMATIC_UPDATER_DISABLED', false );
// 让大版本也自动更新（默认仅小版本自动）
define( 'WP_AUTO_UPDATE_CORE', 'minor' ); // 可选 true / false / 'minor'

经验法则：小版本（7.1.x）放心自动更新；大版本（7.2、8.0 这类）先看更新说明、先备份、先在测试站验证插件主题兼容性，再手动升级。

组件推荐版本兼容 / 最低说明

1.4 WordPress.org 与 WordPress.com：两个完全不同的东西 ​

新手最常踩的第一个坑，就是把这两个网站搞混。它们都叫 WordPress，却几乎是两种产品。

1.4.1 核心区别对比 ​

对比维度WordPress.org（自托管）WordPress.com（托管 SaaS）
本质免费开源的程序，自己下载安装Automattic 运营的在线建站服务
价格程序免费；需自付域名（约几十元/年）与主机（约百元/年起）有免费档（带 .wordpress.com 子域名与平台广告）；付费档按年订阅
代码100% 源码在手，可任意修改封闭托管，无法接触服务器与源代码
主题任意安装官方库、第三方或自研主题免费档只能用限定主题；付费档才能上传自定义主题
插件任意安装、自研插件免费/低档套餐不能自行装插件，高档套餐开放部分插件
广告与盈利想放什么广告、接什么支付都由自己决定免费档由平台投放广告且收益不归你；升级后才可去除/自营广告
维护责任更新、备份、安全、性能自己负责服务器、备份、安全更新由平台负责
学习价值能学到真正的建站与运维技能，可平滑迁移到任何主机学习的是该平台的用法，迁移时受限较多

两者的官方入口分别是：

1.5.2 它不适合做什么 ​

没有万能的工具，下面这些场景请谨慎或另选方案：

  • 高并发实时应用：聊天室弹幕、在线协作白板、高频交易系统。这类场景依赖长连接与常驻进程，PHP 传统的「请求—响应」模型不占优（无头化后作为内容后台仍可）。
  • 纯结构化业务系统：ERP、财务记账、复杂工单流转。虽然插件能硬做，但 WordPress 的数据模型为「内容发布」优化，强行使用会处处别扭。
  • 完全静态的单页宣传页：如果页面三五年不变、也不需要后台，直接写静态页面或用静态站点生成器更省事。
  • 不愿承担任何维护责任：开源软件的自由伴随维护义务。如果你只想注册账号就永远不用管，WordPress.com 或 Squarespace 这类闭源 SaaS 更合适。

💡 判断口诀：有「内容」要持续发布、有「页面」要频繁调整、又想要完全掌控权，就是 WordPress 的甜蜜区。

1.7 GPL 开源协议与商用注意事项 ​

WordPress 采用 GPLv2 或更高版本（GNU General Public License v2）发布，协议全文见 https://www.gnu.org/licenses/old-licenses/gpl-2.0.html。对建站者而言，理解下面几条就够用：

  1. 可以免费用：个人站、企业站、商业站、电商站，都可以零授权费使用，无需向官方付费。
  2. 可以改：源代码完全开放，可以按自己的需求任意修改。
  3. 可以分发，但分发物必须同样开源：GPL 具有「传染性」——如果你把基于 WordPress 代码派生的作品对外分发（卖主题、卖插件），分发部分原则上也须以 GPL 兼容协议开放源码。
  4. 可以收费卖服务/卖产品：开源 ≠ 不能赚钱。GPL 保障的是言论自由（free as in speech）而非免费啤酒（free as in beer）。主题和插件作者可以售卖下载权限、售卖更新与支持服务；官方商业生态普遍遵守「PHP 代码 GPL 兼容、图片/CSS 等资源另行约定」的行业惯例（WordPress.org 官方主题目录则要求整体 GPL 兼容）。
  5. 没有担保：开源软件不附带任何可用性担保，出了问题不能找官方索赔——这也是为什么备份与维护如此重要（第 34、37 章）。

对普通使用者的实际建议：

  • 用 WordPress 做商业网站、收款、挂广告，完全合法，不必有任何顾虑。
  • 购买商业主题/插件时，你买的是「更新 + 支持 + 下载权」，要留意授权是按年订阅还是终身、能用于几个站点。
  • 不要把破解版（Nulled）主题插件用在正式站点：它们常被植入后门，省几百元换来的可能是整站被篡改。

1.7.1 新手最常问的三个版权问题 ​

问 1：网站底部「自豪地采用 WordPress」或主题版权字样可以去掉吗？

可以。GPL 赋予你修改的权利，去掉或修改页脚署名并不违法（保留署名是对社区的礼貌，但不是强制义务）。通过「外观 → 编辑器」或定制器修改对应模板即可，第 13、23 章会讲到具体位置。

问 2：我能用 WordPress 接单做网站、交付给客户并收费吗？

完全可以，而且这是全球非常普遍的商业模式。建议：交付时向客户说明站点基于 GPL 软件、提供管理员账号、交代好主机与续费责任，并保留自己的交付清单（第 35 章提供迁移交付清单）。

问 3：商业主题的「授权」到底买到了什么？

因为代码本身开源，付费购买的实质是：① 一整年的版本更新（兼容新版 WordPress 与安全修复）；② 官方技术支持；③ 正版 demo 模板与配套插件的下载权。到期不续费，主题通常仍可使用，但会停止更新——长期看不续费等于逐步暴露在安全风险中。

动手练习 ​

练-01-01（操作题）｜注册并体验 WordPress.com 免费档

  1. 打开 https://wordpress.com/，使用邮箱注册一个免费账号；
  2. 按向导创建一个免费站点（域名形如 你的名字.wordpress.com）；
  3. 在后台尝试新建一篇文章、更换一次主题；
  4. 记录：哪些功能可以直接用？哪些地方弹出了「升级付费」提示？把这些限制整理成一张不少于 5 条的清单，与本章 1.4 节的对比表互相印证。

练-01-02（思考题）｜.org 还是 .com？

假设你的朋友分别是：① 想记录旅行的大学生；② 准备开店卖手作饰品的设计师；③ 一家有 20 名员工的科技公司市场负责人。请为每个人给出选择（WordPress.com 免费档 / .com 付费档 / WordPress.org 自托管），并各写两条理由。

练-01-03（操作题）｜写下你的建站需求清单

仿照下表，在笔记中建立自己的需求文档（至少 8 条），后续章节会反复用到它：

项目我的情况
网站类型（博客/企业站/电商/……）
预计内容量级（文章数、图片数）
是否需要收款、会员、多语言
是否有同事协作，分别需要什么权限
每月可接受的主机/插件预算
每月愿意花多少时间做维护更新
是否已有域名与主机
学习目标（会用即可 / 想成为开发者）

练-01-04（思考题）｜给术语找位置

不看正文，用自己的话向家人解释「WordPress 核心、主题、插件」三者的关系（提示：可以用手机系统、手机主题壁纸、App 打比方），并把你最陌生的 3 个术语从 1.6 节表格中挑出来，标注计划在第几章解决。

练-01-05（思考题）｜理解「没有 LTS」

为什么说「装一个 WordPress 然后三年不更新」是危险做法？请结合 GPL 无担保、小版本自动更新、安全漏洞公开机制三点谈一谈，并给自己定一条未来的更新原则（一条即可，例如「每月第一个周末检查更新，更新前先备份」）。
