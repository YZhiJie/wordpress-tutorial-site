附录 C 练习参考答案 ​

本文件按章节汇总全 38 章练习题的参考答案要点，编号格式 练-CC-NN（CC=章节号）。

  • 操作题：一行内给「关键步骤 → 预期结果 → 评分点」。
  • 思考题：给「参考结论与理由」。
  • 代码题：给可直接运行的参考实现（WPCS 风格、Tab 缩进、中文注释），仅收录代表性题目（练-10-04、练-16-02、练-26-01、练-27-01）。

练习题目原文见各章末尾；此处仅列答案，便于教师批阅与读者自测。自测建议：先独立完成练习，再对照本答案自查；代码片段请复制到本地 examples/ 环境测试，勿直接在生产环境运行。

第 01 章 ​

  • 练-01-01（.com 注册体验对比）｜步骤：同邮箱注册 .com 免费账号并对比 .org 自托管 → 预期：.com 免费版不能装插件、主题受限 → 评分点：列出功能自由度、费用结构、技术要求至少 3 项差异。
  • 练-01-02（建站需求清单）｜参考结论：用表格列站点类型、内容量、必备功能、预算、维护人力；理由是「先定需求再选型」可避免博客/企业站/电商站方案错配导致的返工。

第 02 章 ​

  • 练-02-01（两种方案起站）｜步骤：Local 与 Docker 各起一空站 → 预期：均可访问 /wp-admin/ → 评分点：记录两套环境的 PHP/MySQL 版本与默认端口差异。
  • 练-02-02（Local Blueprint）｜步骤：装好主题插件后导出 Blueprint → 新站导入 → 预期：配置完整复现 → 评分点：主题、插件、设置三者均与原站一致。
  • 练-02-03（端口占用记录）｜步骤：lsof -i :80/:3306 定位冲突进程，改 Docker 端口映射 → 预期：改端口后服务正常 → 评分点：给出「改端口」或「停冲突服务」至少一条解决路径。

第 03 章 ​

  • 练-03-01（手工 LNMP）｜步骤：依次安装 Nginx 1.24+、PHP 8.3-FPM、MySQL 8 并配置 server 块 → 预期：php -v 显示 8.3、nginx -t 通过、三服务均 active → 评分点：能独立排掉「502 Bad Gateway」（多为 PHP-FPM socket 路径错）。
  • 练-03-02（certbot）｜步骤：certbot --nginx -d 域名 → 预期：80/443 均可访问且锁标正常 → 评分点：certbot renew --dry-run 验证自动续期链路。
  • 练-03-03（扩展检查）｜步骤：php -m 核对 mysqli/curl/dom/mbstring/gd/intl/zip 等 → 预期：全部就位 → 评分点：缺失项能写出安装命令（如 apt install php8.3-mbstring）。

第 04 章 ​

  • 练-04-01（图形安装）｜步骤：下载→上传→建库→填 wp-config（随机前缀+盐值）→走完向导 → 预期：前后台正常 → 评分点：$table_prefix 非 wp_、8 个盐值已生成、安装文件已清理。
  • 练-04-02（WP-CLI 安装）｜步骤：wp core download → wp config create → wp db create → wp core install → 预期：输出 Success → 评分点：全程无人值守、命令顺序正确。
  • 练-04-03（故意改错密码观察报错）｜参考结论：报 "Error establishing a database connection"；理由是生产环境必须关 WP_DEBUG_DISPLAY，避免报错泄露服务器路径与配置细节。
  • 练-04-04（随机表前缀）｜步骤：装前把 $table_prefix 改为 wpa7x_ 类随机串 → 预期：SHOW TABLES 全部带新前缀 → 评分点：装后改前缀需同步改 options/usermeta 中的键，故应装前完成。

  • 练-05-03（WP-CLI 重置密码）｜步骤：wp user update 1 --user_pass='...' → 预期：新密码可登录 → 评分点：密码满足强度要求且不以明文留在命令历史中。
  • 练-05-04（设置巡检）｜参考结论：时区、语言、管理员邮箱、固定链接结构是装机后最易漏改的四项；理由是它们分别影响定时发布、界面语言、通知可达性与全站 URL。

  • 练-06-01（页面树规划）｜步骤：建父子页面并看列表缩进 → 预期：层级正确 → 评分点：能说明「页面适合树状栏目、文章适合时间流」的选型理由。
  • 练-06-02（定时/修订文章）｜步骤：设未来时间发布、多次保存后对比修订 → 预期：定时准点上线、可回滚 → 评分点：修订面板能 diff 任意两版本。

  • 练-07-01（八种区块长文）｜步骤：插入段落/标题/图片/引用/列表/代码/栏目/按钮八类区块 → 预期：前台渲染正常 → 评分点：代码编辑器视图能找到 <!-- wp:... --> 注释。

  • 练-07-03（区块失效观察）｜参考结论：停用提供区块的插件后，文章显示「此区块包含意外或无效内容」；理由是区块解析依赖插件注册的 blockName 与渲染回调。
  • 练-07-04（HTML 视图找注释）｜步骤：切代码编辑器定位区块注释 → 预期：指出区块名、JSON 属性、包裹的原始 HTML 三者对应关系 → 评分点：能手工改属性并切回可视化不失效。

  • 练-08-02（测速观察）｜参考结论：未压缩原图是媒体站 LCP 头号杀手；理由是首屏大图直接决定 LCP 元素大小，压缩前后 PageSpeed 分数差异应明显。

第 09 章 ​

  • 练-09-01（分类树规划）｜步骤：设计 1 父 + 2~3 子分类并建 slug → 预期：层级正确 → 评分点：slug 语义化、无空格、全小写。
  • 练-09-02（归类 10 篇）｜步骤：10 篇文章逐一归类 → 预期：分类归档页聚合正确 → 评分点：无空分类、无文章挂在「未分类」。
  • 练-09-03（查看自定义分类法）｜步骤：启用演示插件 wp-academy-demo 查看新分类法面板 → 预期：编辑界面出现新面板、归档 URL 可访问 → 评分点：说出注册名、关联 post_type、rewrite slug 三要素。
  • 练-09-04（WP-CLI 批量建标签）｜步骤：循环 wp term create post_tag 名称 --slug=... → 预期：wp term list post_tag 可见 → 评分点：批量脚本可重复执行（幂等）不报错。

第 10 章 ​

  • 练-10-01（审核策略配置）｜步骤：设置→讨论开「人工批准」并配黑名单词 → 预期：游客评论进待审 → 评分点：命中黑名单词的评论正确分流到待审/垃圾。
  • 练-10-02（审核队列流转）｜步骤：游客提交评论 → 后台批准/垃圾/删除 → 预期：批准后前台可见 → 评分点：理解批准才展示、垃圾直接隐藏的队列语义。
  • 练-10-03（Akismet）｜步骤：启用并填 API Key → 提交测试评论 → 预期：拦截统计有数据 → 评分点：知道如何复审误判（垃圾队列中「不是垃圾」）。
  • 练-10-04（过滤器改评论表单）｜关键：挂 comment_form_defaults，改标题并追加提示语。参考实现：
php
/**
 * 修改评论表单默认参数
 *
 * @param array $defaults 表单默认参数。
 * @return array 修改后的参数。
 */
function yourprefix_comment_form_defaults( $defaults ) {
	$defaults['title_reply']          = __( '留下你的看法', 'yourprefix' );
	$defaults['comment_notes_before'] = '<p class="comment-notes">' . esc_html__( '你的邮箱不会被公开。', 'yourprefix' ) . '</p>';
	return $defaults;
}
add_filter( 'comment_form_defaults', 'yourprefix_comment_form_defaults' );

评分点：Filter 回调必须 return 修改后的数组；仅改文案不破坏表单字段结构。

  • 练-10-05（排查评论表单消失）｜参考结论：三层开关依次为「设置→讨论全局开关 → 单篇文章评论开关 → 主题 comments_template()」；理由是任一层关闭表单都不显示，应按此顺序排查。

第 11 章 ​

  • 练-11-01（换主题验证内容表现分离）｜步骤：切到默认主题对比内容 → 预期：文章/页面/菜单数据完整保留 → 评分点：说明小工具位置可能重置、菜单需重新指派区域。
  • 练-11-02（主题代际标签）｜步骤：各找 3 个经典/区块主题对比 → 预期：区块主题有 theme.json 与 .html 模板 → 评分点：能按文件结构判断主题代际。
  • 练-11-03（特征过滤）｜步骤：官方库用特征筛选并看更新日期 → 预期：筛出候选清单 → 评分点：超过 2 年未更新的主题列入谨慎名单。
  • 练-11-04（商业主题体检）｜参考结论：至少核查授权方式、更新承诺、文档完整度、退款政策、客服响应五维；理由是商业主题是长期投入，售后权重不低于功能。
  • 练-11-05（功能放主题还是插件）｜参考结论：外观强相关（自定义 CSS、版式微调）放主题/子主题；数据与业务（SEO、表单、CPT）放插件；理由是换主题后业务功能必须保留。

第 12 章 ​

  • 练-12-01（三种安装）｜步骤：后台搜索/上传 ZIP/SFTP 各装一次 → 预期：三种方式均可激活 → 评分点：说出三种方式各自的权限与网络要求。
  • 练-12-02（制造/修复缺 style.css）｜步骤：删除或清空文件头注释 → 观察「模版已损坏」→ 恢复 → 预期：提示消失 → 评分点：理解 style.css 文件头是主题识别依据。
  • 练-12-03（切换配置迁移）｜步骤：记录旧主题菜单/小工具 → 切换 → 重新指派 → 预期：导航恢复 → 评分点：菜单与菜单位置是两个概念，切换后需重新绑定。
  • 练-12-04（白屏回滚）｜步骤：激活含致命错误主题致 WSOD → SFTP 重命名主题目录 → 预期：自动回退默认主题 → 评分点：掌握无后台可用的文件系统回滚法。
  • 练-12-05（更新策略）｜参考结论：安全类小版本可自动更新，大版本与商业主题必须 staging 先测；理由是大版本常带模板/API 变更，直接上线风险高。

第 13 章 ​

  • 练-13-01（自定义器全流程）｜步骤：依次设置站点标识/颜色/背景/菜单/首页 → 预期：右侧实时预览同步 → 评分点：发布后前后台一致，未发布改动不影响线上。
  • 练-13-02（站点编辑器）｜步骤：区块主题下改页眉模板部件 → 预期：所有引用该部件的页面同步更新 → 评分点：区分「模板」「模板部件」「样式」三级修改对象。
  • 练-13-03（逐行 theme.json）｜参考结论：settings 管编辑器开放哪些选项、styles 定默认视觉值、templateParts 注册部件、customTemplates 注册页面模板；理由是四者分别对应编辑器能力、外观、结构与页面级模板。
  • 练-13-04（排查改色不生效）｜步骤：按「缓存 → CSS 优先级 → theme.json 硬编码覆盖」三层排查 → 预期：定位到覆盖源 → 评分点：能说出自定义器输出的是内联 CSS，优先级可能被 theme.json 的 styles 反超。
  • 练-13-05（两代体系决策）｜参考结论：设计稿高度定制且团队熟 PHP 选经典主题；编辑者需要拖拽改全站布局选区块主题；理由是两代体系的维护成本落在不同角色身上。

第 14 章 ​

  • 练-14-01（移动优先改写）｜步骤：基础样式先写移动端，桌面样式包进 min-width 媒体查询 → 预期：手机无横向滚动 → 评分点：媒体查询方向统一为 min-width 递进。
  • 练-14-02（设备清单实测）｜步骤：列目标设备并用 DevTools 逐一测试 → 预期：各视口布局正常 → 评分点：覆盖至少 3 种像素密度与 3 种视口宽度。
  • 练-14-03（自定义断点）｜参考结论：2~3 个断点（如 600/900/1200px）即可覆盖 90% 场景；理由是断点过多会让维护成本指数上升且难以对齐内容自然换行点。
  • 练-14-04（横向滚动排查）｜步骤：DevTools 找超宽元素 → 常见元凶：固定宽图、无 max-width:100% 的表格、负 margin → 预期：滚动消失 → 评分点：给出具体 CSS 修复而非加 overflow-x:hidden 遮羞。
  • 练-14-05（策略评审）｜参考结论：移动优先是「核心内容在最小屏完整呈现」，不是砍功能；评审清单应含图片自适应、字号可读、触控目标 ≥48px、无横向滚动四项。

第 15 章 ​

  • 练-15-01（创建子主题）｜步骤：建目录 + style.css（含 Template: wp-academy）+ functions.php 入队父主题样式 → 预期：可激活且保留父样式 → 评分点：Template 值等于父主题目录名。
  • 练-15-02（模板覆盖）｜步骤：复制父主题 single.php 到子主题并改动 → 预期：子主题版本生效 → 评分点：说出「同路径同名子主题优先」的覆盖机制。
  • 练-15-03（Template 拼写错误）｜参考结论：小写 template 或目录名拼错会导致子主题不被识别/样式丢失；理由是文件头字段区分大小写且必须与父主题目录名完全一致。
  • 练-15-04（致命错误回滚）｜步骤：子主题 functions.php 制造语法错误 → SFTP 修正 → 预期：恢复访问 → 评分点：知道子主题 functions.php 先于父主题加载，错误同样全站白屏。
  • 练-15-05（子主题 vs 插件边界）｜参考结论：模板与样式定制放子主题，CPT、安全、业务逻辑放插件；理由是换主题时子主题内容随之失效，业务功能必须解耦。

第 16 章 ​

  • 练-16-01（解剖空插件）｜步骤：建含 Plugin Name 文件头的单文件插件 → 预期：后台可识别并激活 → 评分点：说出 Plugin Name/Version/Author/License 各字段作用。
  • 练-16-02（Filter 加标题标记）｜关键：挂 the_title，仅在单篇前台主循环内加前缀。参考实现：
php
/**
 * 单篇文章页标题前加「原创」标记
 *
 * @param string $title 文章标题。
 * @return string 处理后的标题。
 */

	if ( is_single() && in_the_loop() && ! is_admin() ) {

/**
 * 站点公告小工具
 */
class Yourprefix_Announcement_Widget extends WP_Widget {

	public function __construct() {
		parent::__construct(
			'yourprefix_announcement',
			__( '站点公告', 'yourprefix' ),
			array( 'description' => __( '显示一条可自定义的公告文本。', 'yourprefix' ) )
		);
	}

	/** 前台输出 */
	public function widget( $args, $instance ) {
		echo $args['before_widget']; // phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped -- 主题侧栏包裹标记
		if ( ! empty( $instance['title'] ) ) {
			echo $args['before_title'] . esc_html( $instance['title'] ) . $args['after_title']; // phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped -- 包裹标记
		}
		if ( ! empty( $instance['content'] ) ) {
			echo '<div class="announcement-content">' . wp_kses_post( $instance['content'] ) . '</div>';
		}
		echo $args['after_widget']; // phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped
	}

	/** 后台表单 */
	public function form( $instance ) {
		$title   = isset( $instance['title'] ) ? $instance['title'] : '';
		$content = isset( $instance['content'] ) ? $instance['content'] : '';
		?>
		<p>
			<label for="<?php echo esc_attr( $this->get_field_id( 'title' ) ); ?>"><?php esc_html_e( '标题:', 'yourprefix' ); ?></label>
			<input class="widefat" id="<?php echo esc_attr( $this->get_field_id( 'title' ) ); ?>" name="<?php echo esc_attr( $this->get_field_name( 'title' ) ); ?>" type="text" value="<?php echo esc_attr( $title ); ?>">
		</p>
		<p>
			<label for="<?php echo esc_attr( $this->get_field_id( 'content' ) ); ?>"><?php esc_html_e( '内容:', 'yourprefix' ); ?></label>
			<textarea class="widefat" rows="4" id="<?php echo esc_attr( $this->get_field_id( 'content' ) ); ?>" name="<?php echo esc_attr( $this->get_field_name( 'content' ) ); ?>"><?php echo esc_textarea( $content ); ?></textarea>
		</p>
		<?php
	}

	/** 保存校验 */
	public function update( $new_instance, $old_instance ) {
		return array(
			'title'   => sanitize_text_field( $new_instance['title'] ),
			'content' => wp_kses_post( $new_instance['content'] ),
		);
	}
}

  • 练-29-01（分层现状图）｜步骤：画「服务器→OS→Web 服务器→PHP-FPM→OPcache→对象缓存→数据库」图并标注已启用层 → 预期：≥5 层 → 评分点：能指出当前瓶颈最可能落在哪一层。

  • 练-29-03（PHP-FPM 估算）｜参考结论：pm.max_children ≈ 可用内存 ÷ 平均进程内存；过高会 OOM、过低会排队；还应设 pm.max_requests 防内存泄漏。
  • 练-29-04（autoload 排查）｜步骤：按 LENGTH(option_value) 倒序查 autoload='yes' 的选项 → 预期：找出大体积项 → 评分点：给出改 autoload='no' 或清理过期 transient 的修复方案。
  • 练-29-05（先测后改）｜参考结论：任何优化必须「基准 → 改动 → 复测」量化验证；理由是感觉快不等于数据快，盲改常引入回退。

第 30 章 ​

  • 练-30-01（上传前工作流）｜步骤：压缩 → 语义化命名 → 选格式 → 填 alt 四步 → 预期：体积降 ≥50% 且视觉无损 → 评分点：工作流可写成团队规范。
  • 练-30-02（读懂 srcset）｜参考结论：srcset 提供多尺寸候选、sizes 描述布局宽度，浏览器按 DPR 与视口自选最优图；评分点：能在 DevTools 中观察到切换视口加载不同文件。
  • 练-30-03（自定义尺寸重建）｜步骤：新注册尺寸后跑 Regenerate Thumbnails 或 wp media regenerate → 预期：旧图补齐新尺寸 → 评分点：理解 add_image_size 只对之后上传的图自动生效。
  • 练-30-04（WebP 验证）｜步骤：确认 GD/Imagick 支持 → 传 WebP 或开自动转换 → 预期：Network 显示 image/webp → 评分点：现代浏览器全覆盖，无需 JPG 回退。
  • 练-30-05（懒加载修复 LCP）｜参考结论：首屏 LCP 图必须 loading="eager" 或 fetchpriority="high"，其余保持懒加载；理由是懒加载延迟了最大内容元素的发现时机。

第 31 章 ​

  • 练-31-01（结构化数据验证）｜步骤：加 BlogPosting/Organization JSON-LD → 富媒体测试工具验证 → 预期：无必需字段缺失错误 → 评分点：类型与属性匹配真实内容，不堆砌无关类型。
  • 练-31-02（面包屑 canonical）｜步骤：核对面包屑层级与 URL 层级一致、canonical 无参数污染 → 预期：每页 canonical 指向自身 → 评分点：分页页的 canonical 策略正确。
  • 练-31-03（robots vs meta）｜参考结论：robots.txt 禁抓取 ≠ 不收录（外链仍可索引），彻底不收录必须 noindex meta；理由是抓取与索引是两个独立环节。
  • 练-31-04（枢纽页内链）｜步骤：建终极指南枢纽页 + 5 篇子文双向链接 → 预期：形成 topic cluster → 评分点：锚文本自然、不堆砌关键词。
  • 练-31-05（收录慢/重复标题）｜参考结论：分页/筛选/搜索页最易产生重复标题；修法是给分页标题加「第 N 页」后缀并合并无价值参数页；理由是重复标题会让搜索引擎合并或降权。

第 32 章 ​

  • 练-32-01（六层清单）｜步骤：文件权限/登录保护/表前缀/后台加固/核心校验/备份六层逐项落实 → 预期：全部达标 → 评分点：无 777 目录、无 wp_ 默认前缀。
  • 练-32-02（注入攻防实验）｜参考结论：$wpdb->prepare() 占位符阻断 SQL 注入，esc_html() 等输出转义阻断 XSS；理由是把「数据」与「指令/标记」严格分离。
  • 练-32-03（REST 枚举封堵）｜步骤：访问 /wp-json/wp/v2/users 复现泄露 → 用认证错误或插件限制 → 预期：未登录返回 401/空 → 评分点：不影响已登录编辑者正常使用。
  • 练-32-04（verify-checksums）｜步骤：改 wp-login.php 一个字符 → wp core verify-checksums 报错 → 恢复 → 预期：校验失败被捕获 → 评分点：知道该校验只覆盖核心文件，主题/插件另需扫描。
  • 练-32-05（入侵应急演练）｜参考结论：隔离 → 取证备份 → 扫描清理 → 轮换全部凭据 → 重装核心 → 复查日志六步；理由是先止损再溯源，避免对抗中二次破坏证据。

第 33 章 ​

  • 练-33-01（三工具轮测）｜步骤：PageSpeed/GTmetrix/WebPageTest 同页各测一次 → 预期：LCP/TBT/CLS 趋势一致 → 评分点：能解释差异（节点位置、浏览器、缓存状态）。
  • 练-33-02（瀑布图标注）｜步骤：在瀑布图标出阻塞 CSS、最大图片、第三方脚本 → 预期：三类标注正确 → 评分点：按色块与时长判断资源类型。
  • 练-33-03（GSC 现场数据）｜参考结论：GSC 的 28 天现场数据代表真实用户，优先级高于实验室单次测试；理由是实验室数据受网络与设备假设影响。
  • 练-33-04（监控网）｜步骤：UptimeRobot（可用性）+ GTmetrix 定时（性能）+ GSC（搜索）三角布防 → 预期：异常 1 小时内可感知 → 评分点：告警渠道可达（邮件/IM）。
  • 练-33-05（完整迭代）｜参考结论：以「LCP 降 1 秒」为目标走完「测基准→定位→优化→复测→记录」闭环；评分点：前后数据可对比、优化手段与瓶颈一一对应。

第 34 章 ​

  • 练-34-01（3-2-1 方案设计）｜步骤：画 3 副本/2 介质/1 异地拓扑 → 预期：覆盖文件+数据库+配置 → 评分点：每份副本标注更新频率与存放位置。
  • 练-34-02（UpdraftPlus 恢复演练）｜步骤：备份 → staging 清空文件与库 → 恢复 → 预期：内容/媒体/设置完整 → 评分点：恢复后跑一遍关键路径（登录、发文、上传）。
  • 练-34-03（backup.sh 走读）｜步骤：逐行注释 examples/bin/backup.sh → 预期：说明 mysqldump 参数、tar 排除项、rsync 目标 → 评分点：解释 --single-transaction 对 InnoDB 一致性的意义。
  • 练-34-04（频率决策）｜参考结论：数据库变更频率远高于文件——电商库应小时级增量、文件日级同步；日更博客库日备即可；理由是备份频率应匹配 RPO（可容忍数据丢失量）。
  • 练-34-05（异地存储）｜步骤：配 UpdraftPlus/rclone 传对象存储 → 预期：云端可下载 → 评分点：保留策略（如 30 天）与访问密钥最小权限。

第 35 章 ​

  • 练-35-01（本地到服务器迁移）｜步骤：打包文件+导出库 → 上传导入 → 改 wp-config → search-replace 换域名 → flush 重写 → 预期：无 404、无混协议 → 评分点：uploads 完整、media 可访问。
  • 练-35-02（DNS TTL）｜参考结论：切换前把 TTL 调低到 300 秒加速生效，切完恢复常态；理由是低 TTL 缩短缓存期但增加解析负载。
  • 练-35-03（Duplicator）｜步骤：打包 → 传 installer+archive → 跑向导 → 预期：自动完成搜索替换 → 评分点：装完立即删除 installer 文件防被利用。
  • 练-35-04（验证清单）｜参考结论：首页/文章/页面/归档/搜索/登录/媒体/表单/HTTPS/速度十项各配验证方法与通过标准；理由是迁移事故 80% 出在媒体与 HTTPS 两项。
  • 练-35-05（零停机方案）｜参考结论：staging 预热 → 数据库主从切换 → 文件 rsync → DNS 切换 → 旧站保留 24h；核心前提是「切 DNS 前新站已完全可用」。

第 36 章 ​

  • 练-36-01（序列化手工实验）｜步骤：对含序列化数据选项直接 SQL REPLACE 域名 → 观察前台异常 → 用 PHP unserialize/serialize 修复 → 预期：复现并修好 → 评分点：说出长度前缀必须与字节数一致的原理。
  • 练-36-02（search-replace dry-run）｜步骤：先 --dry-run 审影响面再执行 → 预期：替换行数符合预期 → 评分点：必带 --skip-columns=guid，执行后抽查关键表。
  • 练-36-03（大库分批）｜参考结论：超 1GB 库应按表拆分导出或先清日志/修订大表；理由是单文件导入易超时且失败回滚成本高。
  • 练-36-04（GUID 论证）｜参考结论：guid 是永久标识符原则上不换；现代阅读器多按 permalink 追踪，故实务上影响有限；评分点：能引官方文档立场并给出实务结论。
  • 练-36-05（全命令序列实操）｜步骤：写「导出→dry-run→替换→验证→导入→flush」完整脚本并在 staging 跑通 → 预期：零手工干预完成 → 评分点：含 wp cache flush 与 wp rewrite flush 收尾。

第 37 章 ​

  • 练-37-01（维护节奏表落地）｜参考结论：安全更新 ≤24h、全量备份 ≤周、速度测试 ≤月、日志检查 ≤月；频率与站点变更量匹配即合格。
  • 练-37-02（更新 SOP 演练）｜步骤：staging 复现 → 执行主题大版本更新 → 记录每步与回滚命令 → 上线 → 预期：有「staging 通过才上线」闸门 → 评分点：回滚方案提前写好且实测可用。
  • 练-37-03（维护日志）｜步骤：记录近 3 次维护的日期/操作人/更新项/结果/异常 → 预期：可被第三方审计 → 评分点：异常处理有结论、有跟进人。
  • 练-37-04（交接文档）｜参考结论：含服务器信息、账号清单（密码只写存放位置）、备份位置、常用命令、紧急联系人五部分；理由是明文密码进文档等于二次泄露。
  • 练-37-05（自动更新邮件）｜步骤：开自动更新 + 邮件日志插件截获通知 → 预期：邮件含更新项与结果 → 评分点：管理员不看后台也能感知站点已自动更新。

第 38 章 ​

  • 练-38-01（日志地图走通）｜步骤：按「Nginx access/error → PHP error_log → WP debug.log → 插件自定义日志」定位模拟报错 → 预期：层级判断正确（如 502 看 Nginx、WSOD 看 PHP）→ 评分点：说出每层日志的默认路径。
  • 练-38-02（白屏注入修复）｜步骤：functions.php 语法错误致 WSOD → SFTP 修正 → 看 debug.log 归因 → 预期：不重装即恢复 → 评分点：理解 WSOD ≈ PHP fatal error。
  • 练-38-03（数据库连接四步）｜步骤：核对 wp-config 四项 → mysql 客户端直连 → 查进程与端口 → 查磁盘与连接数 → 预期：定位到模拟故障点 → 评分点：四步有序、每步有对应命令。
  • 练-38-04（Cron 失效修复）｜步骤：禁用 WP-Cron 复现定时发布失败 → 配系统 crontab 跑 wp cron event run --due-now → 预期：定时恢复 → 评分点：说出访客触发 Cron 在低频站点不可靠的原因。
  • 练-38-05（完整恢复演练）｜步骤：清空文件+删库 → 用备份全量恢复 → 跑验证清单 → 预期：与备份时间点零差异 → 评分点：记录恢复耗时（RTO 实测值）并纳入运维文档。
