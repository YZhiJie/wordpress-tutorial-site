第 5 章 后台管理界面全解析 ​

🟢 入门难度 ｜ 一句话导览：从登录 wp-admin 开始，逐项拆解左侧主菜单、设置六大分页的每一个字段、五大角色的能力边界与站点健康工具，把「后台每个按钮是干什么的」一次讲清，并附上固定链接 404、时区、Gravatar 加载慢、忘记管理员密码等高频问题的标准解法。

学习目标 ​

  • 能通过 wp-login.php 与 /wp-admin 登录、登出，会用邮件找回密码，理解管理栏在前后台切换中的作用
  • 说清左侧主菜单每一项的职责，以及管理员、编辑、作者等不同角色看到的菜单差异
  • 完整走一遍「设置」的六个分页，理解常规、撰写、阅读、讨论、媒体、固定链接、隐私每个字段的影响
  • 讲清 WordPress 地址与站点地址的区别，知道移动网站目录前必须先做什么
  • 掌握五大默认角色的能力矩阵与最小权限原则，会新建用户、完善个人资料、签发应用密码
  • 会使用「工具 → 站点健康」排查环境与配置问题

5.1 登录、登出与找回密码 ​

原理说明 ​

WordPress 有两个与登录相关的地址，分工不同：

地址作用
https://example.com/wp-login.php登录页本体：验证用户名与密码，处理找回密码
https://example.com/wp-admin后台入口：未登录访问会被重定向到登录页，登录成功后再跳回后台

登录成功后，WordPress 会在浏览器写入登录 Cookie。默认会话约 48 小时；登录页勾选「记住我」后延长到约 14 天。换浏览器、换设备、清除 Cookie 都会要求重新登录。

操作方法：登录与登出 ​

  1. 浏览器访问 你的域名/wp-admin，未登录时自动跳转到登录页。
  2. 输入「用户名或电子邮件地址」与「密码」，点击「登录」。
  3. 进入后台首页（仪表盘）。以后每次访问，只要 Cookie 未过期就直接进入。
  4. 登出：把鼠标移到页面右上角管理栏中的「您好，某某」上，在下拉菜单中点「退出」。公用电脑上务必登出。

找回密码（邮件方式） ​

  1. 在登录页点击「忘记密码？」链接。
  2. 输入用户名或注册邮箱，点击「获取新密码」。
  3. 查收邮件（注意垃圾邮件文件夹），点击邮件中的重置链接，在打开的页面里设置新密码。

💡 邮件方式依赖服务器能正常发信。如果收不到重置邮件，需要改用 phpMyAdmin 或 WP-CLI 重置，见本章 5.12 节；邮件发不出去的根因与 SMTP 解决方案见第 10 章与第 38 章。

管理栏：前后台之间的传送带 ​

登录状态下访问前台页面，页面顶部会多出一条黑色的管理栏（Toolbar），它是前后台切换的枢纽：

  • 左侧：WordPress 图标（关于/文档链接）、站点名称（鼠标悬停可点「仪表盘」回后台）、评论气泡、「+ 新建」（快速新建文章/页面/媒体/用户）。
  • 浏览某篇文章时会出现「编辑文章」，一键直达该文的编辑页。
  • 右侧：「您好，某某」，下拉可进入「编辑个人资料」或「退出」。

图 05-2：登录后访问前台时页面顶部的管理栏，左侧可回后台、可新建内容，右侧可编辑资料或退出

操作方法：关闭前台管理栏 ​

  1. 后台右上角点「您好，某某 → 编辑个人资料」（或左侧「用户 → 个人资料」）。
  2. 找到「工具栏」选项，取消勾选「在浏览站点时显示工具栏」。
  3. 拉到页面底部点「更新个人资料」。此后访问前台不再显示管理栏，后台顶栏不受影响。

常见问题 ​

  • 问：登录地址忘记了怎么办？ 答：先试 /wp-admin 和 /wp-login.php。若安全插件改过登录地址，到站点根目录的 .htaccess 或插件设置里查找；实在找不到可用 WP-CLI 停用该插件（wp plugin deactivate 插件目录名），登录页即恢复原状。
  • 问：提示「错误：您输入的用户名无效」但用户名没记错？ 答：登录框同时接受用户名和邮箱，试试用注册邮箱登录。还要排除键盘大小写锁定与多余空格。

5.2 左侧主菜单逐项详解 ​

原理说明 ​

左侧黑色纵向菜单是后台的骨架，WordPress 按当前用户的角色决定显示哪些菜单项。同一套程序，管理员看到全部菜单，订阅者只看到「个人资料」。理解这一点，就不会在换账号后惊呼「菜单丢了」。

图 05-1：管理员视角的后台首页：左侧主菜单 + 顶部管理栏 + 仪表盘小工具（概览、快速草稿、活动、WordPress 活动与新闻）

逐项说明 ​

菜单职责主要子菜单
仪表盘后台首页与系统更新首页（站点概览小工具）、更新（核心/主题/插件升级入口）
文章博客内容的发布与管理全部文章、写文章、分类目录、标签（详见第 06 章、第 09 章）
媒体图片、文档等附件管理媒体库、添加新媒体文件（详见第 08 章）
页面静态页面管理（首页、关于我们等）全部页面、添加新页面（与文章的区别见第 06 章）
评论读者评论的审核与回复评论列表（详见第 10 章）
外观站点颜值与版式主题、自定义/编辑器、小工具、菜单、主题文件编辑器（详见第 11 章）
插件功能扩展的装与管已安装的插件、安装插件、插件文件编辑器
用户账号与角色管理全部用户、添加用户、个人资料
工具导入导出与健康检查可用工具、导入、导出、站点健康、导出个人数据、抹除个人数据
设置全站行为开关常规、撰写、阅读、讨论、媒体、固定链接、隐私

💡 安装插件后，插件可能往主菜单加自己的顶级菜单（如商城、表单插件），或挂在「工具」「设置」下面加子菜单。「设置」分页变多，多半是插件干的。

重点菜单详解 ​

仪表盘：登录后的落地页。「首页」由若干小工具（概览、快速草稿、活动、WordPress 活动与新闻）拼成，可通过页面顶部的「显示选项」勾选开关各模块，也可直接拖拽重排——这套面板是给人看的速览，不产生任何数据。「更新」子页集中列出核心、主题、插件的可用新版本，出现红色数字角标就意味着有更新待处理（更新策略见第 37 章）。

文章：博客站使用频率最高的菜单。「全部文章」支持按分类、日期、作者筛选与批量编辑；「写文章」直达区块编辑器（见第 07 章）；「分类目录」「标签」两个子菜单通向分类法管理（见第 09 章）。

媒体：全站图片、PDF、视频等附件的仓库。图片通常在上传时挂在某篇文章下，但媒体库本身是全站共享的——任何文章都可以复用已上传的文件（管理与编辑技巧见第 08 章）。

页面：与文章并列的第二种内容形态，承载「关于我们」「联系方式」这类不进博客流的静态内容。页面支持父子层级，但没有分类和标签（文章与页面的完整对比见第 06 章）。

评论：读者互动的审核台，待审评论的数量会直接显示在菜单名旁的红圈里。评论系统的架构与反垃圾体系是第 10 章的全部内容。

外观：站点「长什么样」的总开关。经典主题下子菜单为「主题、自定义、小工具、菜单、主题文件编辑器」；启用区块主题后，「自定义」「小工具」会被「编辑器（站点编辑器）」取代，改用区块方式编辑整站模板（两条路线见第 11 章）。「主题文件编辑器」能直接改 PHP 源码，改错即白屏，生产环境不建议使用，很多站点会通过配置常量直接禁用它（见第 32 章）。

插件：WordPress 功能的扩展机制。「安装插件」页可在线搜索官方插件目录并一键安装；「已安装的插件」负责启用、停用与删除。和主题文件编辑器一样，「插件文件编辑器」同样慎用。

用户：站点全部账号的花名册，支持按角色筛选、批量修改角色。任何人（含订阅者）都至少能看到「个人资料」，维护自己的密码与偏好。

工具：运维向功能的集合。「可用工具」里有「分类目录和标签转换器」等按需启用的小工具；「导入」支持从其他平台迁入内容；「导出」打包全站内容为 XML；「站点健康」单独在 5.11 节详解；「导出/抹除个人数据」配合隐私政策使用（见 5.9 节）。

设置：全站行为的地基，六个核心分页在 5.3–5.9 节逐一展开。插件注册的分页通常追加在「设置」菜单末尾。

各角色可见性差异 ​

菜单管理员编辑作者贡献者订阅者
仪表盘✓✓✓✓✓
文章全部全部仅自己的仅自己的—
媒体全部全部全部——
页面✓✓———
评论✓✓———
外观✓————

记忆法：内容越往左越「重」，权限越往下越「轻」——管理员管全站，编辑管内容，作者管自己的文章，订阅者只管自己的资料。

5.3 设置：常规 ​

「设置 → 常规」是全站身份信息的总控台，字段不多但每一个都影响全站。

图 05-3：设置 → 常规：站点标题、副标题、两个 URL、管理邮箱、成员资格、默认角色、站点语言与时区

字段含义注意事项
站点标题站名，出现在浏览器标题、主题页头、邮件落款随时可改
副标题一句话简介默认值「又一个 WordPress 站点」务必改掉或清空，否则会出现在搜索结果里
WordPress 地址（URL）WordPress 核心程序文件所在的目录地址对应数据库 wp_options.siteurl
站点地址（URL）访客在浏览器里输入的前台访问地址对应 wp_options.home
管理电子邮件地址接收新用户注册、评论审核等系统通知修改后需点击新邮箱里的确认链接才生效
成员资格勾选「任何人都可以注册」后开放注册资讯站通常不勾
新用户默认角色开放注册后新账号的角色保持「订阅者」，切勿设为作者以上
站点语言后台与系统文案语言用户可在个人资料里单独覆盖后台语言
时区影响发布时间、定时发布、评论时间国内选「UTC+8」或「上海」
日期格式 / 时间格式前台日期时间的显示样式可选预设或自定义
星期开始于日历小工具/归档的起始日习惯选「星期一」

操作方法：逐项设置常规信息 ​

  1. 后台点「设置 → 常规」，先通读一遍每个字段的当前值。
  2. 「站点标题」填站名；「副标题」清空默认值或改成一句不超过 20 字的简介。
  3. 核对「WordPress 地址」与「站点地址」——两者应与浏览器地址栏里的访问地址一致（本地环境形如 http://localhost:8888/站点目录），确认无误前不要手改，原理见下节。
  4. 「管理电子邮件地址」填自己真实在用的邮箱。
  5. 确认「成员资格」未勾选；「新用户默认角色」保持「订阅者」。
  6. 「时区」选择「UTC+8」（或城市「上海」），注意选择框下方会实时显示当前换算出的本地时间，可用来核对是否选对。
  7. 日期格式选 Y年n月j日 或自定义 Y-m-d；时间格式按需选 24 小时制。
  8. 拉到底部点「保存更改」，页面顶部出现「设置已保存」即完成。

原理说明：WordPress 地址 vs 站点地址 ​

绝大多数站点两者相同。把它们设成不同，是为了实现「程序放在子目录、前台用根域名访问」的部署方式，例如程序装在 example.com/wp，访客访问 example.com 即可。

移动目录的坑：如果你先在服务器上把 WordPress 文件夹从 wp 挪到根目录，再在后台改这两个地址，会出现「改完保存的瞬间后台打不开」的窘境——因为地址与文件位置错位了。正确顺序是：

  1. 先在「设置 → 常规」把两个 URL 改成新地址并保存（此时前台会暂时异常，属正常）。
  2. 立刻把文件移动到新位置（或调整虚拟主机指向）。
  3. 如果已经改错导致后台进不去，用数据库修复：在 wp_options 表把 siteurl、home 两行改回正确值；或用 WP-CLI：
bash
# 查看当前两个地址
wp option get siteurl
wp option get home

# 改回正确地址（把示例域名换成你的）
wp option update siteurl 'https://example.com'
wp option update home 'https://example.com'

地址对不上的更多排查见第 04 章的重定向循环一节与第 38 章。

操作方法：设置时区与常规信息 ​

  1. 后台点「设置 → 常规」。
  2. 填好站点标题、把副标题清空或改成一句简介。
  3. 核对两个 URL 与当前访问地址一致（本地环境是 http://localhost:端口 之类）。
  4. 时区下拉选择「UTC+8」（或城市「上海」）。
  5. 确认「成员资格」未勾选、「新用户默认角色」为「订阅者」。
  6. 拉到底部点「保存更改」，页面顶部出现「设置已保存」即完成。

常见问题 ​

  • 问：为什么「管理电子邮件地址」改了没生效？ 答：出于安全，WordPress 会向新邮箱发确认邮件，点击邮件里的链接后才会真正切换；之前的通知仍发旧邮箱。

5.4 设置：撰写 ​

「设置 → 撰写」决定写文章时的默认行为，字段很少：

字段含义
默认文章分类写文章不勾选分类时自动归入的分类（初始为「未分类」，改名与替换见第 09 章）
默认文章形式标准/日志/链接等形式，取决于主题是否支持
通过电子邮件发表文章官方已标记废弃、计划移除，不建议配置使用
更新服务文章发布时自动通知的 ping 服务地址，默认已填好，保持默认即可

原理说明 ​

这一页的每一项都是「发布流程的默认值」：默认分类决定了漏选分类时文章的去向；默认文章形式只在主题声明支持时出现；「通过电子邮件发表文章」是早期通过专用邮箱发帖的旧机制，官方已不建议使用，不必配置；「更新服务」则是在文章发布时主动 ping 搜索引擎与聚合服务，通知它们来抓取新内容——保持默认填好的服务地址即可，留空等于放弃主动通知。

操作方法：更换默认文章分类 ​

  1. 先在「文章 → 分类目录」建好新分类（如「随笔」）。
  2. 回「设置 → 撰写」，把「默认文章分类」切换为「随笔」并保存。
  3. 此后「未分类」才可以被删除或改名。

5.5 设置：阅读 ​

「设置 → 阅读」决定首页给谁看、看多少，以及 RSS 和搜索引擎的行为。

字段含义常见选择
您的主页显示「您的最新文章」= 博客流；「一个静态页面」= 用指定页面当首页博客选前者；企业站/作品站选后者
主页（静态页面模式下）选哪个页面作为首页需先建好「首页」页面
文章页（静态页面模式下）选哪个页面承载博客文章列表需先建好「博客」页面，留空则没有博客入口
博客页面至多显示列表页每页文章数10 上下
联合供稿（Feed）中显示最近RSS 输出的条目数默认 10
对于 Feed 中的每篇文章，包含「全文」或「摘要」全文方便读者，摘要可引导回访并减少被整体抓取
对搜索引擎的可见性勾选后请求搜索引擎不索引本站仅开发期勾选，上线前必须取消（见第 04 章安装后设置）

操作方法：配置静态首页 + 博客页 ​

  1. 「页面 → 添加新页面」，建一个标题为「首页」的页面并发布；再建一个标题为「博客」的空页面并发布。
  2. 「设置 → 阅读」，「您的主页显示」选择「一个静态页面」。
  3. 「主页」下拉选「首页」，「文章页」下拉选「博客」，保存更改。
  4. 访问前台：域名直达「首页」页面；/blog/（或该页面的别名）显示文章列表。

💡 静态首页模式下，首页的内容排版由该页面决定，可配合区块编辑器设计版面（见第 07 章）。

常见问题 ​

  • 问：设了静态首页后，博客列表页不见了？ 答：多半是没指定「文章页」，或把「主页」和「文章页」选成了同一个页面——两者必须是不同的页面。

5.6 设置：讨论 ​

「设置 → 讨论」控制评论的全局开关、审核规则与头像显示，共六个板块。这里先记住最常用的三个开关：

  1. 「允许他人在新文章上发表评论」——全站评论总闸（对已发布的旧文章不生效）。
  2. 「启用评论嵌套」——允许楼中楼回复。
  3. 「评论必须经人工批准」——最严格的审核策略。

每个字段的精讲、审核关键词的写法、Akismet 反垃圾与评论模板定制，全部在第 10 章展开。

5.7 设置：媒体 ​

「设置 → 媒体」定义上传图片时 WordPress 自动生成的几种派生尺寸。

原理说明 ​

上传一张图，WordPress 会按这里的设置额外生成若干个尺寸的副本，主题在不同位置调用合适尺寸，避免「首页缩略图加载 4MB 原图」：

尺寸默认值数值含义用途举例
缩略图大小150 × 150宽高的精确值，默认勾选「裁剪缩略图到精确尺寸」，不等比、直接裁出正方形列表小图、相册网格
中等大小300 × 300宽高的上限，等比缩放，任一边不超过该值文章内配图
大尺寸1024 × 1024同上，等比缩放的上限正文大图、灯箱

另外两个容易忽略的点：

  • 2560 大图阈值：当上传图片的宽或高超过 2560 像素时，WordPress 会自动生成一张最大边 2560 的缩放副本作为「完整尺寸」（文件名带 -scaled 后缀），原图保留在服务器上但不直接使用。这个阈值可用过滤器调整。
  • 「以年—月文件夹整理上传内容」：勾选后文件存到 uploads/2026/10/ 这样的目录，保持默认勾选便于维护。

操作方法：配置媒体尺寸 ​

  1. 「设置 → 媒体」，先理解三档尺寸的定位再动手：缩略图服务列表与网格，中等服务正文插图，大服务通栏大图。
  2. 缩略图保持 150 × 150 并勾选「裁剪缩略图到精确尺寸」——相册网格需要正方形才整齐；若不勾选则等比缩放，网格会高低不一。
  3. 中等与大尺寸按主题正文的版心宽度调整：正文版心约 700 像素就把中等设 700 上限、大设 1200 上限，让插图清晰度与文件体积平衡。
  4. 确认「以年—月文件夹整理上传内容」保持勾选，保存更改。
  5. 上传一张宽 4000 像素的测试图，到媒体库查看详情：能看到自动生成的各尺寸与一张带 -scaled 后缀的「完整尺寸」。

常见问题 ​

  • 问：改了这里的尺寸，以前上传的图片会变吗？ 答：不会。尺寸设置只影响之后上传的图片；历史图片的派生尺寸需要重新生成，方法见第 08 章。

5.8 设置：固定链接 ​

固定链接（Permalink）决定全站文章 URL 的长相，也是 SEO 与可维护性的地基。

图 05-4：设置 → 固定链接：六种结构选项 + 分类/标签前缀设置，推荐选择「文章名」

原理说明 ​

选项URL 形态评价
朴素/?p=123不依赖伪静态，但无语义、不利于 SEO
日期和名称型/2026/10/04/sample-post/URL 冗长，且把时效钉死在地址里
月份和名称型/2026/10/sample-post/略短，仍带日期
数字型/archives/123无语义
文章名/sample-post/推荐：简短、语义化、稳定
自定义结构用 %year%、%postname% 等标签自由组合有特殊需求时用

下方「可选」区块可改分类目录前缀（默认 category）与标签前缀（默认 tag），改后归档地址变为 /你的前缀/分类别名/。前缀与分类树的规划联动，见第 09 章。

伪静态依赖服务器 rewrite：非「朴素」结构需要 Web 服务器把 /sample-post/ 这类漂亮地址内部转发给 WordPress 处理——

  • Apache：依赖 mod_rewrite 与站点根目录的 .htaccess（保存固定链接时 WordPress 会尝试自动写入规则）；
  • Nginx：没有 .htaccess 机制，需要在站点配置里手写 try_files 规则，配置方法见第 03 章。

操作方法：设置文章名结构 ​

  1. 「设置 → 固定链接」，选择「文章名」（对应 /%postname%/）。
  2. 如使用 Nginx，确认服务器配置已含 try_files $uri $uri/ /index.php?$args;。
  3. 点「保存更改」。即使没有修改，点一次保存也会刷新重写规则——这是排查 404 的常用动作。
  4. 打开任意文章前台，确认 URL 变为 /文章别名/ 且能正常访问。

常见问题 ​

  • 问：保存固定链接后文章全部 404？ 答：重写规则未生效。按顺序排查：① 再点一次「保存更改」；② Apache 检查 .htaccess 是否可写、虚拟主机是否允许 AllowOverride；③ Nginx 检查 try_files 是否配置并 reload。仍不行按第 38 章的流程处理。

5.9 设置：隐私 ​

「设置 → 隐私」只做一件事：指定哪个页面是你的「隐私政策」。

原理说明 ​

只要站点收集任何访客数据——评论表单里的姓名与邮箱、注册账号、统计脚本的 Cookie——就需要一份公开可访问的隐私政策，告知访客数据被如何收集与使用。WordPress 把「隐私政策页面」做成一个一等设置项，是为了让主题、插件（尤其是评论表单与注册流程）有一个统一的地方去取这个页面的链接。

操作方法：指定隐私政策页面 ​

  1. 点「创建」可让 WordPress 生成一个带建议大纲的隐私政策草稿页，或在下拉中选择已有页面。
  2. 点「使用此页面」保存。主题与插件会在需要的位置（注册页、评论表单等）链接到它。
  3. 页面上的「指南」按钮提供按模块编写隐私政策的建议文本，可据此补全内容。

配套工具在「工具」菜单里：「导出个人数据」与「抹除个人数据」，用于响应访客「把我的数据给我/删掉」的请求——把对方邮箱填进去，系统会发确认邮件，确认后打包导出或匿名化其评论等数据。

5.10 用户与权限体系 ​

原理说明 ​

WordPress 的权限模型是角色（Role）→ 能力（Capability）：每个角色是一组能力的命名集合，后台菜单、按钮、操作权限全部由能力决定。默认五大角色能力如下（✓ 表示拥有）：

能力管理员编辑作者贡献者订阅者
阅读✓✓✓✓✓
撰写并编辑自己的文章✓✓✓✓（不能发布，只能提交待审）—
上传图片等媒体文件✓✓✓——
发布文章✓✓✓——
编辑/删除他人文章✓✓———
管理页面✓✓———
审核评论✓✓———
管理分类与标签✓✓———
安装/管理主题与插件✓————
管理用户✓————
修改站点设置✓————

操作方法：快速体验角色差异 ​

  1. 「用户 → 添加用户」建一个作者角色的测试账号（勾选发送通知邮件）。
  2. 用浏览器的无痕窗口登录该账号（无痕窗口与主窗口会话隔离，两个账号可同时在线）。
  3. 观察左侧菜单：作者看不到「外观」「插件」「设置」「页面」「评论」。
  4. 在「文章 → 写文章」里写一段内容，作者可以直接点「发布」；再把该账号角色改回「贡献者」（管理员在「用户 → 全部用户」里快速编辑），重进无痕窗口写文章，此时只有「提交审核」按钮——亲身体验矩阵中那一格 ✓ 与 — 的差别。
  5. 体验完毕，管理员把测试账号删除或降回订阅者。

最小权限原则 ​

给协作者开账号时，只给完成工作所需的最小角色：

  • 投稿人 → 贡献者（写完提交审核，编辑把关）；
  • 专职写手 → 作者（可自己发布）；
  • 内容负责人 → 编辑（管全部内容与评论）；
  • 技术运维才给管理员，且管理员账号越少越好，日常发文不要用管理员账号。

角色给错了不只是「多点几个按钮」的问题：作者无法发布意味着误操作上不了线；编辑碰不到设置意味着改不坏全站。权限是安全事故的第一道闸门，更多加固手段见第 32 章。

操作方法：新建用户 ​

  1. 「用户 → 添加用户」。
  2. 填「用户名」（登录用，创建后不可改）、「电子邮件」（接收通知与找回密码，必填且唯一）。
  3. 可选填姓名、站点、语言；点「显示密码」可查看/修改系统生成的强密码。
  4. 「角色」下拉选择合适角色；保持勾选「向新用户发送账号信息邮件」。
  5. 点「添加新用户」。对方收邮件后自行登录并在「个人资料」里改密。

图 05-5：用户 → 全部用户：每行显示用户名、姓名、邮箱、角色与文章数，可按角色筛选、批量改角色

个人资料的三个重点 ​

每个用户在「用户 → 个人资料」里管理自己的账号信息，其中三项最常用：

  1. 公开显示名：先填「昵称」，再在「公开显示为」下拉里选前台署名（昵称/姓名组合）。不要让署名等于登录用户名——作者归档页地址 /author/用户名/ 会暴露登录名，给暴力破解递梯子（防护见第 32 章）。
  2. 头像（Gravatar）：WordPress 不本地存头像，而是按邮箱去 Gravatar（全球公认头像服务）取图。到 gravatar.com 用同一邮箱注册并上传头像，全互联网支持 Gravatar 的站点都会显示它。国内加载慢的解决方案见 5.12 节。
  3. 应用密码（Application Passwords）：为 REST API、移动应用、外部自动化工具签发的专用密码，格式形如 xxxx xxxx xxxx xxxx xxxx xxxx。每个应用单独签发、可随时单独吊销，泄露一个不影响主密码。生成方法：个人资料底部「应用密码」区，输入应用名称 →「添加新应用密码」→ 立即复制（只显示一次）。生产环境要求站点启用 HTTPS 才能使用。

5.11 站点健康 ​

「工具 → 站点健康」是 WordPress 自带的体检仪，分两页：

图 05-6：工具 → 站点健康：状态页列出关键问题与推荐改进，并显示通过测试的数量

状态页 ​

把检查结果分为两档：

  • 关键问题：需要立即处理，例如 PHP 版本过旧、全站未启用 HTTPS、调试模式在生产环境开启、站点无法发起环回请求（影响定时任务与更新）。
  • 推荐改进：不紧急但建议处理，例如删除未使用的默认主题、移除失活插件、建议安装缺失的 PHP 扩展。

页面顶部的百分比/计数是「通过测试」的数量，整改后点「重新检查」刷新。

信息页 ​

结构化列出站点全量配置：WordPress 版本与常量、目录大小与权限、主题与插件清单、服务器环境（Web 服务器、PHP 版本及各项 ini 参数）、数据库版本等。右上角「复制站点信息到剪贴板」可一键生成纯文本报告——去论坛或群里求助时附上它，比口头描述高效得多。

常见问题 ​

  • 问：状态页报「计划事件未能运行」/环回请求失败？ 答：服务器无法自己访问自己，常见于本地环境域名未解析、或防火墙拦了出站请求。先按信息页确认环境，再按第 38 章排查网络与主机配置。

5.12 常见问题速查 ​

  • 问：同事登录后找不到「外观」「设置」菜单？ 答：不是故障，是角色权限不足。到「用户 → 全部用户」看他的角色：作者/贡献者/订阅者本来就看不到这些菜单。确有需要再提升角色，且遵循 5.10 节的最小权限原则。
  • 问：固定链接保存后文章 404？ 答：重写规则未生效。先回「设置 → 固定链接」再点一次保存强制刷新；Apache 确认 .htaccess 写入成功且站点允许覆写；Nginx 确认配置含 try_files $uri $uri/ /index.php?$args; 并已 reload。详见 5.8 节与第 38 章。
  • 问：时区改成 UTC+8 了，旧文章的发布时间怎么没变？ 答：发布时间按发布那一刻的站点时区写入数据库（同时存一份 UTC 时间），改时区只影响之后的显示换算与新内容，不会回写旧文章。显示异常时先确认改的是「设置 → 常规」里的站点时区，而非仅服务器系统时间。
  • 问：Gravatar 头像在国内加载很慢甚至裂图？ 答：Gravatar 默认服务器在国内访问不稳定。三种解法任选：① 用兼容 Gravatar 协议的国内镜像（如 Cravatar），装对应替换插件即可，无需改数据；② 主题/插件层用过滤器替换头像域名（面向开发者，见第 15 章）；③ 在「设置 → 讨论」底部直接取消「显示头像」，最省事。
  • 问：管理员密码忘了、重置邮件也收不到，怎么进后台？ 答：三种方法按场景选——
    1. 邮件找回（邮件功能正常时）：登录页「忘记密码？」走标准流程。
    2. phpMyAdmin 改哈希：进数据库打开 wp_users 表，编辑管理员那一行，user_pass 字段的函数列选 MD5、值列填新密码明文，保存后即可用新密码登录（WordPress 登录成功时会自动把它升级为安全哈希）。
    3. WP-CLI（有服务器命令行时，推荐）：
bash
# 按用户名重置，密码用引号包住防特殊字符
wp user update admin --user_pass='NewStrongPass!2026'

# 不确定管理员用户名时先列出全部用户
wp user list

💡 方法 2、3 属于「绕过登录」的运维操作，用完即走；日常应保证管理邮箱可用，让方法 1 永远有效。找回后建议立即检查「用户」列表里有无陌生账号（见第 32 章）。

本章总结 ​

  1. 登录走 wp-login.php，后台入口是 /wp-admin；管理栏是登录后前后台切换与快速新建的枢纽，可在个人资料中关闭前台显示。
  2. 左侧主菜单十项各司其职，菜单按角色裁剪——菜单「消失」先查角色，不是故障。
  3. 「设置 → 常规」里 WordPress 地址是程序目录、站点地址是前台入口，移动目录必须「先改地址、立刻挪文件」，改错可用 wp_options 或 WP-CLI 修复；时区、成员资格、默认角色都在这一页把关。
  4. 阅读设置决定首页形态：博客流或「静态首页 + 文章页」；媒体设置的三个尺寸是等比上限（缩略图除外，可精确裁剪），2560 是「完整尺寸」的大图阈值；固定链接推荐 /%postname%/，非朴素结构依赖服务器 rewrite。
  5. 五大默认角色能力递减，协作遵循最小权限原则；个人资料里管好公开显示名、Gravatar 与应用密码。
  6. 「工具 → 站点健康」分关键问题与推荐改进两档，信息页的「复制站点信息」是求助标配；密码三找回法（邮件 / phpMyAdmin MD5 / wp user update）至少掌握两种。

动手练习 ​

练-05-01（操作题）｜五个角色的账号各建一个，体验权限差异

在「用户 → 添加用户」中分别创建管理员之外的四个角色账号（编辑、作者、贡献者、订阅者各一，加上你自己的管理员共五个）。用浏览器的无痕窗口逐个登录，把每个角色实际看到的左侧菜单记录下来，与 5.10 节的能力矩阵逐格核对。重点验证三件事：贡献者写文章时有没有「发布」按钮、能不能上传图片；作者能否看到别人的文章；订阅者登录后还能做什么。

练-05-02（操作题）｜配置静态首页 + 博客页

新建「首页」「博客」两个页面（「首页」用区块编辑器简单排版一段欢迎语），在「设置 → 阅读」中把首页显示切换为静态页面并指定两者。验证：域名直达首页；博客页地址显示文章列表；再把设置改回「您的最新文章」，确认前台恢复博客流。思考：两种形态分别适合什么类型的站点？

练-05-03（操作题）｜用 WP-CLI 重置管理员密码

在本地环境终端执行 wp user list 找到管理员用户名，再用 wp user update 用户名 --user_pass='你设定的新密码' 重置。退出后台后用新密码重新登录验证。加分项：故意把密码改成一个弱密码，登录后观察后台/站点健康有没有相关提示，然后改回强密码。

练-05-04（操作题）｜设置六分页巡检

对照本章 5.3–5.9 节，把你练习站的六个设置分页逐项核对一遍并填表：每项当前值、本章建议值、是否需要修改。其中必须完成：副标题清空或改写、时区 UTC+8、默认角色为订阅者、固定链接为文章名结构、确认未勾选「对搜索引擎的可见性」（开发站除外）。

练-05-05（综合题）｜站点健康整改到「零关键问题」

打开「工具 → 站点健康」，把状态页列出的每一条关键问题与推荐改进抄下来，逐条查明原因并处理（本地练习站常见的有：HTTPS 未启用、调试模式开启、未使用的默认主题与插件）。整改完成后点「重新检查」，目标是关键问题清零，并用「信息」页的复制功能导出一份站点信息存档。
