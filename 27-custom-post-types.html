第 27 章 自定义文章类型与分类法 ​

🔴 高级难度 ｜ 一句话导览：当「文章」和「页面」装不下你的业务（课程、产品、案例、活动），就该请出自定义文章类型（CPT）与自定义分类法。本章以配套插件 wp-academy-demo 的「课程」系统为完整案例：注册参数逐个讲透、重写规则刷新时机、模板层级扩展、查询实战、以及与自定义字段的选型决策。

学习目标 ​

  • 用决策树判断「该用文章+分类，还是新建 CPT」
  • 理解「CPT 必须由插件承载，而不是主题」的内容可移植性原则
  • 逐参数讲透 register_post_type()（对照 class-cpt-course.php）
  • 逐参数讲透 register_taxonomy() 的层级 vs 扁平模式（对照 class-taxonomy.php）
  • 掌握 flush_rewrite_rules() 的正确时机（激活钩子先注册再 flush）与停用语义
  • 会用模板层级扩展 CPT：single-{post_type}.php、archive-{post_type}.php、taxonomy-{tax}.php
  • 会查询 CPT：WP_Query 的 post_type / tax_query、pre_get_posts 把课程混入主页
  • 能在「自定义字段 vs 分类法」之间做出正确选型，了解 register_post_meta 与 Meta Box
  • 理解 show_in_rest 对古腾堡编辑器与 REST API 的双重意义

27.1 CPT 决策树与插件承载原则 ​

27.1.1 原理说明：什么时候该建 CPT ​

遇到一类新内容，按这棵决策树走：

mermaid
flowchart TD
    A[新内容类型] --> B{它是「按时间排列的文章流」吗?}
    B -->|是| C[用 post + 自定义分类法/字段]
    B -->|否| D{它需要独立的后台菜单、独立的 URL 结构、独立的模板吗?}
    D -->|都不需要| C
    D -->|任一需要| E{内容量会持续积累吗?}
    E -->|否，只有几条| F[用 page 或选项页]
    E -->|是| G[新建 CPT]

典型判断：

内容结论理由
新闻/博客post天然文章流
公司介绍/联系方式page少量、层级结构
课程（本教程案例）CPT独立菜单、独立归档 URL、独立模板、持续积累
轮播图CPT（不公开）需要后台管理但不需要前台单页 → public => false 家族参数
全站横幅文字选项/定制器只有一份，不是「列表型内容」（第 28 章）

27.1.2 插件承载原则：换主题不丢内容 ​

CPT 注册代码必须放插件，绝不能放主题 functions.php。 原因：用户换主题时，主题的 functions.php 不再执行——如果 CPT 注册在主题里，换主题后后台「课程」菜单消失、前台课程 404、内容看起来「丢了」（其实还在数据库里）。

配套代码把这个原则做成了活教材：

  • 主题 wp-academy：只负责展示——single-course.php、archive-course.php、front-page.php 里的课程区；
  • 插件 wp-academy-demo：只负责数据结构——注册 CPT、分类法、设置、短代码。

而且主题的每处课程输出都有防御（archive-course.php 文件头原话）：

php
// 防御：course 类型不存在（演示插件未启用）时退回主模板。
if ( ! post_type_exists( 'course' ) ) {
	get_template_part( 'index' );
	return;
}

插件停用时主题零报错、优雅降级——这就是「插件管数据、主题管皮」的边界意识。

27.2 register_post_type 参数逐个讲 ​

对照配套 class-cpt-course.php 的真实注册代码：

php
$args = array(
	'labels'             => $labels,
	'public'             => true,
	'publicly_queryable' => true,
	'show_ui'            => true,
	'show_in_menu'       => true,
	// 古腾堡编辑器与 REST API 路由的必备开关。
	'show_in_rest'       => true,
	'has_archive'        => true,
	'rewrite'            => array(
		'slug'       => 'courses',
		'with_front' => false,
	),
	'menu_icon'          => 'dashicons-welcome-learn-more',
	'menu_position'      => 21,
	'supports'           => array(
		'title',
		'editor',
		'thumbnail',
		'excerpt',
		'comments',
		'revisions',
		'custom-fields',
	),
	// 复用「文章」的能力模型：作者/编辑/管理员按既有角色权限管理课程。
	'capability_type'    => 'post',
	'map_meta_cap'       => true,
	'query_var'          => true,
	'description'        => 'WP Academy 教学用课程内容类型。',
);

register_post_type( 'course', $args );

27.2.1 public 家族参数 ​

public => true 是四个开关的总开关，把它拆开看（都可以单独覆盖）：

参数控制什么教学值
publicly_queryable前台是否可通过 URL 查询（单页/归档是否可达）true
show_ui后台是否出现管理界面true
show_in_menu后台左侧菜单是否出现（可传字符串挂到别的菜单下）true
show_in_nav_menus / show_in_admin_bar菜单编辑器 / 顶部「+ 新建」默认跟随 public

反例场景：轮播图 CPT 通常 public => true 但 publicly_queryable => false——后台能管理，前台没有单页。

27.2.2 show_in_rest：一个开关管住两件事 ​

php
'show_in_rest' => true,

文件头注释说得很直白：古腾堡编辑器与 WP REST API（/wp-json/wp/v2/course）都依赖这一开关。关掉它的后果：

  1. 课程编辑界面退回经典编辑器（古腾堡通过 REST API 读写内容）；
  2. REST 路由不存在，无头（headless）架构、移动端 App 全部取不到课程数据。

27.2.3 rewrite 与 has_archive：URL 结构设计 ​

php
'has_archive' => true,
'rewrite'     => array(
	'slug'       => 'courses',
	'with_front' => false,
),
  • has_archive => true：开启归档页，URL 为 /courses/（与 rewrite slug 一致）；主题里用 archive-course.php 承接（27.4 展开）；
  • rewrite.slug => 'courses'：单篇 URL 形如 /courses/php-入门/。注意 slug 与 CPT 名（course）刻意不同——程序标识用单数、URL 用复数，是常见惯例；
  • with_front => false：文件头注释解释了为什么——如果你的文章固定链接带 /blog 前缀，不开这个选项，课程 URL 会变成 /blog/courses/...，被「文章前缀」污染。

27.2.4 supports：声明编辑能力清单 ​

php
'supports' => array(
	'title',          // 标题
	'editor',         // 正文编辑器
	'thumbnail',      // 特色图片
	'excerpt',        // 摘要
	'comments',       // 评论
	'revisions',      // 修订版本
	'custom-fields',  // 自定义字段面板（教学用；生产建议 Meta Box，见 27.6）
),

漏写 thumbnail 的后果很典型：编辑界面没有「特色图片」面板，has_post_thumbnail() 永远为假，主题里的课程卡片全部无图。supports 是「能力白名单」，没列的功能界面和 API 都不提供。

27.2.5 菜单与权限 ​

  • menu_icon => 'dashicons-welcome-learn-more'：Dashicons 是 WP 后台内置图标字体，官方图标表 直接挑；
  • menu_position => 21：文件头注释写明了选址逻辑——「页面（20)」与「评论（25)」之间，避免与核心菜单撞位。两个插件抢同一个位置时后者会被挤到浮点位，视觉上不可控；
  • capability_type => 'post' + map_meta_cap => true：复用文章的能力模型（edit_post / publish_post …），作者、编辑、管理员按既有角色直接获得对应课程权限。只有当课程需要独立权限体系（如「课程编辑」角色）时，才声明自定义 capability_type。

27.2.6 labels：三十多个文案键 ​

$labels 数组（完整见配套源码 98-133 行）覆盖后台所有界面文案：add_new_item（添加新课程）、not_found（未找到课程）、featured_image（特色图片）……写给中文站就全部写中文，否则后台会冒出英文残片。labels 也是多语言站点翻译的入口（本插件界面直接写中文，第 31 章国际化专题展开）。

27.3 register_taxonomy：层级 vs 扁平 ​

27.3.1 两种模式的选型 ​

配套 class-taxonomy.php 一次注册了两个分类法，恰好是两种模式的对照：

course_category（课程分类）course_tag（课程标签）
hierarchicaltruefalse
类比文章的「分类目录」文章的「标签」
后台界面复选框树逗号分隔输入框
适合有父子关系的组织维度（编程 → PHP/Python）松散的关键词标记

27.3.2 注册参数精读 ​

php
$args = array(
	'labels'            => $labels,
	'hierarchical'      => true,
	'public'            => true,
	'show_ui'           => true,
	'show_admin_column' => true,   // 课程列表页多出「课程分类」列。
	'show_in_nav_menus' => true,   // 外观 → 菜单里可以把分类加进导航。
	'query_var'         => true,
	'show_in_rest'      => true,   // 古腾堡分类面板 + REST API 的开关，与 CPT 保持一致。
	'rewrite'           => array(
		'slug'       => 'course-category',
		'with_front' => false,
	),
);

register_taxonomy( 'course_category', array( 'course' ), $args );

三个要点：

  1. 第二参数绑定对象类型：array( 'course' ) 把分类法绑到课程上。一个分类法可绑多个类型（如 array( 'course', 'post' )）；后绑也可以：register_taxonomy_for_object_type()；
  2. 分类法名 vs rewrite slug 刻意不同（文件头注释原话）：程序标识 course_category 用下划线（WordPress 内部规范），URL slug course-category 用连字符（对用户与 SEO 友好）。这个差异同时影响模板文件名（27.4.3）；
  3. 注册顺序：文件头注释强调——本类在 WPA_CPT_Course 之后实例化，两个 register() 同挂 init、同优先级，按注册顺序执行，所以注册分类法时 course 类型必然已存在。顺序反了不会致命，但会出现「后台分类页文章类型关联丢失」等边界问题。

27.4 模板层级扩展与重写规则 ​

27.4.1 flush_rewrite_rules：激活钩子的正确姿势 ​

CPT/分类法通过 rewrite 注册新的 URL 规则，但规则表是持久化在数据库里的（rewrite_rules 选项）。改完注册代码必须刷新规则，否则新 URL 一律 404。

配套主文件 wp-academy-demo.php 的激活钩子是全行业最标准的写法，注意「先注册、再 flush」的顺序：

php
public static function on_activate(): void {
	if ( ! current_user_can( 'activate_plugins' ) ) {
		return;
	}

	// 关键顺序：先直接注册 CPT（此刻 init 钩子尚未触发，
	// WPA_CPT_Course 挂在 init 上的 register() 不会自动运行），
	// 让 'course' 类型与 courses/course-category 等重写规则进入规则表，
	// 然后再刷新固定链接规则。
	WPA_CPT_Course::activate();

	flush_rewrite_rules();
}

public static function on_deactivate(): void {
	flush_rewrite_rules();
}

逐层拆解为什么必须这样写：

  1. 激活请求中 init 尚未触发：插件的 register_activation_hook 回调执行时，本次请求的 init 已经错过了——挂在 init 上的 register() 不会跑。所以激活时必须直接调用 WPA_CPT_Course::activate()（它内部 self::get_instance()->register()）；
  2. 不注册就 flush 等于白刷：规则表里没有 courses 相关规则，flush 重建出来的依然是旧表；
  3. flush 很贵，只能在这两个钩子里调：flush_rewrite_rules() 要重建整张规则表并写库，文件头注释的原话是「绝不能挂在 init 上每次请求都刷」；
  4. 停用也要 flush：移除插件贡献的规则，让 /courses/ 恢复 404（语义正确），而不是留下指向不存在类型的死规则；
  5. 不需要 after_switch_theme（文件头注释专门驳斥的反例）：CPT 由插件注册，换主题不改变它，切主题时 flush 是无谓的性能开销。

日常开发中的手动刷新等价物：后台「设置 → 固定链接」点一次保存（底层就是 flush），或 WP-CLI wp rewrite flush。

27.4.3 模板精读：single-course.php 的元字段展示 ​

php
// 教学点：读取课程自定义字段（数据来源：演示插件或自定义字段面板）。
$wpa_course_duration = get_post_meta( get_the_ID(), '_wpa_course_duration', true );
$wpa_course_teacher  = get_post_meta( get_the_ID(), '_wpa_course_teacher', true );
?>
<?php get_template_part( 'template-parts/content', 'course' ); ?>

<?php if ( $wpa_course_duration || $wpa_course_teacher ) : ?>
	<aside class="course-meta-box" aria-label="<?php esc_attr_e( '课程信息', 'wp-academy' ); ?>">
		<dl class="course-meta-list">
			<?php if ( $wpa_course_duration ) : ?>
				<dt><?php esc_html_e( '课程时长', 'wp-academy' ); ?></dt>
				<dd><?php echo esc_html( $wpa_course_duration ); ?></dd>
			<?php endif; ?>
			<!-- ……讲师字段同理…… -->
		</dl>
	</aside>
<?php endif; ?>

文件头注释的两条坑都是生产高频事故：

  1. get_post_meta() 取不到返回空字符串，必须判空，否则输出一行空的「课程时长：」；
  2. meta 是可写数据（作者可填任意内容），输出前必须 esc_html——不要因为它「不像用户输入」就信任它。

另外注意单字段参数 true：以字符串返回单个值；省略或传 false 会返回数组（同一键可能有多个值的历史包袱）。

27.4.4 归档与分类法模板的对照精读 ​

archive-course.php（源码）——CPT 归档页的最小完备结构：

php
// 防御：course 类型不存在（演示插件未启用）时退回主模板。
if ( ! post_type_exists( 'course' ) ) {
	get_template_part( 'index' );
	return;
}

get_header();
?>
	<!-- ……容器骨架…… -->
	<header class="page-header course-archive-header">
		<h1 class="page-title"><?php esc_html_e( '全部课程', 'wp-academy' ); ?></h1>
		<p class="archive-description"><?php esc_html_e( '跟着章节顺序，循序渐进掌握 WordPress 主题开发。', 'wp-academy' ); ?></p>
	</header>

	<?php if ( have_posts() ) : ?>
		<div class="courses-grid">
			<?php
			while ( have_posts() ) :
				the_post();
				get_template_part( 'template-parts/content', 'course' );
			endwhile;
			?>
		</div>
		<?php wpa_numeric_pagination(); ?>
	<?php else : ?>
		<?php get_template_part( 'template-parts/content', 'none' ); ?>
	<?php endif; ?>

文件头注释点破两个 CPT 归档特有的坑：① CPT 注册时必须 has_archive => true 本模板才会被层级命中；② 新建模板后若 404，先去「设置 → 固定链接」点保存刷新重写规则——这与 27.4.1 的 flush 机制互为表里。

taxonomy-course_category.php（源码）——分类法归档的关键差异在「当前对象」的取法：

php
$wpa_current_term = get_queried_object();
// ……
printf(
	/* translators: %s: 课程分类名称。 */
	esc_html__( '课程分类：%s', 'wp-academy' ),
	esc_html( $wpa_current_term->name )
);

与分类归档（category.php 用 single_cat_title() + term_description()）不同，自定义分类法没有等价的专用模板标签，直接对 get_queried_object() 返回的 WP_Term 取 ->name / ->description——这种「拿对象、取属性」的写法对任何分类法通用，反而比记专用标签更可靠。命名规则提醒（第 24 章已详述）：模板文件名中的分类法名必须原样使用注册名 course_category（下划线），配套主题此文件即 taxonomy-course_category.php；误写成连字符版本核心不会命中。

27.5 查询 CPT ​

27.5.1 WP_Query 的 post_type 与 tax_query ​

配套 front-page.php 的「最新课程」区是最小实战：

php
$wpa_latest_courses = new WP_Query(
	array(
		'post_type'           => 'course',
		'posts_per_page'      => 3,
		'ignore_sticky_posts' => 1,
	)
);

配合分类法筛选（第 24 章 tax_query 的 CPT 版本）：

php
$wpa_query = new WP_Query(
	array(
		'post_type'      => 'course',
		'posts_per_page' => 6,
		'tax_query'      => array(
			array(
				'taxonomy' => 'course_category',
				'field'    => 'slug',
				'terms'    => array( 'programming' ),
			),
		),
	)
);

配套短代码 class-shortcode-courses.php 的 [wpa_courses category="编程入门"] 就是这套组合的生产实现——shortcode_atts 归一化 → sanitize_title 消毒 slug → tax_query 查询 → ob_start 收集输出 → wp_reset_postdata 复位，五步流水线可直接抄。

27.5.2 pre_get_posts：把课程混入主查询 ​

默认的主页文章流只含 post。想让课程也出现在主页/搜索/主分类归档里，用第 24 章学的 pre_get_posts：

php
/**
 * 主页文章流中混入课程 CPT。
 *
 * 双守卫（is_admin + is_main_query）见第 24 章。
 *
 * @param WP_Query $query 主查询对象。
 * @return void
 */
function wpa_add_course_to_home( $query ) {
	if ( is_admin() || ! $query->is_main_query() ) {
		return;
	}

	if ( $query->is_home() ) {
		$query->set( 'post_type', array( 'post', 'course' ) );
	}
}
add_action( 'pre_get_posts', 'wpa_add_course_to_home' );

⚠️ 注意传数组：只传 'course' 会把文章挤掉。post_type 参数接受数组，两个类型共存。

27.6 自定义字段 vs 分类法 vs Meta Box ​

27.6.1 选型决策表 ​

维度自定义字段（post meta）分类法（taxonomy）
数据形态键值对，随文章存储术语节点，独立实体
能否作为查询维度能，但 meta_query 慢（无索引）能，且 tax_query 走索引，快
是否有归档页没有自带 /course-category/xxx/ 归档
值的集合自由文本受控词表
典型例子课程时长、讲师姓名课程分类、难度等级

经验法则：「需要按它筛选/归档」用分类法；「只是这篇文章的一个属性」用自定义字段。课程的「编程语言」要筛选用分类法；「时长 2 小时 30 分」只展示用字段。

27.6.2 register_post_meta 与 Meta Box 简介 ​

配套的 _wpa_course_duration / _wpa_course_teacher 走的是 supports 里的 custom-fields（后台「自定义字段」面板手填）——教学够用，生产太糙：没有类型校验、没有界面约束、下划线前缀隐藏字段后台默认不显示。

生产级两板斧：

  1. register_post_meta()：向系统声明 meta 键的类型、消毒回调与 REST 可见性：
php
register_post_meta(
	'course',
	'_wpa_course_duration',
	array(
		'type'              => 'string',
		'single'            => true,
		'sanitize_callback' => 'sanitize_text_field',
		'show_in_rest'      => true,  // 古腾堡侧边栏与 REST 可读写。
	)
);
  1. Meta Box：add_meta_box() 在编辑页渲染结构化表单（日期选择器、下拉框），配合 save_post 钩子保存。最小骨架（含三道安全门）：
php
/**
 * 课程信息 Meta Box（最小骨架）。
 *
 * 三道安全门缺一不可：
 *   1. nonce 校验（wp_verify_nonce）——确认请求来自本表单；
 *   2. 能力校验（current_user_can）——确认用户有权编辑该文章；
 *   3. 自动保存守卫（DOING_AUTOSAVE）——定时草稿保存不触发写入。
 *
 * @return void
 */
function wpa_course_meta_box() {
	add_meta_box(
		'wpa-course-meta',
		'课程信息',
		'wpa_course_meta_box_render',
		'course',
		'side',
		'default'
	);
}
add_action( 'add_meta_boxes', 'wpa_course_meta_box' );

/**
 * 渲染 Meta Box 表单。
 *
 * @param WP_Post $post 当前文章对象。
 * @return void
 */
function wpa_course_meta_box_render( $post ) {
	wp_nonce_field( 'wpa_course_meta_save', 'wpa_course_meta_nonce' );
	$wpa_duration = get_post_meta( $post->ID, '_wpa_course_duration', true );
	printf(
		'<p><label for="wpa-course-duration">课程时长</label>
		<input type="text" id="wpa-course-duration" name="wpa_course_duration" value="%s" class="widefat"></p>',
		esc_attr( $wpa_duration )
	);
}

/**
 * 保存 Meta Box 数据。
 *
 * @param int $post_id 文章 ID。
 * @return void
 */
function wpa_course_meta_save( $post_id ) {
	// 门 1：nonce。
	if ( ! isset( $_POST['wpa_course_meta_nonce'] )
		|| ! wp_verify_nonce( sanitize_text_field( wp_unslash( $_POST['wpa_course_meta_nonce'] ) ), 'wpa_course_meta_save' ) ) {
		return;
	}

	// 门 2：能力。
	if ( ! current_user_can( 'edit_post', $post_id ) ) {
		return;
	}

	// 门 3：自动保存不处理。
	if ( defined( 'DOING_AUTOSAVE' ) && DOING_AUTOSAVE ) {
		return;
	}

	if ( isset( $_POST['wpa_course_duration'] ) ) {
		update_post_meta(
			$post_id,
			'_wpa_course_duration',
			sanitize_text_field( wp_unslash( $_POST['wpa_course_duration'] ) )
		);
	}
}
add_action( 'save_post_course', 'wpa_course_meta_save' );

$_POST 读取必须 wp_unslash() 再 sanitize_*（WordPress 会对超全局变量统一加魔术引号，不 unslash 会多出转义反斜杠）。字段一多（10+）直接上 ACF / Meta Box 插件，第 17 章插件选型有过讨论。

27.7 常见问题（本章汇总） ​

  1. 课程归档 404：三步排查——has_archive => true 开了吗？改完 rewrite 后刷新固定链接了吗？主题里有 archive-course.php 没有的话会回退 archive.php/index.php（不算 404，但页面不对）；
  2. 编辑器变成经典编辑器：show_in_rest => true 没开。古腾堡 = REST 驱动，不开即退化；
  3. 「您没有足够的权限」：capability_type 自定义了但没给角色授权。用 capability_type => 'post' + map_meta_cap => true 复用文章权限最省事；自定义能力需用 add_cap() 给角色补权限；
  4. 分类法在课程编辑页不出现：show_ui => true / show_in_rest => true 检查；古腾堡界面下分类面板由 REST 驱动，漏开 show_in_rest 就不显示；
  5. 固定链接结构怎么设计课程 URL：rewrite.slug 独立于 CPT 名；需要 /courses/category/xxx/ 这种「分类在 URL 里」的结构要额外写 add_rewrite_rule + post_type_link 过滤器，属于进阶话题，先用扁平结构起步。
