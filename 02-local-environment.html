第 2 章 本地环境搭建（Windows/macOS/Linux） ​

🟢 入门难度 ｜ 一句话导览：在自己的电脑上搭一个「服务器 + PHP + 数据库」的练习环境，从此改坏了能回滚、断网也能练，本章带你对比并实操 XAMPP、MAMP、Local、Docker 四套方案。

学习目标 ​

  • 理解本地环境的四件套构成，能解释「为什么不能双击 .php 文件」
  • 能说出 80/443/3306 等常见端口的作用，遇到端口占用会排查
  • 掌握 XAMPP 的安装、启动、改密码、建库、放置程序全流程（三平台差异清楚）
  • 了解 MAMP 与 Local 的使用方式，能用 Local 为练习站制作 Blueprint 快照
  • 能使用教程配套的 Docker 环境一键启动 WordPress 并完成初始化

2.1 为什么一定要有本地环境 ​

2.1.1 原理说明：什么是本地环境 ​

本地环境（Local Environment），就是在你自己的电脑上运行一套 Web 服务器 + PHP + 数据库软件，让浏览器通过 http://localhost 访问到这台「自己机器里的服务器」。网站文件和数据库都在本地磁盘上，与互联网上的真实站点完全无关。

与之相对的是生产环境（Production）：部署在云主机或虚拟主机上、绑定真实域名、对外提供服务的站点。二者之间还常见预发布环境（Staging）——与生产配置一致、但不对外公开，用于上线前验证（第 35 章会讲）。

mermaid
flowchart LR
    subgraph 你的电脑
        B[浏览器] -->|http://localhost| L[本地环境<br/>服务器+PHP+MySQL]
        L --> F[(本地文件/数据库)]
    end
    V[访客] -.本地环境访问不到.-> L
    V -->|https://你的域名| P[生产环境<br/>云主机]

2.1.2 操作方法：本地练习的四个好处 ​

  1. 安全试错：主题改白屏了、插件冲突了、数据库清空了，最坏结果就是删掉重建，不影响任何真实访客和数据。
  2. 离线可用：地铁上、飞机上、网络不稳定时照样开发调试，不依赖外网（只有在线安装主题/插件、访问字体与头像等场景需要联网）。
  3. 速度快：文件读写不走网络，保存即刷新；调试代码、批量导入数据效率远高于线上。
  4. 与生产隔离：你可以随便升级 PHP、试用 100 个插件、更换 10 个主题，把「验证过的方案」再搬到生产环境，避免拿正式站当小白鼠。

2.1.3 常见问题：本地环境的三个认知误区 ​

  • 误区 1：本地搭好，别人就能访问了。 不能。localhost / 127.0.0.1 永远指向「当前这台电脑自己」。想让外网访问，需要部署到服务器（第 03 章）或使用 Local 的 Live Link 之类的内网穿透服务临时演示。
  • 误区 2：本地环境就是最终环境。 本地软件栈与线上主机存在配置差异（PHP 扩展、Nginx/Apache、HTTPS），上线前必须在类生产环境验证，不能想当然。
  • 误区 3：装一次本地环境就一劳永逸。 学习过程中你可能要同时维护多个站点、切换 PHP 版本、对比不同方案，本章的 Docker 与 Local 正是为此而生。

2.2 本地环境四件套原理 ​

2.2.1 原理说明：四件套如何协作 ​

一个能跑 WordPress 的本地环境，本质是在一台机器内模拟第 01 章那张请求流转图：

组件本地环境中的角色常见软件默认端口
Web 服务器监听 HTTP 请求、提供静态文件、把 PHP 请求转交给 PHPApache、Nginx80（HTTP）/ 443（HTTPS）
PHP 运行时解释执行 WordPress 代码PHP（mod_php / PHP-FPM）无固定端口（FastCGI 常见 9000）
数据库存储站点数据MySQL、MariaDB3306
浏览器发起请求、渲染返回的 HTMLChrome、Edge、Firefox、Safari—

XAMPP / MAMP 这类「集成包」就是把前三件套预先打包好，再附赠 phpMyAdmin 等管理工具，省去手工编译安装的麻烦。名字的由来也直白：X（跨平台）+ Apache + MySQL + PHP + Perl。

2.2.2 hosts 解析：域名是怎么找到服务器的 ​

浏览器输入网址后，先要把域名解析成 IP。解析顺序的第一站通常是本机的 hosts 文件，其中的静态记录优先于 DNS：

text
# 典型的 hosts 记录：IP 在前，域名在后
127.0.0.1   localhost
127.0.0.1   wp-academy.local

加了第二行后，在本机访问 wp-academy.local 就会指向本机的 127.0.0.1。Local 这类工具创建站点时会自动帮你写 hosts，XAMPP 则默认直接用 http://localhost/子目录 访问，不需要改 hosts。

2.2.3 为什么不能双击打开 PHP ​

.php 文件本质是文本，浏览器没有能力执行其中的 PHP 代码。直接双击打开，要么显示源码，要么浏览器尝试下载。正确的链路必须是：

text
浏览器 → Web 服务器（发现是 .php 请求）→ PHP 解释器执行 → 生成 HTML → 原路返回浏览器

所以「搭建本地环境」=「把 Web 服务器和 PHP 解释器跑起来」，没有捷径。

2.2.4 认识端口 ​

一台电脑上可以同时跑很多网络程序，靠端口号区分。比如 MySQL 占用 3306、Apache 想占 80。端口冲突是新手安装时最常见的报错来源（详见 2.10 节）：

端口默认归属冲突高发原因
80HTTP Web 服务Windows 的 IIS、Skype、其他 Web 服务器
443HTTPS Web 服务同上，VMware、其他代理软件也可能占用
3306MySQL本机已装过 MySQL/MariaDB

2.3 四套方案对比与选择 ​

方案平台上手成本特色适合人群
XAMPPWindows / macOS / Linux低免费老牌、Apache+MariaDB+PHP 全家桶、贴近传统共享主机想理解「手工放程序、手工建库」完整过程的初学者
MAMPmacOS（体验最佳）/ Windows低macOS 原生体验好，PHP 多版本一键切换，默认 8888 端口少冲突Mac 用户、需要频繁切换 PHP 版本的人
LocalWindows / macOS / Linux极低专为 WordPress 设计：建站向导、自动装好 WP、自带 SSL、Blueprint 快照、Live Link想最快开始练 WordPress、需要多站管理的人
Docker全平台中容器化、配置即代码、可复现、最贴近生产架构，教程配套即用开发者、运维，以及想养成工程化习惯的人

📌 本章要求至少完整跟做两套方案（推荐 XAMPP + Local，或直接用 Docker 作为长期主力 + Local 做快照演示）。方案不是越多越好，最终选定一套主力即可。

2.4 方案 A：XAMPP（全平台） ​

2.4.1 原理说明 ​

XAMPP 由 Apache Friends 维护，完全免费，官网 https://www.apachefriends.org/。它把 Apache、MariaDB（MySQL 的社区分支，命令与客户端完全兼容）、PHP、perl 打包，并附带 phpMyAdmin 图形化数据库管理工具。

2.4.2 操作方法：下载与安装 ​

Windows：

  1. 打开 https://www.apachefriends.org/，点击 Download 下载最新 PHP 8.3 系列对应的 Windows 安装包（.exe）。
  2. 双击安装包，出现 UAC 用户账户控制提示时点击「是」。
  3. 安装路径不要选 C:\Program Files 或 C:\Program Files (x86)：受 UAC 保护的目录会导致配置文件写入失败。官方建议直接装到 C:\xampp。
  4. 组件页保持默认勾选（Apache、MySQL、PHP、phpMyAdmin）即可，一路 Next 完成安装。
  5. 安装结束时勾选「Do you want to start the Control Panel now?」启动控制面板。

macOS：

  1. 在同一页面下载与芯片匹配的安装包（Apple Silicon 选 ARM 版，Intel 选 x64 版；不确定芯片时点屏幕左上角 → 「关于本机」查看）。
  2. 双击挂载下载的 .dmg 文件。
  3. 在弹出窗口中把 XAMPP 图标拖入 Applications 文件夹。
  4. 从「启动台」或「应用程序」中打开 XAMPP，首次打开若提示「无法验证开发者」，到「系统设置 → 隐私与安全性」中点击「仍要打开」。

Linux（以 Ubuntu/Debian 为例）：

  1. 下载对应架构（64 位选 x64）的 .run 安装脚本。
  2. 赋予可执行权限并运行安装器（图形向导与另两平台一致）：
bash
# 赋予执行权限并启动图形安装向导
chmod +x xampp-linux-*-installer.run
sudo ./xampp-linux-*-installer.run
  1. 安装完成后，XAMPP 位于 /opt/lampp，控制面板与启停命令为：
bash
# 命令行方式启停（Linux 无 XAMPP 图形面板时最常用）
sudo /opt/lampp/lampp start
sudo /opt/lampp/lampp stop
sudo /opt/lampp/lampp restart
# 打开图形控制面板
cd /opt/lampp
sudo ./manager-linux-x64.run

2.4.3 启动服务并认识控制面板 ​

  1. 打开 XAMPP Control Panel（Windows 在开始菜单搜索「XAMPP Control Panel」；macOS 在应用程序中打开后切到 Manage Servers 标签）。
  2. 在 Windows 版面板中找到 Apache 与 MySQL 两行，分别点击对应的 Start 按钮。
  3. 模块名变为绿色、PID 与 Port 列出现数字，即表示启动成功。
  4. 打开浏览器访问 http://localhost 或 http://localhost/dashboard/，看到 XAMPP 欢迎页说明 Web 服务器与 PHP 正常。

图 02-1：XAMPP 控制面板中 Apache 与 MySQL 已启动（绿色高亮）

2.4.4 修改 MySQL root 密码并登录 phpMyAdmin ​

原理说明：XAMPP 里 MariaDB 的 root 用户默认空密码，这在本地练习无妨，但务必知道这是默认状态，绝不能把同样配置带上生产。

操作步骤（Windows/macOS/Linux 通用，通过 phpMyAdmin）：

  1. 确认 Apache 与 MySQL 都在运行，浏览器打开 http://localhost/phpmyadmin（Linux 版同为该地址）。
  2. 顶部点击 用户账户（User accounts）标签。
  3. 找到主机为 localhost 的 root 行，点击「修改权限 / Edit privileges」。
  4. 点击「修改密码 / Change password」，输入新密码两次（建议用密码管理器生成并本地保存），点击「执行 / Go」。
  5. 打开 XAMPP 的 phpMyAdmin 配置文件，把密码同步进去，否则 phpMyAdmin 会报拒绝访问：
ini
; XAMPP 中 phpMyAdmin 的配置文件位置
; Windows : C:\xampp\phpMyAdmin\config.inc.php
; macOS   : /Applications/XAMPP/xamppfiles/phpmyadmin/config.inc.php
; Linux   : /opt/lampp/phpmyadmin/config.inc.php
; 将其中的空密码改为你刚设置的密码
; $cfg['Servers'][$i]['password'] = '你的新密码';

练习提示：本地学习也可以不改密码，保持空密码能减少新手排障成本。但要把「默认空密码」这件事记牢，第 03 章讲生产环境时我们会用最小权限 + 强密码的正确姿势。

2.4.5 创建数据库 ​

WordPress 安装前需要一个空数据库。在 phpMyAdmin 中：

  1. 点击左侧栏顶部的 新建 / New。
  2. 输入数据库名，例如 wp_academy。
  3. 排序规则（Collation）选择 utf8mb4_general_ci 或 utf8mb4_unicode_ci（第 03 章解释区别），点击「创建 / Create」。
  4. 左侧出现 wp_academy 即成功，此时库里还没有任何表——WordPress 安装时会自动建表。

命令行等价做法（可选，了解即可）：

bash
# 通过 XAMPP 自带的 mysql 客户端建库（-u 指定用户，-p 会提示输入密码）
/Applications/XAMPP/xamppfiles/bin/mysql -u root -p
sql
-- 创建数据库，字符集使用 utf8mb4（支持 Emoji 与生僻字）
CREATE DATABASE wp_academy
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

2.4.6 把 WordPress 放进 htdocs ​

  1. 先按第 04 章的方式从 https://wordpress.org/download/ 或 https://cn.wordpress.org/ 下载最新版压缩包并解压。
  2. 找到 XAMPP 的网站根目录：
系统htdocs 路径
WindowsC:\xampp\htdocs
macOS/Applications/XAMPP/xamppfiles/htdocs
Linux/opt/lampp/htdocs
  1. 把解压出的 wordpress 文件夹整个复制进去。
  2. 浏览器访问 http://localhost/wordpress，出现 WordPress 安装向导即说明程序与环境联通（完整安装流程见第 04 章）。

2.4.7 常见问题：端口冲突 ​

现象：点击 Start 后 Apache 报错 Port 80 in use / Apache shutdown unexpectedly，或启动几秒后自动停止。

Windows 排查：

  1. 以管理员身份打开命令提示符（开始菜单搜索 cmd → 右键「以管理员身份运行」）。
  2. 查占用：netstat -ano | findstr :80，最后一列数字是占用进程的 PID。
  3. 在「任务管理器 → 详细信息」中按 PID 找到程序名。常见元凶：IIS（万维网发布服务）、Skype、其他集成环境。
  4. 处理方式二选一：停掉冲突程序/服务；或在 C:\xampp\apache\conf\httpd.conf 中把 Listen 80 改为 Listen 8080，之后用 http://localhost:8080 访问。HTTPS 端口 443 冲突时改 httpd-ssl.conf 里的 Listen 443。

macOS 排查：

  1. macOS 自带 Apache（httpd），先确认并关闭它：
bash
# 查看 80 端口被谁占用（需要 sudo 才能看到进程名）
sudo lsof -iTCP:80 -sTCP:LISTEN
# 停用 macOS 自带 Apache
sudo apachectl stop
# 防止重启后自动拉起
sudo launchctl unload -w /System/Library/LaunchDaemons/org.apache.httpd.plist 2>/dev/null
  1. 同样可以在 XAMPP 中改端口避开冲突。

Linux 排查：

bash
# ss 是现代发行版推荐的端口查看工具，-t TCP / -p 显示进程 / -l 仅监听端口
sudo ss -tlnp | grep -E ':80|:443|:3306'
# 老系统可用 lsof / netstat
sudo lsof -iTCP:80 -sTCP:LISTEN

2.5 方案 B：MAMP（macOS / Windows） ​

2.5.1 原理说明 ​

MAMP = Mac + Apache + MySQL + PHP，最早是 macOS 上的经典集成包，后来也推出了 Windows 版。它与 XAMPP 的关键差异：默认使用 8888 端口，几乎不与系统服务冲突；PHP 版本切换是图形化一键操作。官网 https://www.mamp.info/，免费版足够本教程使用。

2.5.2 操作方法 ​

  1. 官网下载 MAMP（注意选择免费的 MAMP，而非 MAMP PRO 试用版），macOS 将 MAMP 拖入「应用程序」，Windows 运行安装向导。

  2. 打开 MAMP，点击 Preferences（设置）。

  3. 切到 Ports 标签：

    • 点击「Set Web & MySQL ports to 8888 & 8889」使用默认推荐端口；
    • 若想模拟生产的标准端口，可点「Set ports to 80, 443 & 3306」，但可能需要输入管理员密码并处理端口冲突。

图 02-2：MAMP Preferences 中 Ports 标签与 PHP 版本选择

  1. 切到 PHP 标签，从下拉菜单选择 PHP 8.3.x（列表中没有 8.3 时，先到 MAMP 官网/偏好设置中安装更多 PHP 版本）。

  2. 切到 Server 标签（macOS 版在 Document Root 区域），点击 Choose… 设定网站根目录：

    • 默认为 /Applications/MAMP/htdocs；
    • 建议为每个站点建一个子文件夹，如 /Applications/MAMP/htdocs/wp-academy。

  3. 点击 OK 保存，回到主界面点击 Start Servers。右上角两个服务指示灯变绿即成功。

  4. 浏览器访问 http://localhost:8888/（或你自定义的端口）看到 MAMP 欢迎页；点击工具栏上的 Tools → phpMyAdmin 即可进入数据库管理，建库步骤与 2.4.5 节完全相同。

  5. 将 WordPress 文件放入 Document Root 后，访问 http://localhost:8888/wordpress 进入安装向导。

2.5.3 常见问题 ​

  • Apache 无法启动：80 端口被占时改回 8888；macOS 上先执行 sudo apachectl stop。
  • 选择 PHP 8.3 后启动失败：个别旧 MAMP 版本对最新 PHP 支持滞后，升级 MAMP 本体或改选 8.2（兼容范围内）。
  • 数据库连接不上：MAMP 的 MySQL 端口是 8889，在 WordPress 安装向导的「数据库主机」一栏要填 localhost:8889（XAMPP 用默认 3306，填 localhost 即可）。

2.6 方案 C：Local（专为 WordPress 设计） ​

2.6.1 原理说明 ​

Local（WP Engine 出品，官网 https://localwp.com/）是一个「WordPress 站点管理器」：每个站点拥有独立的 PHP、数据库与 Web 服务器配置（底层按站点自动编排），新建站点时WordPress 程序自动装好，并自带 Adminer 数据库工具、本地可信 SSL 证书、快照与临时公网演示链接。它是目前最省心的图形化方案。

2.6.2 创建第一个站点 ​

  1. 官网下载安装 Local（Windows 运行安装程序；macOS 拖入应用程序；Linux 提供 deb/rpm 包，sudo dpkg -i local-linux.deb 安装）。首次启动可能提示安装虚拟网卡与管理助手，按提示授权即可。

  2. 点击左下角 + Create a new site（或中间的「Create New Site」大按钮）。

  3. 第 1 步：输入站点名，如 wp-academy，点击 Continue。Local 会据此生成默认域名 wp-academy.local。

    • PHP 版本：选 8.3；
    • Web 服务器：nginx 或 Apache（练习默认 nginx，想验证 .htaccess 时选 Apache）；
    • 数据库：MySQL 8.0。

2.6.3 一键启用本地 HTTPS ​

  1. 在站点详情页切到 SSL（或 Overview 中 Trust 区域）。
  2. 点击 Trust SSL certificate，macOS 会弹钥匙串授权、Windows 会将证书加入受信任根，输入系统密码确认。
  3. 之后用 https://wp-academy.local 访问时浏览器地址栏是正常小锁，不会报警——这对练习支付、Service Worker、安全 Cookie 等必须 HTTPS 的功能非常重要。

2.6.4 Blueprint 快照：把「调好的站」存成模板 ​

原理说明：Blueprint（蓝图）是 Local 把当前站点的文件与数据库整体存成模板的功能。以后新建站点可直接基于蓝图生成，跳过装插件、调设置的重复劳动。

  1. 先把站点调成你想要的「基线状态」，例如：装好中文语言包、固定链接改为文章名、安装好 2–3 个常用插件。
  2. 在站点名称右侧的三点菜单中选择 Save as Blueprint。
  3. 为蓝图命名，如 教学基线-7.1-php83，确认保存。

  1. 下次新建站点时，在向导第一步选择 Use a Blueprint，选中该模板即可秒建同款站点。

💡 Local 还提供站点级导出（右键站点 → Export，得到可迁移的压缩包）与 Live Link：点击后生成一个临时公网网址，把本地站演示给别人看。Live Link 仅用于临时演示，不要当生产环境用。

2.6.5 常见问题 ​

  • Apple Silicon 首次启动慢/拉取失败：新版 Local 已原生支持 ARM，若个别组件卡住，可在站点设置中切换 PHP/服务器版本触发重新下载，并保持网络畅通。
  • 浏览器提示 wp-academy.local 打不开：检查 Local 是否在运行（站点为绿色）；Windows 上确认其管理服务与 hosts 写入未被安全软件拦截。
  • 想用自己熟悉的数据库客户端：在 Database 标签可看到 host、端口、用户名、密码（默认 root/root），用 TablePlus、DBeaver 等走 TCP 连接即可。

2.7 方案 D：Docker（教程配套方案） ​

2.7.1 原理说明 ​

Docker 把应用及其依赖装进隔离容器，用一份 docker-compose.yml 描述「WordPress 容器 + MySQL 容器 + WP-CLI 容器」如何组网，任何装了 Docker 的机器执行同一条命令都能得到一致环境。这正是本教程的配套方案，配套文件见 examples/docker-compose.yml 与 examples/.env.example。

前置条件：安装 Docker Desktop（https://www.docker.com/，Windows/macOS）或 Docker Engine + Compose v2（Linux，要求 24+）。安装后在终端验证：

bash
# 验证 Docker 与 Compose v2 可用
docker --version
docker compose version

2.7.2 逐段读懂 docker-compose.yml ​

配套编排文件由三个服务组成，结构如下（注释版见配套文件）：

yaml
# ① 数据库服务：MySQL 8.0
services:
  db:
    image: mysql:8.0            # 官方 MySQL 8.0 镜像
    container_name: wp-academy-db
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}   # 密码来自 .env，不写死在文件里
      MYSQL_DATABASE: ${DB_NAME}                 # 首次启动自动建库
      MYSQL_USER: ${DB_USER}                     # 自动创建最小权限业务用户
      MYSQL_PASSWORD: ${DB_PASSWORD}
    volumes:
      - db_data:/var/lib/mysql   # 数据持久化到数据卷，删容器不丢数据
      - ./config/mysql.init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
yaml
  # ② WordPress 服务：官方 WordPress 镜像（内含 Apache + PHP）
  wordpress:
    image: wordpress:php8.3-apache    # PHP 8.3 + Apache 的官方镜像标签
    container_name: wp-academy-app
    restart: unless-stopped
    depends_on:
      - db
    ports:
      - "${WP_PORT:-8080}:80"         # 本机 8080 映射到容器 80，避免与本机 80 冲突
    environment:
      WORDPRESS_DB_HOST: db:3306      # 容器之间用服务名 db 互访
      WORDPRESS_DB_NAME: ${DB_NAME}
      WORDPRESS_DB_USER: ${DB_USER}
      WORDPRESS_DB_PASSWORD: ${DB_PASSWORD}
    volumes:
      - wp_data:/var/www/html         # WordPress 程序持久化
yaml
  # ③ WP-CLI 服务：装站、装插件、跑维护脚本用（第 04、37 章常用）
  wpcli:
    image: wordpress:cli
    user: "33:33"                     # 容器内 www-data 用户，保证文件属主一致
    depends_on:
      - wordpress
    volumes:
      - wp_data:/var/www/html
    profiles: ["cli"]                 # 带 profile，不会随 up 默认启动，按需调用
volumes:
  db_data:
  wp_data:

配套的 .env.example 用来配置不应该写死在版本库里的变量：

ini
# .env.example：复制为 .env 后按需修改
DB_NAME=wp_academy            # 数据库名
DB_USER=wp_academy            # WordPress 使用的数据库账号（最小权限，不用 root）
DB_PASSWORD=请改成强密码        # 业务账号密码
DB_ROOT_PASSWORD=请改成更强密码 # root 管理员密码
WP_PORT=8080                  # 本机访问端口
WP_URL=http://localhost:8080  # 站点地址

2.7.3 启动与初始化 ​

  1. 进入配套代码目录，复制环境变量模板：
bash
cd examples
cp .env.example .env
# 用任意编辑器修改 .env 中的两个数据库密码
  1. 拉取镜像并在后台启动全部服务（-d = detached，后台运行）：
bash
# 首次执行会下载镜像，耗时取决于网速
docker compose up -d
# 查看运行状态，三个相关容器应为 healthy/running
docker compose ps
  1. 打开浏览器访问 http://localhost:8080，此时会看到 WordPress 安装向导。
  2. 更省事的方式是运行教程配套初始化脚本 examples/bin/setup.sh，它通过 WP-CLI 自动完成「安装站点 → 写入基础设置 → 激活教学主题插件」：
bash
# 赋予执行权限（仅首次需要）并运行
chmod +x ./bin/setup.sh
./bin/setup.sh

脚本内部等价于第 04 章的 WP-CLI 无人值守安装，核心调用包括：

bash
# 在 wordpress 容器内执行 WP-CLI（--add-host 让 cli 容器能访问到站点）
docker compose run --rm wpcli wp core install \
  --url="${WP_URL}" \
  --title="WordPress 从入门到精通" \
  --admin_user="${WP_ADMIN_USER}" \
  --admin_password="${WP_ADMIN_PASSWORD}" \
  --admin_email="${WP_ADMIN_EMAIL}"
  1. 访问 http://localhost:8080 看前台，http://localhost:8080/wp-admin 进后台。

常用日常命令：

bash
docker compose stop     # 停止（保留数据，下次 start 秒开）
docker compose start    # 再次启动
docker compose down     # 停止并删除容器（数据卷保留，数据不丢）
docker compose logs -f  # 跟踪查看日志，排错必备

⚠️ docker compose down -v 会连同数据卷一起删除，练习站会被完全清空——想「推倒重来」时才用。

2.8 跨平台通用：hosts 与本地 HTTPS ​

2.8.1 hosts 文件位置与编辑 ​

系统hosts 文件路径编辑方式
WindowsC:\Windows\System32\drivers\etc\hosts用管理员身份打开记事本再编辑，直接拖文件进普通记事本会无法保存
macOS/etc/hosts终端 sudo nano /etc/hosts，或 sudo open -e /etc/hosts
Linux/etc/hosts同上，需要 sudo 权限

加入一行示例（Local 一般自动写入，手工环境才需要）：

text
127.0.0.1   wp-academy.local

保存后立即生效，无需重启；浏览器可用 ipconfig /flushdns（Windows）或 sudo dscacheutil -flushcache（macOS）刷新 DNS 缓存。

2.8.2 用 mkcert 给本地站做可信 HTTPS ​

XAMPP/MAMP/Docker 环境想模拟生产 HTTPS，推荐 mkcert（https://github.com/FiloSottile/mkcert），它在本机生成一个本地 CA 并自动信任，浏览器不会报警：

bash
# macOS 安装（Windows 可用 scoop/choco，Linux 见项目 README）
brew install mkcert nss
mkcert -install                           # 生成本机 CA 并加入系统信任
mkcert wp-academy.local localhost 127.0.0.1   # 为本地域名签发证书

把生成的 .pem 证书配到 Apache/Nginx 即可（第 03 章有生产环境的 Let's Encrypt 方案，本地用 mkcert 足够）。

2.9 验证安装是否成功 ​

无论用哪套方案，完成 WordPress 安装后（安装过程见第 04 章），按下面清单自检：

  1. 前台：浏览器打开站点地址，看到默认主题的示例页面，无乱码。
  2. 后台：访问 /wp-admin，用管理员账号能登录，看到控制台（Dashboard）。
  3. PHP 信息：后台「工具 → 站点健康 → 信息」标签可看到 PHP 与数据库版本；或安装一个临时 phpinfo 插件查看（看完即删）。命令行方式：
bash
# 列出已加载的 PHP 扩展，与第 03 章扩展清单对照（Docker 内执行）
docker compose exec wordpress php -m
php -v   # 查看 PHP 版本，确认是 8.3.x
  1. 中文环境：后台「Settings → General」或「设置 → 常规」中界面语言选「简体中文」（中文包安装时已选则无需操作）。
  2. 固定链接：第 04 章安装完成后把固定链接改为「文章名」，点开一篇文章不出现 404，说明重写规则正常。

2.10 常见问题速查 ​

现象可能原因解决办法
Apache/nginx 启动报 80/443 被占用IIS、Skype、自带 Apache、其他集成环境见 2.4.7：netstat/lsof/ss 查占用，改端口或停冲突程序
MySQL 启动报 3306 被占用本机已装 MySQL/MariaDB 服务停用旧服务（Windows 服务管理；macOS brew services stop mysql），或把集成环境数据库改到 3307
浏览器打不开 localhost服务没启动 / 端口不是 80确认面板指示灯；带端口访问如 http://localhost:8080
Docker 容器连不上数据库db 容器尚未就绪 / 用了 localhostWordPress 容器内 localhost 指容器自身；连库主机要用服务名 db；等 db healthy 后重试
Linux 下 docker 命令报 permission denied当前用户不在 docker 组sudo usermod -aG docker $USER 后重新登录；不要长期用 sudo 或 chmod socket
Apple Silicon 镜像警告 platform镜像仅有 x64 版本优先选支持 arm64 的镜像（mysql:8.0、wordpress 官方镜像均支持），确无原生版再用 x64 模拟（Rosetta 2）
改了文件前台不变缓存 / 改错目录确认改的是当前站点 htdocs 或挂载目录；清浏览器缓存与插件缓存
文件上传/更新插件要求 FTP 凭据文件属主与 PHP 运行用户不一致本地可在 wp-config.php 加 define('FS_METHOD','direct');（第 04 章详讲，生产慎用）
Windows 下 phpMyAdmin 拒绝 root 登录改了 root 密码没同步配置修改 config.inc.php 中的 password，见 2.4.4

本章总结 ​

  • 本地环境 = Web 服务器 + PHP + MySQL/MariaDB + 浏览器，跑在本机，与生产隔离，是安全试错的沙盒。
  • 浏览器靠 hosts（优先）→ DNS 解析域名；localhost 永远指向本机；端口冲突是 80/443/3306 最常见的坑。
  • 四套方案定位不同：XAMPP 适合理解全过程（htdocs 放程序、phpMyAdmin 建库）；MAMP 在 Mac 上省心（8888、PHP 切换）；Local 一键装 WP + SSL + Blueprint；Docker 可复现、贴近生产，是本教程配套方案。
  • Docker 配套链路：cp .env.example .env 改密码 → docker compose up -d → ./bin/setup.sh 初始化 → 访问 http://localhost:8080。
  • 本地 HTTPS：Local 一键信任证书；其他环境用 mkcert。生产环境的证书方案在第 03 章。
