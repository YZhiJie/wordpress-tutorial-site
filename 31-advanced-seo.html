第 31 章 高级 SEO 技术 ​

🟡 中级难度 ｜ 一句话导览：SEO 插件负责点击级配置，本章深入策略与技术细节——从结构化数据、面包屑、canonical 深度、robots.txt 与 meta robots 分工，到 XML 站点地图细节、内链策略、多语言 hreflang，帮你把 WordPress 站点的搜索可见性从「能搜到」推进到「搜得好」。

学习目标 ​

  • 能写出正确的 Schema.org JSON-LD，区分「插件自动生成」与「手工 wp_head 输出」两种 WP 实现方式
  • 理解 canonical 的深度用法：分页不重复、跨域重复内容、参数 URL 规范化
  • 理清 robots.txt 与 meta robots 的分工，知道 Disallow 不防索引
  • 掌握 XML 站点地图的提交流程与图片站点地图的取舍
  • 会设计站内链接结构：枢纽页、上下文链接、相关文章
  • 理解多语言 SEO 中 hreflang 概念，知道 WPML/Polylang 的处理方式
  • 能排查收录慢、重复标题、结构化数据报错三类高频问题

31.1 结构化数据 Schema.org ​

31.1.1 原理说明 ​

搜索引擎在抓取页面时不仅看文字，还会解析页面中的结构化数据来理解「这是什么实体」。Schema.org 是 Google、Bing、Yandex 共同维护的词汇表，WP 站点最常见的类型有：

  • Article：博客文章、新闻；
  • BreadcrumbList：面包屑路径；
  • FAQPage：问答页；
  • Organization：组织/公司；
  • WebSite：搜索框候选。

当 Google 识别出丰富结构化数据，可能在搜索结果页直接展示富摘要（标题下多一行星级评分、价格、面包屑等），点击率显著提升。

31.1.2 操作方法 ​

方式一：插件自动生成（推荐，省维护成本）

Yoast SEO / Rank Math 在启用「Schema」模块后，自动按内容类型输出 JSON-LD：文章 → Article，首页 → WebSite+Organization 等。安装后无需额外代码。

方式二：手工输出（特殊类型或定制字段时用）

把 JSON-LD 内嵌进 <script type="application/ld+json">，用 wp_head 或 wp_footer 钩子注入。必须配合 WordPress 的转义函数：

php
// 主题 functions.php：为特定自定义文章类型输出 FAQ 结构化数据
add_action( 'wp_head', function () {
	// 仅在 FAQ 页面输出，避免每个页面都带无关 schema
	if ( ! is_singular( 'faq' ) ) {
		return;
	}

	$faqs = get_field( 'faq_list' ); // 假设使用 ACF 存储问答对
	if ( empty( $faqs ) ) {
		return;
	}

	$items = [];
	foreach ( $faqs as $i => $faq ) {
		$items[] = [
			'@type'          => 'Question',
			'name'           => esc_html( $faq['question'] ),
			'acceptedAnswer' => [
				'@type' => 'Answer',
				'text'  => wp_kses_post( $faq['answer'] ),
			],
		];
	}

	$schema = [
		'@context'   => 'https://schema.org',
		'@type'      => 'FAQPage',
		'mainEntity' => $items,
	];

	// 用 wp_json_encode 而非 json_encode，后者不保证对中文做正确转义
	printf(
		"<script type=\"application/ld+json\">%s</script>\n",
		wp_json_encode( $schema, JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES )
	);
} );

安全注意：

  • esc_html()：纯文本字段（标题、问题）转义 HTML 实体，防止注入；
  • wp_kses_post()：富文本字段（答案内容）只允许安全标签（<p><ul><li><strong> 等），剥离危险脚本；
  • 绝不用 echo $raw 或 json_encode() 后无转义直接输出。

31.1.3 验证流程 ​

写完或确认插件已输出后：

  1. 打开 Google 富媒体测试工具 或 Bing Markup Validator；
  2. 输入页面 URL 或粘贴源码；
  3. 逐项修正报错（常见：缺少 author、image 尺寸不合要求、dateModified 为空）。

⚠️ 使用插件自动生成时也要抽检：特别是自定义模板页、自定义字段驱动的内容，插件可能识别不出你的字段，schema 会漏字段或类型不对。

31.1.4 常见问题 ​

Q：富媒体测试提示「无效 JSON-LD」？ 九成是 JSON 语法问题：逗号多一个/少一个、字符串内未转义引号。把页面源码中 <script type="application/ld+json"> 的内容复制到 JSON Lint 在线校验器定位。WP 用 wp_json_encode() 比手工拼 JSON 安全得多。

31.2 面包屑导航（BreadcrumbList） ​

31.2.1 原理说明 ​

面包屑对 SEO 有两重价值：① Google 把它画进搜索结果标题下方（提升点击意图识别与 CTR）；② 用户可快速向上跳转（降低跳出率）。Schema.org 的 BreadcrumbList 与之配合：插件自动标注后搜索引擎更易识别层级。

31.2.2 操作方法：Yoast 面包屑主题集成 ​

Yoast SEO 提供面包屑函数，主题需显式输出（多数主题默认不自动调用）：

php
// 在 single.php / page.php 的合适位置（通常在文章标题上方）插入
if ( function_exists( 'yoast_breadcrumb' ) ) {
	yoast_breadcrumb(
		'<nav class="breadcrumbs" aria-label="面包屑导航">',
		'</nav>'
	);
}

CSS 基础美化示例：

css
.breadcrumbs {
	font-size: 0.875rem;
	color: #666;
	margin-bottom: 1rem;
}
.breadcrumbs a {
	color: #1a73e8;
	text-decoration: none;
}
.breadcrumbs a:hover {
	text-decoration: underline;
}

验证：前端源码查看是否出现 schema.org/BreadcrumbList 的 JSON-LD；富媒体测试也单独检验 Breadcrumb 类型。

31.3 Canonical 深度 ​

31.3.1 原理说明 ​

<link rel="canonical"> 告诉搜索引擎「这个 URL 的规范地址」，解决重复内容导致的权重分散。WordPress 中它很常见，但有几处深度场景容易踩坑。

31.3.2 分页 canonical 不自指争议 ​

对文章分页（.../p/2/）或分类列表分页（.../page/2/），有两种做法：

  • 自指：第 2 页 canonical 指向自己 /page/2/。逻辑：每一页内容不同，理应独立；
  • 指向首：全部指向首页 /。逻辑：避免整站分页沦为「低质重复内容」。

WP 插件（Yoast / Rank Math）默认采用自指，Google 的立场也支持自指（分页内容确实不同）。但内容量小且分页质量低的站，可在插件设置中改为指向首。关键是不要混用两种策略，混用会让搜索引擎困惑。

31.3.3 跨域重复内容与参数 URL ​

  • 跨域重复：站群或中/英站点间内容高度重复时，用 <link rel="canonical" href="https://example.com/原文/" /> 把中文页指向英文源文，避免互相抢排名。同时应给中文页加 hreflang 指向对应语种的自己（见 31.7）。
  • 参数 URL：/?utm_source=xxx、?page_id=123、?view=grid 等参数会产生不同 URL 但同内容的页面。SEO 插件会自动过滤常见跟踪参数；自定义参数（如 ?sort=price）若内容与默认页相同，应 canonical 回默认页：
php
// 示例：商品列表页含 ?sort= 参数时，canonical 永远指向不含 sort 的纯净 URL
add_filter( 'get_canonical_url', function ( $canonical_url ) {
	if ( is_post_type_archive( 'product' ) ) {
		$canonical_url = remove_query_arg( 'sort', $canonical_url );
	}
	return $canonical_url;
} );

31.4 robots.txt 与 meta robots 的分工 ​

31.4.1 原理说明 ​

两者常被混用，但作用域完全不同：

手段控制对象能否防索引场景
robots.txt爬虫能否抓取（爬取层面）不能。爬虫已知的 URL 仍可能在搜索结果标题只留 URL禁止爬虫访问某些目录（如/wp-admin），减少服务器负载
meta robots页面能否进入搜索结果（索引层面）能。noindex 让 Google 不收录该页感谢页、分页（低质页）、搜索结果页、用户档案页

31.4.2 正确配置 ​

robots.txt：Yoast SEO 自带编辑器，建议保留默认即可。但注意一点——wp-content/uploads/ 必须放行：

User-agent: *
Disallow: /wp-admin/
Disallow: /wp-includes/
Disallow: /wp-content/plugins/
Allow: /wp-content/uploads/

为什么 uploads 要放行？因为搜索引擎需要抓取图片才能在图片搜索中索引；同时结构化数据 Article 要求有图片，图片被拦会导致富媒体测试报错。

meta robots：Yoast / Rank Math 给每个页面/文章提供 noindex 开关，批量策略（如全部分类页 noindex）在插件「分类法」设置里配置。不要通过 robots.txt 的 Disallow 去阻止索引——Google 若通过外链知道了该 URL 存在，即使没有抓内容，仍可能在结果中只显示裸 URL。

31.4.3 常见问题 ​

Q：想阻止某个分类页被索引，但 robots.txt 里 Disallow: /category/old/ 无效？ 恰恰说明混淆了两者分工。正确做法：在 Yoast → 分类目录 → 找到该分类 → 设为 noindex。Disallow 只能减少爬虫来爬，不保证不索引；noindex 才是防收录的指令。

31.5 XML 站点地图细节 ​

31.5.1 原理说明 ​

XML 站点地图是搜索引擎的「楼层导航」：告诉爬虫哪些 URL 重要、何时更新过。但它不直接提高排名，只帮助更快更全地收录。

31.5.2 操作方法 ​

WordPress 5.5+ 核心自带基础站点地图：/wp-sitemap.xml。SEO 插件（Yoast / Rank Math）会生成更丰富版本的站点地图（含文章、分类、标签、自定义类型、作者）。配置流程：

  1. 插件里确认「XML Sitemaps」已启用，复制站点地图 URL（通常是 /sitemap_index.xml）；
  2. 提交到 Google Search Console（GSC）：GSC → 索引 → 站点地图 → 提交 URL；
  3. 同样提交到 Bing Webmaster Tools（一次提交会同步到 Bing、Yahoo、DuckDuckGo）；
  4. 后续页面发布/更新时，插件自动刷新站点地图，搜索引擎下次抓取即可感知。

关于优先级（priority）：2010 年前曾被认为影响抓取优先级，但 Google 已明确声明不再参考。插件生成的 priority 值只是兼容旧习惯，不必纠结调整。

图片站点地图：若站点有大量原创高质量图片（图库、电商、摄影站），可为图片单独生成站点地图并提交，提升图片搜索收录。小站图片不多时收益有限，用通用站点地图里的图片标签即可。

31.5.3 站点地图包含/排除策略 ​

站点地图不是「越多越好」——它应当只包含你希望被索引的优质页面。排除清单：已 noindex 的页面（插件会自动同步排除）、搜索结果页、标签数量稀少的标签页（31.10.7）、附件页（30.8.3 已重定向）。提交后在 GSC「站点地图」面板观察「已发现的网页」数量是否与你预期的页面总数吻合，差距大说明有页面没被收录进站点地图或大量薄页面混入。

31.6 内链策略 ​

31.6.1 原理说明 ​

外链决定「别人认不认可你」，内链决定「你认不认可自己」。内链是 WP 站点最有可控性的 SEO 手段：你写的每篇文章都在帮搜索引擎理解站点的层级与主题相关性。

搜索引擎顺着链接爬行分配权重：首页权重最高，离首页点击距离越近的页面获得的权重越多。内链策略的本质就是用链接结构投票，告诉搜索引擎哪些页面是站点的核心资产。

31.6.2 操作清单 ​

  1. 枢纽页（Pillar Page）：选一个核心关键词，写 2000+ 字的长文，深度覆盖主题；然后围绕它写 5~10 篇细分文章，每篇都链回枢纽页，枢纽页再链向每篇细分文。WP 中可用专题页或置顶文章实现。
  2. 上下文链接：正文里提到旧文章时，直接给关键词加超链（不要只写「点击这里」）。WP 古腾堡编辑器的链接面板支持搜索已有文章，很方便。
  3. 相关文章：在文章底部展示 3~5 篇同分类/同标签的相关文章。插件（Yet Another Related Posts Plugin / Rank Math 自带）可自动匹配；手动的做法是调用 get_posts：
php
// 当前文章底部展示同分类的 4 篇相关文章（排除自己）
$cat_ids = wp_get_post_categories( get_the_ID(), [ 'fields' => 'ids' ] );
$related = get_posts( [
	'category__in' => $cat_ids,
	'post__not_in' => [ get_the_ID() ],
	'posts_per_page' => 4,
	'orderby'        => 'rand',
] );
  1. 避免孤立页：每篇公开发布的文章至少被一个内部链接指向（首页最新文章列表也算）。全站若有大量孤立页，搜索引擎可能误判为低价值内容。

31.7 内容 SEO 基础与多语言 SEO ​

31.7.1 搜索意图与标题结构 ​

Google 排名已不只看关键词密度，核心指标是是否满足搜索意图。写内容前问自己：搜这个词的用户想要什么？（信息型/导航型/交易型）

标题层级规范：

  • 每个页面有且只有一个 H1（主题模板中的文章标题）；
  • H2~H6 按内容层级递进，不要跳级（H2 下用 H3，别直接跳 H4）；
  • 不要把层级当字号用：CSS 控制视觉大小，语义层级只负责结构。

URL 规范：短、含关键词、全小写、用连字符分隔。固定链接用 /%postname%/ 即可，WP 会自动把标题转 slug。

31.7.2 多语言 SEO：hreflang ​

多语言站点必须告诉搜索引擎「同一内容的不同语言版本互相关联」。核心机制是 <link rel="alternate" hreflang="...">，让搜索引擎向用户展示其语言版本的页面。

WordPress 多语言方案：

  • WPML：老牌，商业，翻译管理完善，自动生成 hreflang；
  • Polylang：免费版够用，手动给每篇文章指定语言，hreflang 由插件自动输出；
  • Weglot：SaaS 式翻译，自动生成语言子目录，hreflang 自动处理。

WPML / Polylang 的 hreflang 自动输出示例（出现在页面 <head> 中）：

html
<link rel="alternate" hreflang="zh-CN" href="https://example.com/seo/" />
<link rel="alternate" hreflang="en-US" href="https://example.com/en/seo/" />
<link rel="alternate" hreflang="x-default" href="https://example.com/seo/" />
<!-- x-default：当用户语言不在已有版本中时，回退到默认页 -->

关键规则：

  • 每个语言页都要互相指向对方，不能只单向指；
  • URL 要一一对应，语言 A 有、语言 B 没有的文章会报 hreflang 错误；
  • 翻译不是机翻硬上：低质量翻译比单语言站更伤 SEO。

31.8 速度与移动友好对排名的间接影响 ​

31.8.1 原理说明 ​

Google 反复确认：Core Web Vitals（速度）与移动友好性是排名信号，但权重有限——内容质量仍是首要。然而，糟糕的体验会产生间接排名惩罚：

  • 加载慢 → 用户快速回退 → 高跳出率、低停留时间 → 搜索引擎判定页面不相关；
  • 移动端排版错乱 → 用户无法阅读 → 同样的负反馈循环。

因此，速度优化（第 29 章）与图片优化（第 30 章）不只是「用户体验」的事，也是 SEO 的一部分。

31.8.2 移动友好自检清单 ​

Google 已全面转向移动优先索引——它抓取和评估的是你的移动版页面。自检四项：

  1. 响应式布局：任何设备宽度下无横向滚动条（DevTools 设备模拟各档宽度过一遍）；
  2. 可点击元素间距：按钮/链接不小于 44×44px 且不拥挤（GSC「移动设备易用性」报告会抓这项）；
  3. 字号可读：正文 ≥ 16px，小屏不缩放即可读；
  4. 无侵入式弹窗：移动端全屏订阅弹窗会被官方点名降权——改横幅或延迟触发。

31.9 404、重定向与常见误区 ​

31.9.1 404 与重定向策略 ​

删文章、改 slug、换固定链接结构都会产生旧 URL 的 404。处理原则：

  1. 有替代内容的旧 URL → 301 到最相关的新页面（改 slug 后 301 到新 slug；删除的文章 301 到同分类最相近的文章或分类页），权重得以传递；
  2. 彻底无替代 → 让它是 404 或 410（410 Gone 语义更明确，Google 会更快移出索引），不要全部 301 到首页——Google 视其为「软 404」，反而损害质量信号；
  3. 工具：Redirection 插件管理 301 规则并记录 404 日志，每周看一次 404 日志，把有外链/有流量的 404 逐一补重定向；GSC「索引 → 页面 → 未找到（404）」报告作为对照。

大批量 URL 变更（如整站换域名、换目录结构）时，在服务器层（Nginx rewrite 或 Apache RedirectMatch）写规则比在插件里逐条配置高效，且有规律可循时一条正则即可覆盖：

nginx
# 旧博客目录 /blog/xxx 整组迁移到根目录 /xxx
location /blog/ {
    rewrite ^/blog/(.*)$ /$1 permanent;   # permanent = 301
}

31.9.2 关键词研究基础 ​

SEO 插件提示的「焦点关键词」只是检查器，选什么词是策略问题。入门级流程：

  1. 头脑风暴 + 下拉词：在搜索引擎输入主题词，记录下拉联想与「相关搜索」；
  2. 看意图不看量：月搜 10 万的词你排不上去，月搜 500 的长尾词（「新生儿 摄影 布光 教程」）竞争小、意图明确、转化高。新站从长尾词起步；
  3. 一词一页：一个页面只主攻一个关键词及其同义词，避免多页自相竞争（keyword cannibalization）；
  4. 记录台账：建一张「关键词 → 对应文章 URL → 当前排名」的表，每月更新，看出趋势。

31.9.3 E-E-A-T 与内容质量信号 ​

Google 质量评估指南的核心概念 E-E-A-T（经验、专业、权威、可信）。对 WP 站点的落地动作：

  • 作者署名：文章页显示真实作者与简介（作者档案页写资历），YMYL（健康/理财等）领域尤其重要；
  • 关于页与联系方式：完整的 About、Contact 页面是信任基础分；
  • 引用来源：数据与观点给出来源链接，出站链到权威站点不是「权重流失」而是可信度信号；
  • 内容保鲜：教程类内容定期更新（更新后改 dateModified 并在文中标注更新日期），过时内容主动合并或 301。

误区事实

31.10 常见问题速查 ​

31.10.1 收录慢排查 ​

新站发布一周，Google 只收录了首页：

  1. GSC → 索引 → 页面 → 看「未被索引」列表，常见原因：被 robots.txt 拦住、页面报 noindex、服务器返回 404；
  2. 检查 robots.txt 是否意外 Disallow: /；
  3. 检查主题或插件是否在页面级加了 noindex（Yoast 文章元数据面板）；
  4. 提交站点地图，并在 GSC 的「URL 检查」里主动提交未收录的 URL；
  5. 看服务器访问日志（/var/log/nginx/access.log）确认 Googlebot（User-Agent 含 Googlebot）是否在抓取，抓取状态码是什么。

31.10.2 重复标题（分页页与首页标题相同） ​

分类首页标题「摄影教程」，第 2 页标题仍是「摄影教程」，GSC 提示「重复标题」：

  • 在主题中给分页标题加页码：
php
// 分类页/标签页分页时，标题后追加「 - 第 2 页」
add_filter( 'get_the_archive_title', function ( $title ) {
	if ( is_paged() ) {
		$title .= sprintf( __( ' - 第 %d 页', 'your-textdomain' ), get_query_var( 'paged' ) );
	}
	return $title;
} );
  • 或在 Yoast 的「分类归档 SEO 标题」模板中写入 %%term_title%% %%page%%，Yoast 自动处理分页后缀。

31.10.3 结构化数据报错逐项修 ​

GSC「增强功能」下出现红色报错时，按「错误类型 → 示例页面 → 查看源码」定位。常见报错与修复：

报错修复
Missing field author确认文章有作者；如是自定义模板页，手工输出 author 字段或禁用该类型 schema
Missing field image文章必须有特色图；如纯文字内容确实无图，改用不需要 image 的 schema 类型
Invalid date format确保 datePublished/dateModified 是 ISO 8601 格式（插件通常已处理）
Incomplete microdata混合使用 JSON-LD 与 microdata 造成冲突，统一用一种格式

31.10.4 GSC 提示「重复网页，用户未指定规范网页」 ​

说明 Google 发现了多个相似 URL（带参/不带参、www/非 www、http/https）且没收到明确 canonical 信号。检查：① 全站是否强制 301 到唯一主域（https + 带或不带 www 二选一）；② SEO 插件 canonical 是否开启；③ GSC「网址检查」看 Google 选的规范页与你预期是否一致，不一致则按上述补齐信号后提交重新索引。

31.10.5 改版/换主题后排名下跌 ​

先区分正常波动（一两周内）与事故：① 检查新主题是否改了标题结构（H1 丢失/重复）、是否输出了 noindex、面包屑与 schema 是否还在；② 确认 URL 结构未变，变了是否全部 301；③ 用「改版前后」的 WebPageTest/PSI 对比性能是否大幅退化（第 33 章）；④ 一切正常则观察 4~6 周，搜索引擎需要重新评估。

31.10.6 站点地图提交后显示「无法获取」 ​

GSC 提交站点地图后状态为「无法获取/Couldn't fetch」：① 先直接浏览器访问站点地图 URL 确认能打开（注意大小写与尾斜杠，GSC 对 URL 精确匹配）；② 确认 robots.txt 没有拦它；③ 确认服务器返回 200 且 Content-Type 是 XML——某些安全插件会拦陌生 UA，把 Googlebot 误挡；④ 都没问题时，删掉重新提交一次（GSC 的状态刷新本身有延迟，等 24~48 小时再看）。

31.10.7 标签页（tag）该不该被索引 ​

标签页内容通常与分类页、文章页高度重复，是薄内容重灾区。经验法则：标签数量少（<20）且每个标签下有 5 篇以上实质文章时可以保留索引；否则全站标签页设 noindex，权重集中到分类页。分类页同理——「未分类」这类空壳分类要么充实内容，要么 noindex。

31.10.8 改完 SEO 设置多久见效 ​

按改动类型预期：① 标题/描述的修改——重新抓取后数天~两周在搜索结果更新；② 新文章收录——小站数天，有权重的老站数小时；③ 结构化数据富摘要——数天~数周，且 Google 不保证展示；④ 排名变化——内容级改动以周~月计。GSC「效果」报告的点击/展现曲线是唯一可靠的观察口径，不要每天盯着排名工具焦虑。

动手练习 ​

练-31-01（操作题）｜验证并补充结构化数据

打开你的练习站任意一篇文章，用 Google 富媒体测试工具扫描，记录当前已识别的 schema 类型；然后在文章页手工通过 wp_head 输出一个自定义 Organization schema（含名称、URL、Logo），再测一次，对比两次结果并截图。

练-31-02（操作题）｜面包屑与分页 canonical

在主题中集成 yoast_breadcrumb()（31.2.2），刷新文章页确认面包屑可见；然后访问分类列表第 2 页，查看源码中 <link rel="canonical"> 的值，记录它是「自指」还是「指向首」。再在 Yoast 设置中切换两种模式，分别验证并说明你的站点更适合哪种。

练-31-03（操作题）｜robots.txt 与 meta robots 验证

故意制造一次错误：在某篇文章的 Yoast 面板设 noindex，同时 robots.txt 里 Disallow: / 全站拦截。用 GSC 的「URL 检查」工具提交该 URL，记录两个错误提示；然后分别只留 noindex（去掉 robots Disallow）、只留 Disallow（去掉 noindex），再次检查，对比三种情形下 Google 的行为差异。

练-31-04（思考题）｜内链结构设计

假设你要为摄影博客做一个「人像摄影」枢纽页。请画出枢纽页 → 细分文章的内链结构（至少 5 篇细分文章），并为每篇文章写出应从正文链回枢纽页的关键词锚文本。说明：为什么枢纽页模式对 SEO 比零散单篇文章更有效？

练-31-05（排错题）｜收录慢与重复标题

在练习站新建 5 篇文章并发布，记录 GSC 中它们被收录的耗时；检查分类分页页标题是否重复，若重复按 31.10.2 修复后提交 GSC 验证。总结：你站点收录慢的最可能瓶颈在哪一层（内容/抓取/索引/服务器）？
