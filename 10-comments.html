第 10 章 评论系统深度配置 🟡 ​

一句话导览：评论不是「文章底下几个输入框」那么简单——它有独立的数据表、四级状态的审核队列、可嵌套的层级结构和一整套反垃圾流水线。本章从 wp_comments 表讲起，逐项精讲讨论设置，搭好以 Akismet 为核心的反垃圾体系，最后写出第一段评论模板定制代码。

第 5 章我们知道了「设置 → 讨论」里三个最常用开关，第 6 章写文章时也见过「允许评论」的勾选框。但当站点开始有真实读者，问题会接踵而来：垃圾评论一夜几百条、读者回复盖了十几层楼、评论邮件通知收不到、想在评论表单里去掉「网站」输入框。本章把评论系统从数据库到模板一次性讲透。

学习目标 ​

  • 理解 wp_comments 表的核心字段、comment_parent 嵌套机制、comment_approved 审核队列与 pingback/trackback 的本质
  • 逐项掌握「设置 → 讨论」六个板块每个字段的行为与推荐配置
  • 熟练使用评论管理界面的四种状态、行内操作与批量操作
  • 能独立配置 Akismet 反垃圾，掌握关闭全站/单篇评论的所有路径
  • 看懂 comments.php、wp_list_comments()、comment_form() 的分工，会用过滤器移除网址字段、修改标题文案

10.1 评论系统的架构 ​

原理说明：wp_comments 表 ​

每一条评论是 wp_comments 表中的一行。核心字段与分工：

字段含义备注
comment_ID评论主键全站自增
comment_post_ID所属文章 ID关联 wp_posts.ID
comment_author / comment_author_email / comment_author_url访客的昵称、邮箱、网址未登录评论者填写的三项
comment_author_IP提交者 IP审核与封禁依据之一
comment_date / comment_date_gmt站点时区时间 / UTC 时间与文章的双时间设计一致
comment_content评论正文
comment_approved审核状态：'1' 已批准、'0' 待审、'spam' 垃圾、'trash' 回收站管理界面四个标签页的数据来源
comment_type评论类型：comment（空值等价）/ pingback / trackback见下文
comment_parent父评论 ID，0 表示顶级评论嵌套回复的全部秘密
user_id已登录用户的 ID，游客为 0
comment_karma内部计分，核心未使用留给插件

评论的扩展信息（如 Akismet 的判定历史）存在 wp_commentmeta 表，与 wp_postmeta 的设计完全对称。

层级嵌套：回复只是填了 parent 的评论 ​

「回复某条评论」本质上是插入一条 comment_parent = 被回复评论的 comment_ID 的新记录。前台的楼中楼缩进效果，是主题按父子关系递归渲染出来的。嵌套最多几层由「设置 → 讨论」控制（默认 5 层），超过层数的回复在视觉上退化为平铺，但 comment_parent 关系依然保留。

审核队列：comment_approved 的四级状态 ​

评论从提交到展示，全程只是在 comment_approved 的四个值之间流转：

text
 提交评论
    │
    ▼
 待审（'0'）──批准──▶ 已批准（'1'）──标垃圾──▶ 垃圾（'spam'）
    │                    │                        │ 误判
    ├──标垃圾────────────┼────────────────────────┤
    │                    ▼                        ▼
    └──丢回收站──▶ 回收站（'trash'）◀────恢复────┘
  • 「待审」只出现在命中审核规则时（见 10.2），否则评论直接进「已批准」并对前台可见。
  • 「垃圾」与「回收站」都可在后台一键恢复，区别是垃圾队列默认会被定期自动清空。

后台的每个审核动作，都只是对这一个字段的改写：

后台操作comment_approved 变化
批准'0' → '1'
标记为垃圾任意 → 'spam'
不是垃圾（恢复）'spam' → '1'
移至回收站任意 → 'trash'
还原'trash' → '1'
永久删除整行记录从表中删除

pingback 与 trackback：机器写的「评论」 ​

当别的博客文章链接到你的文章时，对方站点可以自动发一条通知，在你的文章下生成一条 comment_type 为 pingback 或 trackback 的特殊评论，内容通常是对方文章的标题与摘要。它们的初衷是博客间的引用互知，但现实中绝大多数 pingback/trackback 是垃圾引流，现代站点通常直接关闭（10.2 节）。删掉它们不影响任何真实评论。

操作方法：亲眼认识 pingback ​

  1. 保持「设置 → 讨论」中「允许其他博客发送链接通知」暂时开启。
  2. 在同一站点发布文章 A，再写文章 B 并在正文中放入 A 的完整链接，发布 B。
  3. 稍等片刻后打开 A 的评论区：会出现一条样式特殊的「评论」，内容形如「[…] 在《B》中提到了本文」——这就是站点自己发给自己的 pingback。
  4. 进「评论」列表找到它，悬停后点「回收站」删除；随后回讨论设置关闭链接通知（见 10.2 节）。

操作方法：在数据库里亲眼看评论落库 ​

  1. 前台打开一篇允许评论的文章，用游客身份填昵称、邮箱提交一条评论「数据库实验一号」。
  2. 打开本地数据库工具（phpMyAdmin / TablePlus），浏览 wp_comments 最后几行：找到该评论，观察 comment_approved 的值（取决于你的讨论设置）、comment_parent = 0、comment_type 为空。
  3. 回后台「评论」把它批准，刷新数据表：comment_approved 从 '0' 变为 '1'。
  4. 在前台对这条评论点「回复」再发一条：新行的 comment_parent 等于上一条的 comment_ID。
  5. 后台把第一条评论「移至回收站」：它的 comment_approved 变为 'trash'，前台两条评论同时消失（子评论随父级隐藏）。

常见问题 ​

  • 问：删除文章时，它的评论去哪了？ 答：一起删除。文章进回收站时评论随之隐藏，文章被永久删除时其评论也被清除——删除有大量评论的文章前请确认。
  • 问：为什么评论 ID 跳号？ 答：comment_ID 全站自增，垃圾评论、回收站清理都会消耗 ID，跳号属正常现象。
  • 问：登录用户发表评论和游客评论，在数据表里有何区别？ 答：登录用户的评论 user_id 字段会写入其账号 ID，comment_author 等字段取账号资料；游客评论 user_id 为 0，昵称邮箱来自表单填写。审核规则对两者一视同仁——除非开了「用户必须注册并登录才可以发表评论」，游客根本走不到落库这一步。

10.2 讨论设置逐项精讲 ​

「设置 → 讨论」共六个板块，下面逐块过一遍。

图 10-1：设置 → 讨论全貌：默认文章设置、其他评论设置、邮件通知、评论显示条件、评论审核、禁止关键词与头像设置

板块一：默认文章设置 ​

选项行为建议
尝试通知文章中链接到的所有博客你写文章引用别人时，向对方发 pingback随意，不影响本站
允许其他博客发送链接通知（pingback 和 trackback）到新文章接收别站的引用通知，生成特殊评论建议取消：绝大多数是垃圾引流
允许他人在新文章上发表评论全站评论总闸按站点性质决定；注意只影响设置之后发布的文章

板块二：其他评论设置 ​

选项行为
评论者必须填入姓名和电子邮件地址不填无法提交，建议开启（游客身份的最低门槛）
用户必须注册并登录才可以发表评论最严格，适合会员站；资讯站通常不开
自动关闭发布 X 天后的文章的评论功能老文章不再接收新评论，有效减少垃圾与「考古帖」争论；填 0 或不勾为不自动关闭
显示评论 cookies 选择框让游客勾选「记住我的信息」，建议开启
启用评论嵌套，最多 X 层楼中楼开关与深度，默认 5 层，2–5 均可
分页显示评论，每页 X 条评论超多的热门站开启，避免单页加载几百条
每页默认显示最后一个/第一个页面 + 评论按旧/新排序控制翻页与排序方向，配合分页使用

板块三：发送电子邮件通知我 ​

  • 「有人发表评论时」「有评论等待审核时」两封通知都发到管理邮箱（设置 → 常规里那个）。活跃站建议只留「等待审核」，否则信箱会被淹没。

板块四：在评论显示之前 ​

选项行为建议
评论必须经人工批准每条评论都进待审队列小站/低流量站最省心
评论者先前须有评论通过了审核首审制：老读者自动放行，新面孔进待审活跃站的推荐折中

两者都不勾则全部即时显示——只有配了强力反垃圾才敢这么玩。

板块五：评论审核 ​

  • 「当评论包含 X 个或更多超链接时放入待审队列」：垃圾评论的典型特征是堆链接，阈值 2 即可（0 会拦所有带链接的正常评论，1 太严）。
  • 下方文本框是审核关键词：每行一个词，评论的正文、作者名、邮箱、网址、IP 任一匹配即进待审。注意它匹配的是子串——写「 press」这类短词会误伤正常词。

板块六：禁止评论关键词 ​

每行一个词，命中后评论直接进回收站（不给你看的机会），同样匹配子串。用于明确的违禁词。与审核关键词的区别：审核 = 留待你裁决；禁止 = 直接丢弃。

板块七：头像 ​

  • 「显示头像」总开关；
  • 「最高等级」按 Gravatar 分级（G 全年龄 → X 限制级）过滤，一般保持 G；
  • 「默认头像」：评论者没有 Gravatar 时显示的占位图，可选神秘人、空白、Gravatar 标志、Identicon（抽象图形）、Wavatar、MonsterID（小怪物）等按邮箱哈希生成的图案。

操作方法：一套推荐的中等强度配置 ​

  1. 「设置 → 讨论」：取消「允许链接通知（pingback/trackback）」，保留「允许发表评论」。
  2. 勾选「评论者必须填姓名和邮箱」「显示 cookies 选择框」，嵌套保持 5 层。
  3. 邮件通知只勾「有评论等待审核时」。
  4. 评论显示条件勾「评论者先前须有评论通过了审核」。
  5. 链接阈值设 2；审核关键词框留空（先靠 Akismet，误杀多了再补词）。
  6. 保存更改，用无痕窗口以游客身份发一条评论验证：应进入待审队列。

常见问题 ​

  • 问：讨论设置改了，旧文章没变化？ 答：「默认文章设置」板块的三个选项都只作用于设置之后发布的新文章，不回溯旧文。要给存量文章统一关闭评论，用批量编辑（见 10.4 节的关闭路径表）。
  • 问：审核关键词和禁止关键词会不会误伤正常评论？ 答：会，因为匹配的是子串。两个原则降低误伤：① 词尽量长而具体，避免两三个字的高频词根；② 拿不准的词先放进「审核关键词」（进待审、还有人工兜底），观察一段时间无误伤后再升级到「禁止关键词」。

10.3 评论管理界面 ​

「评论」菜单是审核流水线的操作台。

图 10-2：评论管理页：顶部为 全部/我的/待审/已批准/垃圾/回收站 状态标签，列表按时间倒序展示评论摘要

四种状态与标签页 ​

  • 待审：命中审核规则的评论，前台不可见，等待你裁决。
  • 已批准：前台可见的正常评论。
  • 垃圾：被 Akismet 或你标记的垃圾，前台不可见，默认定期自动清空。
  • 回收站：你手动删除或命中禁止关键词的评论，保留 30 天可恢复。

行内操作与批量操作 ​

鼠标悬停某条评论，出现操作链接：

图 10-3：待审评论的悬停操作：批准、回复、快速编辑、编辑、垃圾、回收站

  • 批准 / 拒绝：改变状态；
  • 回复：在后台直接写一条回复（以后台账号身份发表，前台显示为作者回复）；
  • 快速编辑 / 编辑：修正评论者的昵称、邮箱、网址或正文（如帮读者去掉误贴的隐私信息）；
  • 垃圾 / 回收站：打入对应队列。

批量操作：勾选多条评论后，用左上角「批量操作」下拉一次性批准 / 移入回收站 / 标记为垃圾 / 永久删除，点「应用」执行。清理成百上千条垃圾评论时，这是唯一现实的方式。

操作方法：一轮完整审核演练 ​

  1. 无痕窗口发两条评论（一条正常、一条带三个链接触发审核阈值）。
  2. 后台「评论 → 待审」：正常那条点「批准」，带链接的确认是广告后点「垃圾」。
  3. 在「已批准」里对正常评论点「回复」，输入回复内容提交。
  4. 到前台文章页验证：评论与你的回复按嵌套显示。
  5. 到「垃圾」标签页把误伤的评论点「不是垃圾」恢复（演练恢复路径）。

操作方法：批量清理积压垃圾评论 ​

  1. 进入「评论 → 垃圾」，顶部批量操作下拉选择「永久删除」，勾选后点「应用」。
  2. 或者直接用列表右上方的「清空垃圾评论」按钮一键清空整个垃圾队列（不可恢复，执行前扫一眼有没有误判）。
  3. 待审队列同理：确认整页都是广告后，可整页勾选批量「标记为垃圾」，让 Akismet 学习这批样本。

常见问题 ​

  • 问：误把正常评论标成垃圾，能恢复吗？ 答：垃圾队列清空之前可以。进「评论 → 垃圾」，悬停该评论点「不是垃圾」，它会回到已批准状态；用 Akismet 时这个动作还会「教」它以后别再误判同类评论。
  • 问：「待审」队列能关闭吗，让评论全部直接显示？ 答：可以但不推荐。把「在评论显示之前」板块的两个选项全部取消勾选即可实现即发即显，但这样把防线完全压给了 Akismet——一旦它漏判，广告会直接公开出现在前台。至少保留「先前须有评论通过了审核」这道首审闸。

10.4 反垃圾体系 ​

原理说明：为什么评论是垃圾重灾区 ​

评论表单是全站少数无需登录即可向数据库写内容的入口，垃圾程序（spambot）因此昼夜不停地扫描 WordPress 站点批量提交广告链接。单靠关键词拦截是打地鼠，成熟的防御是分层：

  1. 设置层：链接阈值、禁止关键词、自动关闭老文章评论（10.2 节）；
  2. 云端判定层：Akismet，用全网垃圾特征库做概率判定；
  3. 人机验证层：验证码插件，拦纯机器提交；
  4. 釜底抽薪层：不需要互动的页面/站点直接关闭评论。

分层的关键在于各层判据不同：关键词是字符串匹配，验证码看的是「提交者是不是人」，Akismet 看的是全网垃圾样本的概率特征——绕过一层的评论很难同时绕过所有层，而正常读者在每一层几乎都无感。

Akismet：官方出品的云端反垃圾 ​

Akismet 由 WordPress 母公司 Automattic 运营，随 WordPress 安装包自带（在「插件 → 已安装的插件」里躺着），但默认未启用，因为它需要一个 API key：

  1. 「插件 → 已安装的插件」，启用 Akismet Anti-spam。
  2. 按提示点「设置 Akismet 账号」，跳转到 akismet.com 注册并选择方案：个人/非商业站点可免费（自定价滑块拉到 0），商业站点需付费订阅。
  3. 拿到 API key 后回到后台粘贴，完成连接。
  4. 此后每条评论提交时都会发给 Akismet 云端判定：判定垃圾的直接进「垃圾」队列，可疑的进待审；特征极其恶劣的会被直接丢弃，不占用你的审核精力。

Akismet 的工作原理与注意点 ​

Akismet 的判定依据是全网数亿条被人工标记的垃圾样本训练出的特征库：提交者的邮箱、网址、IP、内容特征与行为模式都会被综合评估，因此它能识别「换着措辞来的」同一拨垃圾程序，这是本地关键词做不到的。两点注意：

  • 隐私合规：评论数据会被发送到 Akismet 服务器判定，站点的隐私政策里应如实披露这一点（隐私政策页的维护见第 05 章的隐私设置）。
  • 免费边界：个人博客、非商业站点可免费使用（注册时把价格滑块拉到 0）；有广告、带货、公司背景的网站应选择付费方案，官方会按站点性质核查。

操作方法：关闭评论的所有路径 ​

范围路径说明
全站（今后新文章）设置 → 讨论，取消「允许他人在新文章上发表评论」不影响已发布的旧文章
全站（含旧文章）「文章 → 全部文章」全选 → 批量操作「编辑」→ 评论选「不允许」→ 更新文章多时分批处理；页面同理
单篇文章/页面编辑页右侧「讨论」面板取消「允许评论」（经典编辑器在「讨论」元框；列表页「快速编辑」里也有勾选框）对个别争议文章最常用
页面类型整体主题控制：多数主题默认不在页面输出评论区页面要不要评论由主题的模板决定，见 10.5 节

操作方法：关闭单篇与批量关闭旧文章 ​

  1. 单篇：编辑该文章，在区块编辑器右侧边栏找到「讨论」面板（若看不到，点右上角三点菜单 →「偏好设置」→「面板」里启用），取消勾选「允许评论」，更新文章。
  2. 批量：「文章 → 全部文章」，勾选目标文章（可按分类/日期先筛选），顶部「批量操作」选「编辑」→「应用」，在展开的批量编辑区把「评论」设为「不允许」，点「更新」。
  3. 验证：分别打开被处理的文章前台，评论区应只剩既有评论、表单消失；若表单仍在，按 10.6 节四步法排查。

人机验证层 ​

若 Akismet 之后仍有机器漏网，可加验证码类插件（Cloudflare Turnstile、hCaptcha、reCAPTCHA 均有成熟插件），在评论表单加一道无感或轻交互的人机校验。注意验证码会抬高正常读者的评论成本，中小站点通常 Akismet 已足够，不必层层加码。

常见问题 ​

  • 问：Akismet 把正常读者评论判成垃圾怎么办？ 答：到「评论 → 垃圾」点「不是垃圾」恢复，Akismet 会学习这次纠错。同一读者反复被误杀时，让对方减少链接数量、避免关键词密集；持续大面积误杀可在 Akismet 设置里调整严格程度或联系其支持。
  • 问：关闭了评论，已有的评论还能显示吗？ 答：能。关闭评论只是关闭表单，已批准的旧评论仍会展示；想连展示区一起去掉需改主题模板或在讨论设置配合主题选项处理。

10.5 评论模板定制入门 ​

原理说明：三个角色各管一段 ​

评论在前台的呈现由三层协作：

  1. comments_template()：主题模板（如 single.php）调用它，WordPress 按模板层级去加载主题的 comments.php——层级查找的完整规则见第 23 章。
  2. comments.php：主题的评论模板，负责「已有评论列表 + 评论表单」的整体结构，内部通常调用 wp_list_comments() 渲染列表、comment_form() 输出表单。
  3. 过滤器（filter hooks）：不改模板文件也能改表单字段与文案的插件化入口，是入门定制的首选。

⚠️ 永远不要直接修改父主题的 comments.php——主题一更新你的改动就没了。正确姿势是放进子主题的 comments.php/functions.php（子主题见第 15 章），或写成一个迷你功能插件。

操作方法：用过滤器移除网址字段、修改标题文案 ​

以下代码放进子主题的 functions.php，遵循 WordPress 编码标准（WPCS）：Tab 缩进、Yoda 条件、输入消毒、输出转义，文本域用 wp-academy：

php
<?php
/**
 * 评论表单定制：移除「网站」字段、修改回复标题。
 *
 * 存放位置：子主题 functions.php 或独立功能插件，切勿直接改父主题。
 *
 * @package WPA_Demo
 */

/**
 * 过滤器一：从评论表单默认字段中移除「网站（url）」。
 *
 * comment_form_default_fields 过滤的是未登录访客可见的字段数组
 * （author / email / url / cookies），unset 掉 url 即可。
 *
 * @param array $fields 评论表单默认字段数组。
 * @return array 修改后的字段数组。
 */
function wpacademy_remove_comment_url_field( array $fields ): array {
	if ( isset( $fields['url'] ) ) {
		unset( $fields['url'] ); // 去掉网址框：减少垃圾评论动机，也降低读者填写负担。
	}

	return $fields;
}
add_filter( 'comment_form_default_fields', 'wpacademy_remove_comment_url_field' );

/**
 * 过滤器二：修改 comment_form() 的默认参数，更换标题与按钮文案。
 *
 * @param array $defaults comment_form() 的默认参数数组。
 * @return array 修改后的参数数组。
 */
function wpacademy_customize_comment_form( array $defaults ): array {
	// Yoda 条件：字面量写在比较符左侧，防止把 === 误写成 = 而不报错。
	if ( isset( $defaults['title_reply'] ) && '' !== $defaults['title_reply'] ) {
		// esc_html__()：翻译并转义输出文本；第二个参数 'wp-academy' 为文本域。
		$defaults['title_reply'] = esc_html__( '写下你的想法', 'wp-academy' );
	}

	$defaults['label_submit'] = esc_html__( '提交评论', 'wp-academy' );

	return $defaults;
}
add_filter( 'comment_form_defaults', 'wpacademy_customize_comment_form' );

要点回顾：

  • Tab 缩进（不是空格），函数前缀 wpacademy_ 防命名冲突；
  • Yoda 条件：'' !== $defaults['title_reply'] 把字面量放左边；
  • 输出转义：所有要显示在页面上的文本经 esc_html__() 处理；若是写入前先清洗用户输入，则用 sanitize_text_field()——消毒（sanitize）管输入，转义（escape）管输出，不可混用；
  • 文本域统一为 wp-academy，便于后续做国际化。

验证方法 ​

  1. 保存 functions.php，刷新任意文章的评论区。
  2. 未登录（或用无痕窗口）查看表单：应只剩「昵称、邮箱、评论正文」三个输入项，「网站」字段消失。
  3. 表单标题应显示为「写下你的想法」，提交按钮为「提交评论」。
  4. 已登录状态再验证一次：登录用户本来就看不到昵称/邮箱/网址字段，重点确认标题与按钮文案已变。

效果：访客评论表单只剩昵称、邮箱与评论框，标题从默认文案变为「写下你的想法」。

图 10-5：前台文章页评论区：嵌套回复缩进展示，表单已移除「网站」字段、标题为定制文案

进阶一瞥：comments.php 骨架 ​

主题 comments.php 的典型结构（看懂即可，先不要照抄重写）：

php
<?php
// 密码保护文章直接返回，不显示评论。
if ( post_password_required() ) {
	return;
}
?>
<div id="comments" class="comments-area">
	<?php if ( have_comments() ) : ?>
		<h2 class="comments-title">…评论数标题…</h2>
		<ol class="comment-list">
			<?php
			wp_list_comments(
				array(
					'style'       => 'ol',
					'avatar_size' => 48,
				)
			);
			?>
		</ol>
	<?php endif; ?>

	<?php comment_form(); // 输出评论表单，可被上文过滤器定制。 ?>
</div>

wp_list_comments() 支持传入自定义 callback 函数逐条控制单条评论的 HTML，这是深度定制的入口，留待第 23 章模板体系学完后再动它。

骨架里每个函数的职责：

函数职责
post_password_required()密码保护文章直接不渲染评论区
have_comments()判断当前文章是否存在已批准评论
wp_list_comments()渲染评论列表（含嵌套、头像、回复链接）
comment_form()输出评论表单，字段与文案可被过滤器定制

常见问题 ​

  • 问：过滤器代码加了，前台没变化？ 答：按顺序查：① 代码是否放进了当前启用的子主题 functions.php（改的是不是正在用的那个主题）；② 是否有 PHP 语法错误导致文件未执行（看服务器错误日志）；③ 页面缓存/缓存插件是否还吐旧页面，清一次缓存再看。
  • 问：过滤器和直接改 comments.php 怎么选？ 答：能用过滤器解决的（改字段、改文案、改默认值）一律用过滤器——代码集中、升级主题不受影响；只有要动评论区的整体 HTML 结构（比如重排列表与表单的先后顺序、包一层自定义容器）时，才在子主题里放自己的 comments.php 整体替换父主题模板。
  • 问：子主题的 comments.php 会覆盖父主题的吗？ 答：会。模板文件的查找遵循「子主题优先」：子主题目录里存在 comments.php 时，WordPress 完全使用子主题的版本，父主题同名文件不再加载——这正是子主题机制的核心规则，详见第 15 章。

10.6 常见问题速查 ​

  • 问：文章下面评论表单不见了？ 答：按四步排查——① 单篇开关：编辑该文章，看「讨论」面板里「允许评论」是否勾选；② 全局开关：「设置 → 讨论」里「允许他人在新文章上发表评论」是否取消（只影响新文章）；③ 自动关闭：是否设了「自动关闭发布 X 天后的文章的评论功能」，老文章超期被关；④ 主题因素：当前主题的 single.php/page.php 是否调用 comments_template()——页面（page）类型很多主题默认不输出评论区，不是故障。换个默认主题测试可快速定位是否主题问题，仍不行按第 38 章排查。
  • 问：正常评论总是进待审或垃圾？ 答：命中了三道闸门之一：链接数超过审核阈值、命中审核/禁止关键词（注意子串误伤，如词根太短）、或被 Akismet 判定。对照 10.2 节逐一放宽；Akismet 误判用「不是垃圾」纠正。
  • 问：评论邮件通知收不到？ 答：虚拟主机普遍禁用或限制 PHP 的 mail() 发信，WordPress 发出的邮件常进垃圾箱甚至直接丢失。标准解法是装 SMTP 插件（如 WP Mail SMTP 之类），把发信通道切到你自己的邮箱 SMTP 服务（QQ 邮箱、163、Gmail 等均提供 SMTP 与授权码），配置后发一封测试邮件验证。通知发件人地址与域名的匹配也会影响送达率，进阶见第 32 章与第 38 章。
  • 问：嵌套回复突然不缩进了，全部平铺？ 答：先看「设置 → 讨论」里嵌套是否被关或层数被调小；再看是否更换过主题——缩进样式由主题的评论渲染负责，换主题后视觉层级变化属预期；数据库里的 comment_parent 关系不受影响，调回设置即恢复。
  • 问：换了域名/装了缓存插件后评论提交报错或反复转圈？ 答：多半是缓存把评论表单页整页缓存了——表单里的安全校验字段（nonce）过期导致提交被拒。给缓存插件配置「已登录用户不缓存、含评论的页面缩短缓存期」，或按缓存插件文档为评论表单页设置例外；其余缓存类故障的排查思路见第 38 章。

本章总结 ​

  1. 评论存在 wp_comments 表：comment_parent 实现嵌套回复，comment_approved 的 '1'/'0'/'spam'/'trash' 四个值撑起审核队列，pingback/trackback 是 comment_type 特殊的机器通知。
  2. 讨论设置六板块各司其职：默认文章设置管总闸与链接通知，其他评论设置管表单门槛与嵌套/分页，审核靠「人工批准/首审制 + 链接阈值 + 关键词」，禁止关键词直接进回收站。
  3. 评论管理界面以待审/已批准/垃圾/回收站四个标签组织，行内操作管单条，批量操作管清理。
  4. 反垃圾要分层：设置层打底、Akismet 云端判定为主力（个人站免费，需 API key）、验证码兜底、不需要互动的场景直接关评论；关闭评论有全站新文章、批量改旧文、单篇三个粒度。
  5. 模板定制认三层：comments_template() 加载 comments.php，内部 wp_list_comments() + comment_form() 分工；入门改动优先用过滤器（comment_form_default_fields、comment_form_defaults），代码放子主题或插件，遵守 WPCS。

动手练习 ​

练-10-01（操作题）｜配置并实测一套审核策略

按 10.2 节的推荐配置完成讨论设置，然后用无痕窗口以游客身份提交三条评论：① 正常短评；② 含 3 个链接的评论；③ 命中你自设审核关键词的评论。逐条记录它们进入了哪个队列，与你的预期是否一致；最后到待审队列把正常评论批准，确认前台可见。

练-10-02（操作题）｜审核队列全状态流转演练

用 5 条测试评论完成一轮完整流转：待审 → 批准 → 回复 → 标垃圾 → 「不是垃圾」恢复 → 移回收站 → 回收站还原。其中「批量操作」至少使用一次（如批量标垃圾再批量恢复）。在 phpMyAdmin 里同步观察 comment_approved 字段值随每一步操作的变化，把状态流转图（10.1 节）与实际操作对应起来。

练-10-03（操作题）｜启用 Akismet 并观察拦截

启用 Akismet 插件，到 akismet.com 注册个人免费方案拿到 API key 并完成连接。随后用典型的垃圾评论特征（广告口吻 + 多个外链 + 无意义昵称）提交测试评论，观察它是否直接进入「垃圾」队列；再到「垃圾」里执行一次「不是垃圾」，理解人工纠错对云端模型的反馈作用。

练-10-04（代码题）｜用过滤器定制评论表单

按第 15 章的方法为当前主题建好子主题（或用 Code Snippets 类插件），加入 10.5 节的两个过滤器：移除网址字段、把标题改为「写下你的想法」。前台验证后做两个拓展：① 用 esc_html__() 再改一处文案（如提交按钮）；② 试着把代码故意改错一个分号，观察白屏/报错，再从错误日志定位行号并修复（体会为什么改 PHP 前要有备份，见第 37 章）。

练-10-05（排查题）｜制造并修复「评论表单消失」

在练习站上分别用三种方式让某篇文章的评论表单消失：① 单篇讨论面板取消允许评论；② 设置自动关闭 1 天前文章的评论并等一篇旧文命中；③ 切到一个页面（page）观察主题默认不输出评论区的情况。每种方式先让同伴（或自己隔半天后）按 10.6 节的四步排查法定位，再恢复正常，记录各方式的排查耗时与关键线索。
