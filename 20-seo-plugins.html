第 20 章 SEO 插件高级设置 ​

🟡 进阶难度 ｜ 一句话导览：SEO 插件解决「技术 SEO」——标题模板、元描述、站点地图、面包屑、社交卡片，但它不能替你写出好内容。本章以 Yoast SEO 为例做点击级配置，讲透标题写作规范、canonical 与 noindex 的应用场景，并与第 31 章「SEO 策略」明确分工。

学习目标 ​

  • 说清 SEO 插件能做什么（技术 SEO）与不能做什么（内容质量、外链建设）
  • 完成 Yoast SEO 的配置向导、搜索外观模板、XML 站点地图、面包屑、社交卡片的完整配置
  • 掌握标题与元描述的写作规范：长度、关键词前置、唯一性
  • 理解 canonical 标签的作用与默认行为，知道何时需要手动覆盖
  • 掌握 noindex 的应用场景：标签归档、搜索结果页、感谢页
  • 明确本章与第 31 章的分工：本章讲插件操作，第 31 章讲策略与结构化数据
  • 遇到 sitemap 404、标题被改写、重复元描述时，能独立排查修复

20.1 SEO 插件的边界：能做什么，不能做什么 ​

20.1.1 原理说明 ​

SEO（搜索引擎优化）分两大块：

  • 技术 SEO：让搜索引擎「能抓到、能读懂、能索引」你的网站。包括：合理的标题与元描述、XML 站点地图、canonical 标签、noindex 控制、面包屑导航、结构化数据。这些是「规则明确、可自动化」的工作，SEO 插件能帮你完成 90%。
  • 内容 SEO：让搜索引擎「愿意排名」你的网站。包括：原创内容质量、关键词研究、用户搜索意图匹配、外链建设、品牌权威度。这些需要人工创作与长期运营，插件完全帮不上忙。

关键认知：装 SEO 插件 ≠ 排名上升。插件只是把「技术 SEO」从「手写代码」变成「后台配置」，让你把省下的时间投入到内容创作。

20.1.2 操作方法：评估你的 SEO 现状 ​

在安装插件之前，先检查以下基础是否已做：

检查项合格标准去哪章
固定链接结构已设为 /%postname%/ 或自定义结构第 06 章
HTTPS全站已启用 HTTPS，无混合内容警告第 03 章
网站速度首页加载 < 3 秒（用 PageSpeed Insights 测）第 19 章
移动端适配主题响应式，Google 移动设备适合性测试通过第 11 章

任何一项不合格，先修复再谈 SEO 插件——技术 SEO 的地基不牢，插件配置再精细也白搭。

20.1.3 常见问题 ​

问：Yoast 与 Rank Math 选哪个？ 两者功能高度重叠，都是主流选择。Yoast 历史更久、文档更全、中文教程多；Rank Math 界面更现代、免费版功能更多（如结构化数据类型更丰富）。本章以 Yoast 为例，但概念完全互通。

问：装了 SEO 插件，Google 就会收录吗？ 不会。SEO 插件只是让网站「更容易被收录」，但收录与否取决于：内容是否原创、是否有外链、域名年龄、服务器稳定性。新站通常需要 2-4 周才会被 Google 收录，这是正常周期。

20.2 Yoast SEO 点击级配置 ​

20.2.1 安装与配置向导 ​

原理说明 ​

Yoast SEO 的配置向导会引导你完成基础设置：站点类型、组织信息、搜索引擎可见性、多作者设置。向导生成的配置会写入数据库，后续可在「Yoast SEO → 设置」中逐项修改。

操作方法：走完配置向导 ​

  1. 后台「插件 → 安装插件」，搜索 Yoast SEO，安装并启用。
  2. 启用后自动进入配置向导，或手动进入「Yoast SEO → 常规 → 配置向导」。
  3. 「环境」：选择「生产环境」（如果你的站点已上线）或「开发环境」（本地练习站）。开发环境会自动添加 noindex，防止搜索引擎收录。
  4. 「站点类型」：选择最匹配的类型（博客、企业官网、电商、作品集等）。这会影响结构化数据的默认类型。
  5. 「组织或个人」：选择「组织」则填写公司名与 Logo；选择「个人」则填写姓名。这会影响 Google 知识图谱的展示。
  6. 「搜索引擎可见性」：保持默认「允许搜索引擎索引」——除非你明确要隐藏某些内容类型。
  7. 「多作者」：如果是单人博客，选择「否」——Yoast 会自动 noindex 作者归档页，避免与「关于我」页面内容重复。
  8. 「标题设置」：填写站点名称与分隔符（推荐用「|」或「-」）。

图 20-1：站点类型影响结构化数据，选最接近的类型即可，后续可改。

20.2.2 搜索外观：标题与元描述模板 ​

原理说明 ​

「搜索外观」控制不同内容类型在搜索结果中的展示形式。Yoast 用变量模板批量生成标题与元描述，如 %%title%% | %%sitename%% 会输出「文章标题 | 站点名称」。

为什么要用模板？ 如果你有 1000 篇文章，不可能每篇都手写元描述。模板让你「一次配置，全站生效」，同时为单篇文章保留自定义入口（文章编辑页的 Yoast 面板可覆盖模板）。

操作方法：配置内容类型模板 ​

  1. 进入「Yoast SEO → 设置 → 搜索外观 → 内容类型」。
  2. 「文章」标签页：
    • 「SEO 标题」：%%title%% | %%sitename%%（推荐）。%%title%% 是文章标题，%%sitename%% 是站点名称。
    • 「元描述」：%%excerpt%%（文章摘要）。如果文章没写摘要，Yoast 会自动截取正文前 160 字符。
    • 「显示文章在搜索结果中」：是。
  3. 「页面」标签页：同上，但元描述建议留空——页面通常需要手写元描述（首页、关于我、联系页等核心页面）。
  4. 「分类法」标签页：
    • 「分类目录」：标题模板 %%term_title%% 分类 | %%sitename%%；元描述 %%term_description%%（分类描述）。
    • 「标签」：建议设为「不显示在搜索结果中」——标签页通常内容单薄、重复度高，索引它们会稀释权重。

图 20-2：变量模板批量生成标题与描述，单篇文章可在编辑页覆盖。

20.2.3 XML 站点地图与 Google Search Console ​

原理说明 ​

XML 站点地图是「给搜索引擎看的目录」，列出全站所有重要页面，帮助搜索引擎更快、更全地抓取。Yoast 会自动生成站点地图，你只需「开启 → 提交给 Google」。

操作方法：开启与提交 ​

  1. 进入「Yoast SEO → 设置 → 常规 → 功能」。
  2. 确认「XML 站点地图」为「开启」。
  3. 点击「查看 XML 站点地图」，应看到 https://你的域名/sitemap_index.xml。
  4. 登录 Google Search Console（https://search.google.com/search-console）。
  5. 添加你的站点（验证所有权：HTML 文件上传或 DNS 记录）。
  6. 进入「站点地图」，提交 sitemap_index.xml。
  7. 状态显示「成功」后，Google 会定期抓取站点地图。

图 20-3：提交站点地图后，Google 会按站点地图抓取页面，加快收录速度。

20.2.4 面包屑导航 ​

原理说明 ​

面包屑（Breadcrumbs）是「首页 > 分类 > 文章标题」的路径导航，既能提升用户体验（让用户知道自己在哪），也能在搜索结果中显示（增强点击率）。Yoast 会生成面包屑的 HTML 代码，但需要主题支持或手动集成。

操作方法：开启与集成 ​

  1. 进入「Yoast SEO → 设置 → 高级 → 面包屑」。
  2. 「启用面包屑」：开启。
  3. 「面包屑分隔符」：推荐用 » 或 /。
  4. 「首页锚文本」：填「首页」。
  5. 主题集成（关键步骤）：
    • 如果你的主题支持 Yoast 面包屑（大多数现代主题支持），无需额外操作。
    • 如果主题不支持，需在主题模板文件中手动添加代码。通常在 single.php 或 page.php 的标题上方添加：
php
<?php
if ( function_exists( 'yoast_breadcrumb' ) ) {
	yoast_breadcrumb( '<nav class="breadcrumb">', '</nav>' );
}
?>

图 20-4：面包屑在搜索结果中会显示为「首页 > 分类 > 文章」，提升点击率。

20.2.5 社交卡片（Open Graph 与 Twitter Card） ​

原理说明 ​

社交卡片控制文章被分享到 Facebook、Twitter、微信等平台时显示的标题、描述、缩略图。没有社交卡片时，平台会随机抓取页面内容，展示效果不可控。

操作方法：配置社交卡片 ​

  1. 进入「Yoast SEO → 设置 → 社交」。
  2. 「Facebook」标签页：
    • 「启用 Open Graph 元数据」：开启。
    • 「默认图片」：上传一张 1200×630 的默认分享图（当文章没有特色图片时使用）。
  3. 「Twitter」标签页：
    • 「启用 Twitter Card 元数据」：开启。
    • 「卡片类型」：选择「大图片摘要」（Summary with Large Image）。
  4. 单篇文章的社交卡片可在文章编辑页的 Yoast 面板「社交」标签页自定义标题、描述、图片。

图 20-5：社交卡片预览让你在发布前看到分享效果，避免缩略图被裁切。

20.2.6 内容分析红绿灯的正确态度 ​

Yoast 在文章编辑页提供「内容分析」，用红绿灯（红/橙/绿）评估 SEO 得分：关键词密度、标题长度、元描述长度、内链外链数量、段落长度等。

正确态度：

  • 绿灯是参考，不是目标。为了凑绿灯而堆砌关键词、强行加内链，反而会伤害用户体验与排名。
  • 重点关注「元描述长度」与「标题长度」——这两项有明确的像素/字符限制，超了会被截断。
  • 关键词密度不必追求 1-2%——自然写作即可，Google 早已能识别语义相关性，不需要机械重复。

图 20-6：红绿灯是写作辅助，不是硬性标准。内容质量永远优先于 SEO 得分。

20.2.7 批量编辑器：治理存量内容 ​

原理：新配置只对「之后发布」的内容自动生效，存量文章需要逐个编辑或批量治理。Yoast 的批量编辑器（「Yoast SEO → 工具 → 批量编辑器」）提供两个标签页——「标题」与「描述」，用表格形式列出全站文章，直接在单元格里改 SEO 标题与元描述，无需逐个打开编辑器。

操作方法：

  1. 进入「Yoast SEO → 工具 → 批量编辑器 → 描述」标签页。
  2. 按「元描述为空」或「元描述重复」筛选（用浏览器的页面内搜索辅助）。
  3. 优先处理：首页引用的核心分类页、流量前 20 的文章（从 Search Console 查）、所有元描述为空的页面。
  4. 每行改完点「保存」按钮，或改完一整页统一保存。

图 20-7：批量编辑器是治理存量内容最高效的工具，一行一篇，改完即存。

💡 治理顺序建议：先模板（20.2.2 节，保证新内容有兜底）→ 再批量编辑器（治理存量高价值页面）→ 最后逐篇精修（核心转化页面手写标题与描述）。

20.3 标题与元描述写作规范 ​

20.3.1 标题（Title Tag）规范 ​

规范说明示例
长度50-60 字符（约 25-30 个汉字），超出会被截断✅「WordPress 插件开发入门教程」❌「WordPress 插件开发入门教程：从零开始学习如何开发一个完整的插件」
关键词前置核心关键词放在标题前 1/3✅「WordPress 插件开发：5 步写出第一个插件」❌「5 步写出第一个插件：WordPress 插件开发」
唯一性全站每个页面标题唯一，避免重复用 Yoast 的「批量编辑器」检查重复标题
品牌后缀统一加站点名，用分隔符隔开`文章标题
吸引力用数字、疑问、痛点词提升点击率✅「5 个常见错误」比「一些错误」更吸引人

20.3.2 元描述（Meta Description）规范 ​

规范说明示例
长度150-160 字符（约 75-80 个汉字），超出会被截断用 Yoast 的实时预览检查长度
唯一性每个页面元描述唯一，避免全站用同一句分类页用分类描述，文章页用摘要
包含关键词自然融入关键词，不堆砌✅「本文讲解 WordPress 插件开发的核心概念」❌「WordPress 插件开发、WordPress 插件、开发教程」
行动号召用「立即学习」「免费下载」「查看详情」引导点击✅「立即学习 5 步开发法」

20.3.3 关键词放置的位置学 ​

标题与元描述之外，正文中的关键词位置也影响搜索引擎对主题的判断。按重要性排序：

  1. H1（文章主标题）：一篇文章只有一个 H1，必须与标题标签呼应。
  2. 首段前 100 字：搜索引擎对文章开头赋予更高权重，关键词应在首段自然出现。
  3. H2/H3 小标题：帮助搜索引擎理解文章结构，同时提升用户扫读体验。
  4. 图片 alt 属性：既是无障碍要求，也是图片搜索的流量入口。
  5. URL 别名（slug）：简短、含关键词、用连字符分隔，如 /wordpress-seo-guide/。

反面清单（这些做法会被判定为堆砌）：正文里同一个词不换行重复十次、页面底部塞隐形关键词文本、标签云挂满无关热词。

20.3.4 常见问题 ​

问：标题被 Google 改写了怎么办？ Google 有时会「改写」标题（用你的 H1 或正文第一句话），通常是因为：

  • 标题太长，被截断后 Google 重新生成。
  • 标题与内容不匹配，Google 认为内容更能代表页面。
  • 标题堆砌关键词，Google 判定为过度优化。

解法：缩短标题到 60 字符内、确保标题与内容一致、避免堆砌关键词。如果仍被改写，说明 Google 认为它的版本更好——接受它，或重写内容让标题更贴切。

问：元描述重复会有什么后果？ Google 不会惩罚重复元描述，但会在搜索结果中随机抓取页面内容生成描述——展示效果不可控。用 Yoast 的「批量编辑器」检查全站重复元描述，优先修复核心页面（首页、分类页、热门文章）。

20.4 canonical 与 noindex ​

20.4.1 canonical 标签 ​

原理说明 ​

canonical 标签（<link rel="canonical" href="..." />）告诉搜索引擎「这个页面的权威版本是哪个 URL」。用于解决「同一内容多个 URL」的问题：

  • https://example.com/article/ 与 https://example.com/article?utm_source=weibo（带参数）
  • https://example.com/article/ 与 https://example.com/amp/article/（AMP 版本）
  • https://example.com/category/article/ 与 https://example.com/article/（分类路径与独立路径）

Yoast 默认会为每个页面生成 canonical 标签，指向「当前页面的标准 URL」，通常无需手动修改。

操作方法：何时手动覆盖 canonical ​

  • 跨站转载：如果你的文章被其他网站转载，且对方愿意加 canonical 指向你的原文，这是保护原创权重的最佳方式。
  • 内容合并：把多篇相似文章合并为一篇时，旧文章的 canonical 指向新文章，权重会传递过去。
  • 分页归档：某些情况下，把分页归档（如 /page/2/）的 canonical 指向第一页，避免分页内容稀释权重。

20.4.2 noindex 应用场景 ​

原理说明 ​

noindex 告诉搜索引擎「不要索引这个页面」——页面可以被访问，但不会出现在搜索结果中。用于「内容单薄、重复、无搜索价值」的页面。

操作方法：哪些页面应该 noindex ​

页面类型是否 noindex理由
标签归档页✅ 建议 noindex内容通常与分类页重复，且标签页数量庞大，稀释权重
搜索结果页✅ 必须 noindex每个搜索词生成一个页面，内容重复，无搜索价值
感谢页✅ 必须 noindex表单提交后的「谢谢」页面，无内容价值
作者归档页（单人博客）✅ 建议 noindex与「关于我」页面内容重复
分页归档（第 2 页及以后）❌ 不建议分页内容有索引价值，用 canonical 指向第一页即可
附件页（图片详情页）✅ 建议 noindexWordPress 为每张图片生成独立页面，内容单薄

Yoast 中配置：进入「Yoast SEO → 设置 → 搜索外观 → 分类法」，把「标签」设为「不显示在搜索结果中」；进入「高级 → 特殊页面」，把「搜索结果页」设为 noindex。

图 20-8：标签归档页建议 noindex，避免与分类页内容重复。

20.4.3 常见问题 ​

问：noindex 的页面还会被 Google 抓取吗？ 会。noindex 只阻止「索引」，不阻止「抓取」。Google 仍会定期抓取 noindex 页面，只是不把它放入搜索结果。如果要彻底阻止抓取，用 robots.txt 的 Disallow 规则。

问：canonical 与 301 重定向选哪个？

  • 内容永久迁移（旧 URL 不再使用）：用 301 重定向，权重 100% 传递。
  • 内容多版本并存（带参数、AMP、打印版）：用 canonical，告诉 Google 哪个是权威版本。

20.6 robots.txt 与爬取控制 ​

20.6.1 原理说明 ​

robots.txt 是站点根目录下的一个纯文本文件，告诉搜索引擎爬虫「哪些路径可以抓、哪些不要抓」。它与 noindex 的区别要记牢：

  • robots.txt 的 Disallow 阻止抓取——爬虫根本不会访问该 URL，页面也就无从被索引；但已索引的页面不会因此消失。
  • noindex 元标签阻止索引——爬虫正常抓取页面内容，只是不把页面放进搜索结果。

两者不能混用：如果你用 Disallow 封了一个页面，爬虫抓不到页面上的 noindex 标签，该页面仍可能以「仅 URL、无描述」的形式出现在搜索结果中。正确的屏蔽姿势是：允许抓取 + 页面 noindex。

20.6.2 操作方法：查看与编辑 ​

WordPress 默认生成一个虚拟的 robots.txt（访问 https://你的域名/robots.txt 即可看到）。Yoast 提供在线编辑入口：「Yoast SEO → 工具 → 文件编辑器」（需要在站点根目录有可写的 robots.txt 文件，没有则先创建空文件）。

一个适合 WordPress 的推荐配置：

User-agent: *
Disallow: /wp-admin/
Allow: /wp-admin/admin-ajax.php
Disallow: /?s=
Disallow: /search/

Sitemap: https://你的域名/sitemap_index.xml

要点解读：后台目录 /wp-admin/ 禁止抓取，但放行 admin-ajax.php（很多前端功能依赖它）；站内搜索结果页禁止抓取（配合 noindex 双保险）；最后一行声明站点地图位置，帮助爬虫发现。

图 20-9：robots.txt 的每一行都影响爬虫行为，修改后建议用 Search Console 的 robots.txt 测试工具验证。

20.6.3 常见问题 ​

问：开发站想整站屏蔽搜索引擎怎么办？ 后台「设置 → 阅读」勾选「建议搜索引擎不索引本站点」，WordPress 会自动把 robots.txt 改为全站 Disallow 并给所有页面加 noindex。上线前务必取消勾选——无数站点上线后流量为零，原因就是忘了这一项。

问：robots.txt 能防爬虫抓敏感内容吗？ 不能。robots.txt 只是「君子协定」，恶意爬虫完全可以无视。敏感内容要靠权限控制（登录可见、密码保护）而不是 robots.txt。

20.7 常见问题速查 ​

20.7.1 sitemap 404 ​

现象：访问 https://你的域名/sitemap_index.xml 返回 404。

排查：

  1. 检查 Yoast SEO「设置 → 常规 → 功能」中「XML 站点地图」是否开启。
  2. 重新保存固定链接：进入「设置 → 固定链接」，什么都不改，直接点「保存更改」。这会刷新重写规则，90% 的 sitemap 404 由此解决。
  3. 检查 Nginx/Apache 配置：如果你的服务器配置了「禁止访问 XML 文件」或「所有请求都走 index.php」，需添加站点地图的例外规则。
  4. 检查是否有安全插件（如 Wordfence）拦截了站点地图的 User-Agent。

图 20-10：重新保存固定链接会刷新重写规则，解决大部分 sitemap 404。

20.7.2 标题被主题改写 ​

现象：Yoast 设置的标题在前台不生效，显示的是主题默认标题。

原因：主题没有声明支持 title-tag 特性，WordPress 用主题的 wp_title() 函数生成标题，Yoast 无法接管。

修复：

  1. 检查主题的 functions.php 是否有：
    php
    add_theme_support( 'title-tag' );
    如果没有，添加这一行（推荐在子主题中修改，避免主题更新被覆盖）。
  2. 检查主题的 header.php 是否硬编码了 <title> 标签：
    php
    <!-- 错误示例：硬编码 title 标签 -->
<title><?php wp_title( '|', true, 'right' ); ?></title>
    如果有，删除它——声明 title-tag 后，WordPress 会自动输出 <title>，无需主题手动添加。

20.7.3 重复元描述 ​

现象：Google Search Console 报告「重复的元描述」，或多个页面在搜索结果中显示同一句描述。

排查：

  1. 进入「Yoast SEO → 工具 → 批量编辑器 → 描述」。
  2. 查看哪些页面的元描述为空或重复。
  3. 优先修复核心页面：首页、分类页、热门文章。
  4. 如果文章数量庞大，可在「搜索外观 → 内容类型」中设置元描述模板（如 %%excerpt%%），让 Yoast 自动生成唯一描述。

20.7.4 社交媒体分享时缩略图不对 ​

现象：把文章分享到微信/微博/Facebook 时，显示的缩略图不是文章特色图片，而是站点 Logo 或一张不相关的图。

排查：

  1. 检查该文章是否有「特色图片」（Featured Image），WordPress 5.5+ 中 Yoast 默认用它做社交分享图。
  2. 检查「Yoast SEO → 设置 → 社交 → Facebook」中「默认图片」是否上传——当文章没有特色图片时，Yoast 会退回到默认图。
  3. 用 Facebook 的调试工具（https://developers.facebook.com/tools/debug/）输入文章 URL，抓取最新缓存，查看 og:image 标签的值。
  4. 如果还是不对，在单篇文章的 Yoast 面板「社交」标签页手动指定图片。

20.7.5 Search Console 索引覆盖率下降 ​

现象：Google Search Console 的「索引 → 覆盖率」中，有效页面数突然减少，或「已排除」页面数增多。

排查：

  1. 检查 noindex 设置是否误伤——可能是某次批量操作把「文章」类型设成了 noindex。
  2. 检查 robots.txt 是否意外阻止了某些目录。
  3. 检查站点地图是否包含这些页面——如果站点地图与 noindex 同时存在，Google 会优先尊重 noindex。
  4. 检查「增强功能 → 面包屑」是否有报错，结构化数据错误会影响富媒体展示，但不影响索引本身。

20.7.6 同时装了两个 SEO 插件 ​

现象：后台同时启用了 Yoast SEO 与 Rank Math（或 All in One SEO），页面源代码里出现两套重复的 <title>、meta description 与 OG 标签。

危害：搜索引擎看到冲突的元数据会随机选择一套或干脆忽略，social 卡片抓取结果不可预测。

处理：SEO 插件是互斥品类，全站只能启用一个。决定保留哪个后：① 用目标插件的「导入」功能（Yoast 与 Rank Math 都支持互相导入对方数据）迁移已有的标题/描述配置；② 停用并删除另一个；③ 抽查核心页面源代码，确认只剩一套元数据标签。

练-20-01（操作题）｜完成 Yoast SEO 完整配置
