附录 A 术语表（Glossary） ​

收录本教程中出现的核心概念，中英对照、按拼音/字母混排分组。每条附 1–3 句通俗解释，并给出主讲解章节链接，建议阅读正文时随时回查。

使用说明

  • 词条按「中文拼音首字母 / 英文首字母」混排分组（A–C、D–F、G–J、K–M、N–P、Q–S、T–W、X–Z），中英文词条一视同仁。
  • 括号内为英文原名；同一概念的常见叫法（如「别名 / Slug」）合并为一个词条。
  • 链接指向该术语讲解最系统的章节，正文其他章节出现时不再逐一回链。
  • 查函数、命令、常量请改用 速查卡；查报错请直接翻 第 38 章。

A–C ​

  • Action（动作钩子）：WordPress 在特定时机（如保存文章、构建后台菜单）广播的「事件点」，插件/主题用 add_action() 把自己的函数挂上去执行。与 Filter 的区别是：Action 做事、Filter 改数据。

    详见 第 16 章。

  • Attachment（附件）：上传到媒体库的每个文件都会生成一条 attachment 类型的文章记录，拥有自己的 ID、固定链接与元数据，可单独设置标题、说明与替代文本。

    详见 第 8 章。

  • Autoload（自动加载选项）：wp_options 表中 autoload = yes 的选项会在每次请求时一次性读入内存；被插件滥用（塞进大数组、过期缓存）会显著拖慢站点。

    详见 第 29 章。

  • CDN（内容分发网络）：把图片、CSS、JS 等静态资源缓存到离访客更近的边缘节点，降低源站压力、缩短加载时间，是高并发站点的标配。

    详见 第 29 章。

  • CMS（内容管理系统）：Content Management System，让用户无需手写代码即可发布与管理内容的系统；WordPress 是全球份额最大的 CMS。

    详见 第 1 章。

  • Cookie：浏览器保存的小段数据，WordPress 用它维持登录态与评论者信息；更换域名或强制 HTTPS 后常需清理旧 Cookie 才能正常登录。

    详见 第 38 章。

  • CPT（自定义文章类型）：Custom Post Type，在文章/页面之外注册的新内容类型（如「作品」「课程」），用 register_post_type() 创建，可拥有独立后台菜单与模板。

    详见 第 27 章。

  • 备份（Backup）：对「文件 + 数据库」的整体留档；可靠备份须满足 3-2-1 原则——3 份副本、2 种介质、1 份异地，且必须定期做恢复演练。

    详见 第 34 章。

  • 宝塔面板（BT Panel）：国产服务器图形管理面板，可一键建站、签发证书、管理 PHP 与数据库版本，适合不熟悉命令行的新手运维。

    详见 第 3 章。

  • 本地环境（Local Environment）：在自己电脑上运行的 WordPress（XAMPP / MAMP / Local / Docker 四套方案），用于学习与开发，改动不影响线上站点。

    详见 第 2 章。

  • 别名（Slug）：内容在 URL 中的友好标识，如 /hello-world 中的 hello-world；应短、全小写、用连字符分词，发布后尽量不再改动。

    详见 第 6 章。

  • 博客（Blog）：按时间倒序展示文章的站点形态，也是 WordPress 的起点；如今 WordPress 已能胜任企业站、电商、课程站等各种形态。

    详见 第 1 章。

  • 区块（Block）：区块编辑器中内容的最小单元（段落、图片、按钮……），每个区块独立排版与配置，最终以 HTML 注释包裹的形式存入数据库。

    详见 第 7 章。

  • 区块编辑器（Block Editor）：WordPress 5.0 起取代经典编辑器的新编辑器，项目代号 Gutenberg；区块主题下它进一步扩展为全站编辑器。

    详见 第 7 章。

D–F ​

  • Dashboard（仪表盘）：登录后看到的后台总览页（/wp-admin/），汇总站点动态、快速草稿、活动与统计等小面板，可用「显示选项」裁剪。

    详见 第 5 章。

  • DNS（域名系统）：把域名翻译成服务器 IP 的分布式系统；迁移站点前的标准动作是把 A 记录 TTL 调低，以缩短切换生效时间。

    详见 第 35 章。

  • Docker：用容器一键打包 Web 服务器、PHP、数据库的虚拟化方案；本教程 examples/ 目录提供开箱即用的 docker-compose.yml。

    详见 第 2 章。

  • 短代码（Shortcode）：形如 [gallery ids="1,2"] 的方括号标记，由代码在渲染时替换为动态内容；区块时代仍被表单、电商等插件广泛使用。

    详见 第 16 章。

  • 多媒体 / 媒体库（Media Library）：后台集中管理图片、视频、PDF 等上传文件的仓库，支持网格/列表视图、批量编辑与「未附加」筛选。

    详见 第 8 章。

  • 分类（Category）：文章自带的层级式分类法，每篇文章必须至少属于一个分类（默认「未分类」），适合做内容的纵向栏目。

    详见 第 9 章。

  • 分类法（Taxonomy）：对内容归组的机制统称，分类与标签都是内置分类法，也可用 register_taxonomy() 注册自定义分类法并挂到任意文章类型。

    详见 第 9 章。

  • FTP / SFTP：文件传输协议及其加密版，用于向服务器上传/下载站点文件；生产环境只应使用 SFTP 或 SSH，明文 FTP 已被视为不安全。

    详见 第 4 章。

  • Feed / RSS：站点自动输出的 XML 订阅源（/feed/），供阅读器与聚合平台抓取；可在「设置 → 阅读」控制输出全文还是摘要。

    详见 第 6 章。

  • 固定链接（Permalink）：内容的永久 URL 结构，在「设置 → 固定链接」配置；推荐「文章名」结构，注册新 CPT/分类法后需保存一次以刷新重写规则。

    详见 第 4 章。

  • 过滤器（Filter）：WordPress 在输出或保存数据前给的「过一手」机会，用 add_filter() 挂接的回调必须返回处理后的值。

    详见 第 16 章。

  • functions.php（主题函数文件）：每个主题特有的「插件位」，主题激活即自动加载，常用来注册菜单、侧栏、缩略图尺寸与加载资源。

    详见 第 23 章。

  • FSE（全站编辑）：Full Site Editing，用区块编辑器直接编辑页眉、页脚等模板区域的能力，是区块主题区别于经典主题的核心特征。

    详见 第 13 章。

G–J ​

  • GPL（通用公共许可证）：WordPress 采用的开源协议，赋予用户运行、研究、修改、再分发的自由，也是整个主题/插件生态的法律基石。

    详见 第 1 章。

  • Gravatar（全球通用头像）：按邮箱识别的在线头像服务，评论区与后台用户头像默认取自它；国内访问慢时可替换为镜像源。

    详见 第 10 章。

  • GUI（图形用户界面）：相对命令行而言的可视化操作界面，如后台仪表盘、宝塔面板；本教程点击级操作均以 GUI 为准。

    详见 第 5 章。

  • 钩子（Hook）：Action 与 Filter 的统称，是 WordPress 插件体系的「扩展插座」；开发第一原则是「用钩子扩展，永不修改核心文件」。

    详见 第 16 章。

  • Gutenberg（古腾堡）：区块编辑器的项目代号，历经多年迭代后已并入核心；日常语境中与「区块编辑器」同义。

    详见 第 7 章。

  • HTTPS / SSL：HTTP 的加密传输层；2026 年起所有新站强制启用，证书常用 certbot 免费签发并配置自动续期。

    详见 第 3 章。

  • jQuery：WordPress 核心内置的 JavaScript 库，运行于 noConflict 模式；主题脚本应以它为依赖并在 IIFE 中显式接收 $。

    详见 第 25 章。

K–M ​

  • LAMP / LNMP：Linux + Apache/Nginx + MySQL + PHP 的经典建站栈缩写，是绝大多数 WordPress 服务器的软件底座。

    详见 第 3 章。

  • 懒加载（Lazy Load）：图片/iframe 滚动到视口附近才真正加载的技术；核心已原生支持，但首屏主图必须排除，否则会拖慢 LCP。

    详见 第 30 章。

  • Loop（主循环）：模板中 while ( have_posts() ) : the_post(); 的经典结构，逐条取出查询结果并填充 the_title() 等模板标签。

    详见 第 23 章。

  • Media（媒体）：泛指站点中的图片、音视频与文档文件，统一进入媒体库管理并落盘到 wp-content/uploads/ 目录。

    详见 第 8 章。

  • 菜单（Menu）：站点导航链接集合，经典主题在「外观 → 菜单」维护，区块主题直接在站点编辑器中拖放导航区块。

    详见 第 13 章。

  • Meta Box（元框）：编辑界面中围绕主编辑器的功能小面板（发布、分类、特色图像等），开发者可注册自定义元框承载业务字段。

    详见 第 27 章。

  • mu-plugins（必用插件）：wp-content/mu-plugins/ 下的插件无需激活、不可在后台停用，适合放站点级基础设施代码。

    详见 第 16 章。

  • MySQL / MariaDB：WordPress 官方支持的两种关系型数据库，MariaDB 是 MySQL 的开源分支，二者语法高度兼容，可互换使用。

    详见 第 3 章。

N–P ​

  • Nonce（一次性令牌）：WordPress 的 CSRF 防护令牌，表单与 AJAX 提交时用 wp_verify_nonce() 校验，证明请求来自本站界面而非伪造。

    详见 第 28 章。

  • oEmbed：粘贴一个受支持的链接（如视频站 URL）即自动转成嵌入式播放器的协议；区块编辑器中以「嵌入」区块呈现。

    详见 第 7 章。

  • OPcache：PHP 的字节码缓存扩展，把编译结果常驻内存，是 PHP 层面性价比最高的加速手段，生产环境必须开启。

    详见 第 29 章。

  • Page（页面）：用于「关于我们」「联系方式」等相对稳定内容的类型，不参与时间流，支持父子层级并可挂自定义模板。

    详见 第 6 章。

  • 插件（Plugin）：以钩子机制扩展功能的 PHP 包，存放于 wp-content/plugins/；基本原则是「功能属于插件、外观属于主题」。

    详见 第 16 章。

  • Pingback / Trackback：其他站点链接到你时自动发来的通知机制，历史上被垃圾信息滥用严重，多数站点建议直接关闭。

    详见 第 10 章。

  • Post（文章）：按时间流组织的主要内容类型，默认进入博客列表与 RSS，可挂分类与标签，支持定时发布与修订版本。

    详见 第 6 章。

  • Post Format（文章形式）：主题可声明支持的轻量体裁标记（日志 aside、相册 gallery、视频 video 等），区块主题时代已较少使用。

    详见 第 11 章。

  • postmeta（文章元数据表）：存储文章键值对扩展数据的表，自定义字段、缩略图 ID 等都保存在这里；查询时注意索引与缓存开销。

    详见 第 27 章。

  • 评论（Comments）：访客针对内容的讨论区，内置审核队列、黑名单与反垃圾机制，可全局关闭或按篇关闭。

    详见 第 10 章。

Q–S ​

  • 查询（Query）：向数据库取内容的过程；WordPress 自动生成主查询，开发者用 WP_Query 发起自定义查询、用 pre_get_posts 修改主查询。

    详见 第 24 章。

  • Query Monitor：开发者必备调试插件，面板化展示当前页面的 SQL 查询、钩子、命中模板、HTTP 请求与耗时告警。

    详见 第 22 章。

  • 权限 / 角色（Role）：WordPress 的权限模型——管理员、编辑、作者、投稿者、订阅者五种内置角色，各自拥有一组能力（Capability）。

    详见 第 5 章。

  • REST API：WordPress 内置的 JSON 接口（/wp-json/），供移动端、前端框架与外部系统读写站点数据；公开读取、写操作需认证。

    详见 第 27 章。

  • Revision（修订版本）：文章每次保存的历史快照，可随时对比与回滚；数量过多会膨胀数据库，可用常量限制保留条数。

    详见 第 6 章。

  • SEO（搜索引擎优化）：让内容更易被搜索引擎理解、收录与排名的一系列技术与运营手段，分技术 SEO 与内容 SEO 两条线。

    详见 第 20 章。

  • Sidebar（侧栏）：主题注册的小工具容器区域，命名源于博客时代的侧栏，实际可位于页脚等任何位置，用 register_sidebar() 注册。

    详见 第 26 章。

  • Site Health（站点健康）：后台「工具 → 站点健康」面板，自动检测配置、性能与安全项并给出改进建议，装机后应消掉所有关键问题。

    详见 第 5 章。

  • 站点编辑器（Site Editor）：区块主题下「外观 → 编辑器」打开的全站编辑界面，可直接修改模板、模板部件与全局样式。

    详见 第 13 章。

  • SMTP（简单邮件传输协议）：让站点邮件通过正规邮箱服务商代发的协议，是解决 wp_mail() 进垃圾箱问题的标准方案。

    详见 第 21 章。

  • Staging（预发布环境）：与线上配置一致的彩排环境，用于更新、改版前的验证，确认无异常后再同步上线。

    详见 第 37 章。

T–W ​

  • 标签（Tag）：文章自带的非层级分类法，适合做横向关键词聚合；宁缺毋滥，避免与分类重复建词造成内容孤岛。

    详见 第 9 章。

  • Template（模板）：决定一类页面输出结构的文件——经典主题为 PHP 模板，区块主题为 HTML 区块模板，按模板层次规则被选中。

    详见 第 23 章。

  • 模板层次（Template Hierarchy）：WordPress 按「最具体到最通用」顺序挑选模板文件的规则体系，如 single-book.php → single.php → singular.php → index.php。

    详见 第 23 章。

  • 主题（Theme）：控制站点外观与模板输出的代码包，存放于 wp-content/themes/；切换主题不应丢失任何内容数据。

    详见 第 11 章。

  • theme.json：区块主题的全局配置文件，声明配色、字体、间距与区块默认值，站点编辑器的全局样式界面与之双向同步。

    详见 第 13 章。

  • 缩略图（Thumbnail）：上传图片时按主题声明尺寸自动生成的裁切副本；特色图像（Featured Image）即调用这套缩略图体系。

    详见 第 8 章。

  • Transient（瞬态缓存）：带过期时间的临时数据缓存 API，有对象缓存时自动走内存、否则落数据库，适合缓存耗时计算结果。

    详见 第 29 章。

  • 上传（Uploads）：所有媒体文件落盘的目录 wp-content/uploads/，默认按年/月分文件夹；迁移与备份都必须完整包含它。

    详见 第 8 章。

  • 用户（User）：站点账号体系，登录态、作者署名、评论身份均基于用户；角色决定其能做什么，新增用户应遵循最小权限原则。

    详见 第 5 章。

  • Widget（小工具）：可拖入侧栏等容器的功能块（搜索、近期文章、自定义 HTML），区块时代逐步被区块取代，但经典小工具 API 仍广泛使用。

    详见 第 26 章。

  • WooCommerce：最流行的 WordPress 电商插件，把站点变成完整网店，自带商品 CPT、购物车、订单与支付网关体系。

    详见 第 21 章。

  • WordPress.org vs .com：前者是开源自托管软件（本教程的对象），后者是 Automattic 公司的托管服务；自由度与省心程度互为取舍。

    详见 第 1 章。

  • WP-CLI：WordPress 官方命令行工具，一条命令完成安装、更新、换域名、清缓存等操作，是自动化运维的基座。

    详见 第 4 章。

  • wp-config.php：站点级配置文件，保存数据库凭据、表前缀、盐值与各类常量开关；权限应收紧到 640/600，且绝不提交进公共仓库。

    详见 第 4 章。

  • WPCS（WordPress 编码标准）：PHP_CodeSniffer 的 WordPress 规则集，统一 Tab 缩进、蛇形命名与转义约定，配合 phpcs 自动检查。

    详见 第 22 章。

  • WSOD（白屏死机）：White Screen of Death，PHP 致命错误导致页面全白的现象；排查第一步是开启 WP_DEBUG_LOG 查看日志。

    详见 第 38 章。

X–Z ​

  • XML-RPC：WordPress 的历史远程发布接口（xmlrpc.php），如今多被 REST API 取代，且常成为暴力破解目标，闲置时建议关闭。

    详见 第 32 章。

  • XML Sitemap（站点地图）：向搜索引擎提交的 URL 清单；核心自 5.5 起内置 /wp-sitemap.xml，SEO 插件会输出更精细的版本。

    详见 第 20 章。

  • 首页（Front Page）：站点入口页，可在「设置 → 阅读」设为最新文章流或指定静态页面；对应 front-page.php / home.php 模板。

    详见 第 6 章。

  • 正则表达式（Regex）：按模式匹配文本的语法，wp search-replace --regex 与重写规则都会用到；正式替换前务必先 --dry-run。

    详见 第 36 章。

  • 主机（共享主机 / VPS / 托管主机）：三种典型托管形态——共享主机便宜但受限，VPS 自由但要自己运维，托管主机（Managed WP）省心但价高。

    详见 第 1 章。

  • 字符集（utf8mb4）：MySQL 中完整的 UTF-8 实现，支持 emoji 与生僻字，是 WordPress 建库的默认与硬性要求。

    详见 第 3 章。

  • 子主题（Child Theme）：继承父主题全部模板与样式的轻量主题，只放自己的改动，父主题升级时定制不丢失。

    详见 第 15 章。

  • 自定义字段（Custom Field）：挂在文章上的键值对扩展数据（存 postmeta），适合结构化但无需归档页的信息；需要归档筛选时应改用分类法。

    详见 第 27 章。

  • 自定义器（Customizer）：经典主题的实时预览设置界面（外观 → 自定义），选项存 theme_mod 或 option，配合 postMessage 实现无刷新预览。

    详见 第 13 章。

  • 数据库（Database）：站点所有内容与配置的存储中心（默认 12 张核心表），备份、迁移、排障都绕不开它。

    详见 第 3 章。
