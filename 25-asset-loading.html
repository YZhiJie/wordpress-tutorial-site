第 25 章 主题资源加载与缓存策略 ​

🔴 高级难度 ｜ 一句话导览：CSS 和 JS 不是直接贴进 HTML 的字符串，而是由 WordPress 通过 wp_enqueue 体系统一管理的有序队列。本章讲清为什么绝不手写 <link> / <script>、如何控制加载顺序与版本号、怎样按条件精准入队、区块主题与现代构建工具怎么适配——让你的主题样式和脚本既快又安全。

学习目标 ​

  • 理解为什么绝不直接往模板里写 <link> 或 <script> 标签
  • 讲清 wp_register_* 与 wp_enqueue_* 的分工、全部参数（deps / ver / in_footer / wp_add_inline_script）
  • 对照配套 inc/assets.php 逐行讲透版本号策略（WPA_VERSION vs filemtime）
  • 掌握条件加载写法（is_page_template、is_singular + comment-reply）与后台钩子 admin_enqueue_scripts
  • 会用 wp_localize_script / wp_add_inline_script 向前端传数据（ajaxurl / nonce）
  • 了解区块主题资源入队（wp_enqueue_block_style）及 Vite manifest 按 hash 入队示例
  • 会用 script_loader_tag 给脚本加 defer / async
  • 能诊断并修复 jQuery noConflict、重复加载、CSS 特异性战争

25.1 绝不直接写 link / script ​

25.1.1 原理说明：为什么手写是灾难 ​

模板里直接写：

html
<!-- 错误示范，课程结束后从代码库删除 -->
<link rel="stylesheet" href="<?php echo get_template_directory_uri(); ?>/assets/css/main.css">
<script src="<?php echo get_template_directory_uri(); ?>/assets/js/main.js"></script>

三条死罪：

  1. 子主题无法安全覆盖：<link> 指向父主题目录，子主题想换一份样式只能全文件复制，无法复用 handle 精确替换；
  2. 顺序不可控：两份样式谁前谁后？jQuery 在插件 A 还是主题里加载？手写标签随机输出，依赖关系靠猜；
  3. 无法被核心和插件干预：缓存插件没法给手写的 URL 自动加 CDN 前缀，SEO 插件没法把不重要的脚本推迟，jQuery Migrate 没法自动启用——因为手写标签完全游离于 WordPress 资源管理系统之外。

正确做法是全部走 wp_enqueue_style / wp_enqueue_script，由核心按依赖树排序后集中输出到 wp_head() 和 wp_footer()。

25.1.2 操作方法：把硬编码改成入队 ​

把上面的错误示范改成正确版本：

php
wp_enqueue_style(
	'wp-academy-main',                           // handle：本主题内的唯一标识。
	get_template_directory_uri() . '/assets/css/main.css',
	array(),                                      // deps：无依赖。
	'1.0.0'                                       // ver：版本号。
);

wp_enqueue_script(
	'wp-academy-main-js',
	get_template_directory_uri() . '/assets/js/main.js',
	array(),                                      // deps：无依赖（原生 JS，不需要 jQuery）。
	'1.0.0',
	true                                          // in_footer：加载到 </body> 前。
);

然后这两个函数挂到 wp_enqueue_scripts 动作上。核心在调用 wp_head() 和 wp_footer() 时，会把队列里所有入队资源按 handle 和依赖树排好序后输出。

25.2 wp_register vs wp_enqueue：先挂号，再上车 ​

25.2.1 两者的关系 ​

函数作用输出位置
wp_register_style / wp_register_script把资源信息登记到系统，不输出无
wp_enqueue_style / wp_enqueue_script入队，输出到 HTMLwp_head() / wp_footer()

分开的意义：只注册不入队 → 资源存在但不加载；需要时由条件或别的代码触发入队。

php
// 在 functions.php 里先注册（挂 plugins_loaded / init 都行）。
wp_register_script(
	'wp-academy-charts',
	WPA_URI . '/assets/js/charts.js',
	array(),
	WPA_VERSION,
	true
);

// 模板里（或别的条件分支里）只在需要时入队。
if ( is_page_template( 'page-templates/template-landing.php' ) ) {
	wp_enqueue_script( 'wp-academy-charts' ); // 只写 handle，其他参数已在注册时存好。
}

配套主题没有使用这种拆分模式（教学主题资源少，直接 enqueue 更直观），但在插件层，配套 class-shortcode-courses.php 就用了 wp_register_style + 条件入队（用注释给出了「按需加载」的两种写法），这是生产项目的推荐形态。

25.2.2 参数逐个讲 ​

以 wp_enqueue_script 为例（共 5 个参数）：

php
wp_enqueue_script(
	$handle,      // 1. handle：字符串，全局唯一。主题名前缀防冲突。
	$src,         // 2. URL：用 get_template_directory_uri() / get_stylesheet_directory_uri()。
	$deps,        // 3. 依赖数组：handle 字符串数组。WordPress 按依赖树排序输出，被依赖的先出。
	$ver,         // 4. 版本号：Query String 破缓存；null 时不追加 ?ver=…；false 用 core ver。
	$in_footer    // 5. boolean：true → wp_footer() 输出；false → wp_head() 输出。
);

deps 的级联效应（配套 inc/assets.php 核心设计）：

php
wp_enqueue_style(
	'wp-academy-main',
	WPA_URI . '/' . $main_css_rel,
	array( 'wp-academy-style' ),  // 依赖父 style.css，保证级联顺序。
	$main_css_ver
);

wp-academy-main 排在 wp-academy-style 之后，同特异性规则自然生效——不需要 !important。

25.3 版本号策略： WPA_VERSION vs filemtime ​

25.3.1 逐行精读 inc/assets.php ​

配套 inc/assets.php 的版本号决策写在文件头注释里，值得全文背诵：

方案 A：用 WPA_VERSION 常量，发版才变更 → 用户浏览器可能长期缓存旧 CSS。
方案 B（本主题采用）：用 filemtime() 取文件修改时间戳，开发期每次保存都自动破缓存；缺点是每次出队多一次磁盘 stat，可忽略不计。正式发版想锁版本时改回 WPA_VERSION 即可。

看主样式入队的真实代码：

php
$main_css_rel  = 'assets/css/main.css';
$main_css_path = WPA_DIR . '/' . $main_css_rel;
$main_css_ver  = file_exists( $main_css_path )
	? (string) filemtime( $main_css_path ) // 开发期：保存即破缓存。
	: WPA_VERSION;                          // 文件缺失时退回主题版本号。

wp_enqueue_style(
	'wp-academy-main',
	WPA_URI . '/' . $main_css_rel,
	array( 'wp-academy-style' ),
	$main_css_ver
);

为什么先 file_exists 再 filemtime？若文件缺失，filemtime 会发 PHP Warning（开发环境 WP_DEBUG_DISPLAY=true 时直接暴露），用 file_exists 做守卫再 filemtime 才是安全的。

主脚本同理，wp_enqueue_script 第五参数 true 让它输出到 </body> 前，再跟 wp_script_add_data 加 defer：

php
wp_enqueue_script(
	'wp-academy-main-js',
	WPA_URI . '/' . $main_js_rel,
	array(),
	$main_js_ver,
	true
);
wp_script_add_data( 'wp-academy-main-js', 'defer', true );

wp_script_add_data 是给脚本标签加额外属性（如 defer、async、crossorigin、module 等）的标准 API。配套文件头注释强调：不加 data 时即使 in_footer 为 true，标签也是普通 <script>；加了 defer 后浏览器并行下载、DOM 解析完成后才执行，兼顾首屏速度。

25.3.2 版本号决策表 ​

场景推荐策略代码示例
开发期filemtime()配套 assets.php 方案 B
生产发版WPA_VERSION常量更新即统一破缓存
库/共享脚本库自身版本号'5.3.0'（jQuery UI 等）
永远最新的 CDNnull不追加 ?ver=，CDN 回源控制

25.4 条件加载与后台资源 ​

25.4.1 前台条件入队 ​

不是所有页面都需要全部资源。配套 inc/assets.php 的条件加载示范：

php
// 4) 嵌套回复评论时才加载 WP 自带的 comment-reply.js。
if ( is_singular() && comments_open() && get_option( 'thread_comments' ) ) {
	wp_enqueue_script( 'comment-reply' );
}

三条件同时满足：单篇文章/页面、评论开启、后台设置了嵌套评论。把 comment-reply 放在没有评论的页面上是常见浪费，这段条件写法可直接抄进生产主题。

另一个经典场景——只在落地页加载额外脚本：

php
function wpa_conditional_enqueue() {
	// 当前页面使用了落地页模板时，入队统计图表脚本。
	if ( is_page_template( 'page-templates/template-landing.php' ) ) {
		wp_enqueue_script( 'wp-academy-charts' );
	}
}
add_action( 'wp_enqueue_scripts', 'wpa_conditional_enqueue' );

条件判断用模板标签（is_page_template、is_singular、is_archive 等），第 23 章和第 24 章的底子在这里直接用上。

25.4.2 后台资源：admin_enqueue_scripts ​

后台加载资源用 admin_enqueue_scripts 钩子，不是 wp_enqueue_scripts。它还带一个 $hook_suffix 参数，让你只在特定后台页面入队：

php
/**
 * 只在「课程设置」页面加载后台样式。
 *
 * @param string $hook_suffix 当前后台页面的钩子后缀。
 * @return void
 */
function wpa_demo_admin_enqueue( $hook_suffix ) {
	// 配套插件设置页 slug 为 'course_page_wpa-demo-settings'。
	if ( 'course_page_wpa-demo-settings' !== $hook_suffix ) {
		return;
	}

	wp_enqueue_style(
		'wpa-demo-admin',
		WPA_DEMO_URL . '/assets/css/admin.css',
		array(),
		WPA_DEMO_VERSION
	);
}
add_action( 'admin_enqueue_scripts', 'wpa_demo_admin_enqueue' );

💡 如何快速知道自己的 $hook_suffix？在回调里写 error_log( $hook_suffix );，访问目标后台页面看日志即可。或者安装 "Admin Menu Editor" 这类调试插件。

25.5 向前端传数据：wp_localize_script vs wp_add_inline_script ​

25.5.1 wp_localize_script：经典但约束多 ​

php
wp_localize_script(
	'wp-academy-main-js',            // 目标 handle：必须在它之后入队。
	'WPA_L10N',                      // 全局变量名。
	array(
		'ajaxUrl' => admin_url( 'admin-ajax.php' ),
		'nonce'   => wp_create_nonce( 'wpa_nonce_action' ),
		'homeUrl' => home_url( '/' ),
	)
);

wp_localize_script 的本质是：在目标脚本标签之前输出一段 <script>var WPA_L10N = {…};</script>。它要求目标 handle 已入队，否则静默不输出。

25.5.2 wp_add_inline_script：现代推荐写法 ​

配套子主题 wp-academy-child/functions.php 的真实用法：

php
$wpa_child_l10n = 'var WPA_CHILD_L10N = ' . wp_json_encode(
	array(
		'backToTop' => __( '回到顶部', 'wp-academy-child' ),
	),
	JSON_UNESCAPED_UNICODE
) . ';';
wp_add_inline_script( 'wp-academy-child-js', $wpa_child_l10n, 'before' );

两个关键细节：① 用 wp_json_encode() 而不是 json_encode()——前者会经过 wp_json_encode 过滤器，兼容更宽；② JSON_UNESCAPED_UNICODE 让中文直接输出，避免 中文 这种转义——JS 能正常解析，但可读性差且增大体积。

两者对比：

wp_localize_scriptwp_add_inline_script
出现版本古早WP 4.5+
用途主要设计给「翻译字符串」任意 JS 代码片段
变量名自动生成对象名完全由你控制
数据类型只接受数组 → 转成对象任意字符串（也可是完整脚本）
推荐度兼容旧代码新项目首选

25.5.3 nonce 与 ajaxurl 的安全传递 ​

AJAX 请求必须带 nonce 校验（第 32 章安全专题展开），而 nonce 必须从前端传到后端。传递的标准姿势：

php
// 1. 服务端生成 nonce。
$wpa_ajax_nonce = wp_create_nonce( 'wpa_frontend_action' );

// 2. 通过 wp_add_inline_script 输出到全局变量。
$wpa_ajax_config = 'var WPA_AJAX_CONFIG = ' . wp_json_encode(
	array(
		'ajaxUrl' => admin_url( 'admin-ajax.php' ),
		'nonce'   => $wpa_ajax_nonce,
		'restUrl' => rest_url( 'wp/v2/' ),
	),
	JSON_UNESCAPED_UNICODE
) . ';';
wp_add_inline_script( 'wp-academy-main-js', $wpa_ajax_config, 'before' );

前端消费：

javascript
fetch( WPA_AJAX_CONFIG.ajaxUrl, {
	method: 'POST',
	body: new URLSearchParams( {
		action: 'wpa_load_more',
		nonce:  WPA_AJAX_CONFIG.nonce,
		// ……
	} ),
} );

admin_url( 'admin-ajax.php' ) 不是秘密地址，真正防住未授权攻击的是后端对 nonce 的校验。nonce 的作用不是隐藏端点，而是验证请求确实来自当前用户、当前页面、当前会话。

25.6 区块主题与现代构建工具 ​

25.6.1 区块主题样式：wp_enqueue_block_style ​

经典主题在编辑器里想让区块有「主题专属外观」，用 add_editor_style()（配套 inc/assets.php 已含）。对于全区块主题，如果需要在前台为特定区块追加样式，用 wp_enqueue_block_style：

php
/**
 * 给 core/quote 区块注册主题专属样式。
 */
add_action( 'init', function () {
	wp_enqueue_block_style(
		'core/quote',
		array(
			'handle' => 'wp-academy-block-quote',
			'src'    => get_theme_file_uri( 'assets/css/blocks/quote.css' ),
			'path'   => get_theme_file_path( 'assets/css/blocks/quote.css' ),
		)
	);
} );

它会生成内联 <style> 标签，只在「该区块真正出现在页面内容中」时才加载（不是全局加载），是区块主题性能优化的关键 API。

25.6.2 Vite 构建与 manifest 按 hash 入队 ​

现代前端开发用 Vite / Webpack 打包后，文件名带 hash：main-a3f1b2c.js。PHP 需要读取构建产物目录下的 manifest.json 才能正确拿到 URL：

json
{
  "src/main.js": {
    "file": "assets/main-a3f1b2c.js",
    "css": ["assets/main-a3f1b2c.css"]
  }
}

PHP 端入队逻辑：

php
/**
 * 从 Vite manifest 读取资源并入队（教学示例，生产需加缓存）。
 *
 * @return void
 */
function wpa_vite_enqueue() {
	$manifest_path = WPA_DIR . '/dist/.vite/manifest.json';
	if ( ! file_exists( $manifest_path ) ) {
		return;
	}

	$manifest = json_decode( file_get_contents( $manifest_path ), true ); // phpcs:ignore WordPress.WP.AlternativeFunctions.file_get_contents_file_get_contents
	if ( ! is_array( $manifest ) || ! isset( $manifest['src/main.js'] ) ) {
		return;
	}

	$entry = $manifest['src/main.js'];

	// CSS（Vite 把 CSS 抽成独立文件）。
	if ( ! empty( $entry['css'] ) ) {
		foreach ( (array) $entry['css'] as $css_file ) {
			wp_enqueue_style(
				'wp-academy-vite',
				WPA_URI . '/dist/' . $css_file,
				array(),
				null // hash 已在文件名中，ver 给 null 不再追加 Query String。
			);
		}
	}

	// JS。
	wp_enqueue_script(
		'wp-academy-vite',
		WPA_URI . '/dist/' . $entry['file'],
		array(),
		null,
		true
	);
}
add_action( 'wp_enqueue_scripts', 'wpa_vite_enqueue' );

要点：① ver => null 不追加 ?ver=——文件名已含内容哈希，Query String 反而干扰 CDN 缓存键；② CSS 与 JS 的文件名由 manifest['src/main.js'] 统一带出，保证二者同源同版本；③ 生产环境建议把 file_get_contents + json_decode 结果缓存到 transient，避免每次请求都读文件。

25.7 script_loader_tag：给脚本加 defer / async ​

25.7.1 原理说明 ​

wp_enqueue_script 的 $in_footer 控制位置，但它不会改标签属性。要加 defer、async、type="module" 等，用 script_loader_tag 过滤器：

php
/**
 * 给主脚本追加 defer 属性（配套主题已在 assets.php 用 wp_script_add_data，
 * 这里是 script_loader_tag 的演示写法，两者等价）。
 *
 * @param string $tag    完整的 <script> 标签 HTML。
 * @param string $handle 脚本 handle。
 * @return string
 */
function wpa_defer_main_script( $tag, $handle ) {
	if ( 'wp-academy-main-js' === $handle ) {
		$tag = str_replace( ' src=', ' defer src=', $tag );
	}
	return $tag;
}
add_filter( 'script_loader_tag', 'wpa_defer_main_script', 10, 2 );

配套 inc/assets.php 选择用 wp_script_add_data( 'wp-academy-main-js', 'defer', true )——这是 WP 5.7+ 的原生支持，不需要字符串替换，更干净。两种写法效果一样：最终标签变成 <script defer src="…"></script>。

⚠️ defer 和 async 不要混用。defer 保证按入队顺序执行（适合有依赖的模块化脚本）；async 下载完立即执行，顺序不可控（适合独立统计/埋点）。

25.7.2 style_loader_tag：同理给样式加属性 ​

php
function wpa_preload_main_style( $tag, $handle ) {
	if ( 'wp-academy-main' === $handle ) {
		$tag = str_replace(
			"rel='stylesheet'",
			"rel='preload' as='style' onload=\"this.rel='stylesheet'\"",
			$tag
		);
	}
	return $tag;
}
add_filter( 'style_loader_tag', 'wpa_preload_main_style', 10, 2 );

这是「关键 CSS 内联 + 非关键 CSS preload」策略的一部分，第 29 章性能专题会深入。

25.8 常见问题 ​

25.8.1 jQuery noConflict 与重复加载 ​

WordPress 自带的 jQuery 默认运行在 noConflict 模式：$ 不是 jQuery，必须用 jQuery(...) 或自执行函数包裹：

javascript
// 正确
jQuery( function ( $ ) {
	$( '.toggle' ).on( 'click', function () { /* …… */ } );
} );

// 错误：noConflict 下 $ 未定义。
$( '.toggle' ).on( 'click', function () { /* …… */ } );

重复加载通常来自：插件单独引入了自己的 jQuery CDN；主题 hand-written 标签又加载一次。解法：全部走 wp_enqueue_script 并用 'jquery' 作为依赖 handle——核心保证同一 handle 只输出一次。

25.8.2 CSS 特异性战争 ​

「我加了样式为什么不生效？」第一排查项不是 !important，而是入队顺序。看配套主题的设计：

php
// style.css（wp-academy-style）
// main.css（wp-academy-main，deps = [ 'wp-academy-style' ]）

main.css 排在 style.css 之后，同特异性规则按后出者胜。若子主题要覆盖 main.css，按第 15 章（子主题）的做法：在 wpa_child_enqueue_assets() 里把 wp-academy-child 的 deps 写成 array( 'wp-academy-style', 'wp-academy-main' )，子样式自然排在最后。不改 HTML、不改选择器、不用 !important，只靠入队顺序打赢特异性。

25.8.3 表单里用了 <link> 标签导致 CSP 报错？ ​

那不是 WordPress 的锅，而是 Content Security Policy（CSP）。如果用 wp_enqueue 体系，插件可以挂 wp_enqueue_scripts 统一给资源加 nonce 属性；手写标签则完全暴露。一句话：手写标签在 CSP 环境下是自寻死路。
