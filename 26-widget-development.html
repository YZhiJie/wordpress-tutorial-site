第 26 章 小工具开发：经典与区块化 ​

🔴 高级难度 ｜ 一句话导览：小工具是主题侧栏和页脚的「乐高积木」。本章从 WP_Widget 四方法骨架入手，逐行精读配套公告小工具的真实源码，再讲清经典小工具在 5.8+ 区块编辑器中的生存方式，最后用侧栏注册把主题与小工具衔接起来。

学习目标 ​

  • 能独立写出 WP_Widget 子类：构造函数（注册信息）、widget（前台输出）、form（后台表单）、update（保存清洗）
  • 逐行讲透配套 class-widget-announcement.php 的安全设计：esc/wp_kses_post、get_field_id/get_field_name、颜色白名单
  • 理解经典小工具与区块小工具在 5.8+ 时代的共存：legacy-widget、register_sidebar 的 before_widget 约定
  • 会注册侧栏并在模板中消费，掌握 is_active_sidebar / dynamic_sidebar 的兜底策略
  • 能给出一个「近期文章带缩略图」小工具的完整骨架
  • 能诊断 update 返回缺失、kses 白名单截断、区块界面找不到经典小工具等常见问题

26.1 WP_Widget 四方法与 widgets_init ​

26.1.1 原理说明：小工具的生命周期 ​

经典小工具（Classic Widget）由 WP_Widget 子类实现，生命周期四阶段对应四个方法：

阶段方法调用时机核心职责
注册__construct()widgets_init 时 register_widget()声明 id_base、name、描述、类名
前台展示widget( $args, $instance )侧栏输出时按 $args 包裹 HTML + $instance 数据渲染
后台表单form( $instance )小工具编辑器里输出表单字段，id/name 用 helper 方法
保存清洗update( $new_instance, $old_instance )保存配置时消毒、白名单校验、返回清洗后的数组

widgets_init 是 WordPress 注册小工具和小工具区的标准钩子。配套插件在 wp-academy-demo.php 的 WPA_Demo 类里：

php
add_action( 'widgets_init', [ __CLASS__, 'register_widgets' ] );

public static function register_widgets(): void {
	register_widget( 'WPA_Widget_Announcement' );
}

注意 register_widget 的参数是类名字符串，不是实例。核心在 widgets_init 时自动实例化。

26.1.2 方法签名约束：不要加类型声明 ​

WP_Widget 父类的三个方法没有类型声明。PHP 子类收窄签名会报 fatal error：

php
// 错误：父类没有声明返回类型，子类不能加。
public function widget( array $args, array $instance ): void { /* …… */ }

// 正确：保持父类签名原样。
public function widget( $args, $instance ) { /* …… */ }

配套 class-widget-announcement.php 文件头注释第三条坑点原话：「重写 WP_Widget 的三个方法时不要加参数/返回值类型声明」。

26.2 逐行精读：class-widget-announcement.php ​

26.2.1 构造函数：注册小工具信息 ​

php
public function __construct() {
	parent::__construct(
		'wpa_announcement',            // id_base：全站唯一标识，数据库按它存实例。
		'WP Academy：公告',              // name：后台小工具列表显示的名字。
		[
			'description'                 => '展示一条带主题色左边框的站点公告，内容支持 a、br、strong 等安全 HTML。',
			'classname'                   => 'wpa-widget-announcement',
			'customize_selective_refresh' => true, // 支持定制器局部刷新。
		]
	);
}

三个字段的含义：

  • id_base：数据库里存储的小工具实例键前缀（形如 wpa_announcement-2）。改这个值等于让已保存的配置全部丢失；
  • classname：输出到小工具外层 HTML 的 CSS 类名（见 before_widget 里的 %2$s）；
  • customize_selective_refresh：支持定制器的「局部刷新」——改标题/内容时不重载整页（第 28 章展开）。

26.2.2 widget()：前台输出与转义纪律 ​

php
public function widget( $args, $instance ) {
	$instance = wp_parse_args(
		(array) $instance,
		[
			'title'   => '',
			'message' => '',
			'color'   => '#2563eb',
		]
	);

	$title   = (string) $instance['title'];
	$message = (string) $instance['message'];
	$color   = (string) $instance['color'];

	// 再做一次白名单兜底（历史脏数据/手动改库的情况）。
	if ( ! array_key_exists( $color, self::colors() ) ) {
		$color = '#2563eb';
	}

wp_parse_args 给缺省键补上默认值——小工具首次被拖入侧栏时 $instance 可能是空数组。随后对 $title、$message、$color 做强制类型转换，避免后续拼接时类型报错。

颜色白名单在 widget() 里再验一次：数据库里可能被手动改脏、或旧版本白名单升级后部分旧值失效。这是「不信任任何存储数据」的防御性写法。

前台输出的 HTML 构造：

php
$slugs = self::color_slugs();
$slug  = $slugs[ $color ] ?? 'blue';

// before_widget / after_widget 是主题在 register_sidebar 时声明的受信 HTML。
echo $args['before_widget']; // phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped

if ( '' !== $title ) {
	echo $args['before_title'];
	echo esc_html( apply_filters( 'widget_title', $title, $instance, $this->id_base ) );
	echo $args['after_title'];
}

$style = 'border-left-color:' . esc_attr( $color ) . ';';

printf(
	'<div class="wpa-announcement wpa-announcement--%1$s" role="note" style="%2$s">%3$s</div>',
	esc_attr( $slug ),
	$style,
	wp_kses_post( $message )
);

echo $args['after_widget'];

转义纪律逐条对照：

数据处理方式为什么
$args['before_widget'] 等直接 echo，phpcs:ignore主题 register_sidebar 声明的受信 HTML，WP 惯例豁免
$titleesc_html() + apply_filters('widget_title')小工具标题可能被插件修改，过滤后再转义
$coloresc_attr()进 style 属性，用属性级转义
$slugesc_attr()进 class 属性
$messagewp_kses_post()允许安全的内联 HTML（a/br/strong 等），剥除 script/事件属性

⚠️ 配套注释强调：小工具保存走核心流程，核心已做 nonce + 能力校验；widget() 里只负责输出转义，不要自己加 wp_verify_nonce——那是自建 AJAX/设置表单才需要的。

26.2.3 form()：后台表单与字段关联 ​

php
public function form( $instance ) {
	$instance = wp_parse_args(
		(array) $instance,
		[
			'title'   => '站点公告',
			'message' => '',
			'color'   => '#2563eb',
		]
	);
	?>
	<p>
		<label for="<?php echo esc_attr( $this->get_field_id( 'title' ) ); ?>">标题</label>
		<input
			type="text"
			class="widefat"
			id="<?php echo esc_attr( $this->get_field_id( 'title' ) ); ?>"
			name="<?php echo esc_attr( $this->get_field_name( 'title' ) ); ?>"
			value="<?php echo esc_attr( $instance['title'] ); ?>"
		>
	</p>

两个 helper 方法的作用：

  • $this->get_field_id( 'title' )：返回形如 widget-wpa_announcement-2-title 的唯一 id，保证同一小工具多个实例时 label 与 input 正确关联；
  • $this->get_field_name( 'title' )：返回形如 widget-wpa_announcement[2][title] 的 name，保证 POST 数据能被核心按小工具实例分桶。

🔥 不用的后果：拖入两个公告小工具，改第二个的标题，第一个跟着变——id/name 不唯一导致数据互相覆盖。

textarea 的回显用 esc_textarea()，不是 esc_attr()：

php
<textarea
	class="widefat"
	rows="5"
	id="<?php echo esc_attr( $this->get_field_id( 'message' ) ); ?>"
	name="<?php echo esc_attr( $this->get_field_name( 'message' ) ); ?>"
><?php echo esc_textarea( $instance['message'] ); ?></textarea>

esc_textarea() 同时处理 HTML 实体和换行符，是 textarea 回显的标准函数。

26.2.4 update()：保存清洗是安全最后一道门 ​

php
public function update( $new_instance, $old_instance ) {
	unset( $old_instance ); // 旧实例不用，全部按白名单重建。

	$new_instance = is_array( $new_instance ) ? $new_instance : [];
	$colors       = self::colors();

	$instance = [
		'title'   => sanitize_text_field( $new_instance['title'] ?? '' ),
		'message' => sanitize_textarea_field( $new_instance['message'] ?? '' ),
	];

	$raw_color         = is_string( $new_instance['color'] ?? null ) ? $new_instance['color'] : '#2563eb';
	$instance['color'] = array_key_exists( $raw_color, $colors ) ? $raw_color : '#2563eb';

	return $instance;
}

清洗逻辑逐条：

字段清洗函数为什么
titlesanitize_text_field()纯文本，剥 HTML 标签与多余空白
messagesanitize_textarea_field()保留换行，但剥 HTML 标签与多余空白
colorarray_key_exists 白名单只允许预定义四色，拒绝任意 CSS 注入

颜色用 array_key_exists($raw_color, $colors) 而不是 in_array()：前者 O(1) 且语义精确（白名单是键不是值）。如果前端提交 #ff0000（不在白名单），直接回退默认蓝——这就是「拒绝非法输入，不报错、不爆炸」的防御性姿态。

必须 return $instance。漏了返回值，保存后配置全部丢失——这是新人踩坑第一名。

26.3 经典小工具与区块小工具的共存 ​

26.3.1 5.8+ 的变化：区块编辑器接管小工具界面 ​

WordPress 5.8 起，后台「外观 → 小工具」默认切换到区块编辑器界面。经典小工具没有消失，只是换了一个入口：拖入「传统小工具」区块（legacy widget block），然后在里面选你的经典小工具。

配套 class-widget-announcement.php 的构造函数声明了 'customize_selective_refresh' => true，所以它在定制器里也能局部刷新——这是经典小工具在现代界面下保持体验的关键。

26.3.2 register_sidebar 的 before_widget 约定 ​

经典小工具的输出依赖主题在小工具区注册时声明的包裹 HTML。看配套 inc/widgets.php：

php
register_sidebar(
	array(
		'name'          => __( '主侧栏', 'wp-academy' ),
		'id'            => 'sidebar-1',
		'before_widget' => '<section id="%1$s" class="widget %2$s">',
		'after_widget'  => '</section>',
		'before_title'  => '<h2 class="widget-title">',
		'after_title'   => '</h2>',
	)
);

%1$s 和 %2$s 是 WordPress 自动填充的占位符：

  • %1$s：小工具实例的 DOM id（如 wpa_announcement-2）；
  • %2$s：小工具类名（来自构造函数里的 classname + 核心追加的 widget_wpa_announcement）。

如果主题的 before_widget 不写 %1$s/%2$s，小工具就没有唯一 id 和类名，CSS 和 JS 无法精准定位——这是主题对小工具生态的基本契约。

图 26-2：5.8+ 区块编辑器侧栏中，拖入「传统小工具」后可选择已注册的经典小工具

26.3.3 常见问题 ​

  • 问：区块编辑器里找不到我的经典小工具？ 确认类已注册到 widgets_init；确认小工具没有 show_in_rest => false 限制；清除浏览器缓存后刷新。
  • 问：经典小工具在定制器里改了不刷新？ 构造函数里没开 customize_selective_refresh => true，或者主题没声明对应支持。开它。

26.4 主题侧栏注册与模板消费 ​

26.4.1 配套四区注册 ​

配套 inc/widgets.php 注册了四个小工具区：

id名称用途
sidebar-1主侧栏文章/页面/归档右侧
footer-1页脚栏目一页脚第一列
footer-2页脚栏目二页脚第二列
footer-3页脚栏目三页脚第三列

footer-1/2/3 用 foreach 批量注册，减少复制粘贴：

php
$footer_areas = array(
	'footer-1' => __( '页脚栏目一', 'wp-academy' ),
	'footer-2' => __( '页脚栏目二', 'wp-academy' ),
	'footer-3' => __( '页脚栏目三', 'wp-academy' ),
);

foreach ( $footer_areas as $footer_id => $footer_name ) {
	register_sidebar(
		array(
			'name'          => $footer_name,
			'id'            => $footer_id,
			// ……
		)
	);
}

26.4.2 模板中消费：is_active_sidebar 与 dynamic_sidebar ​

配套 sidebar.php 的完整策略（复习 23.2.5）：

php
<?php if ( is_active_sidebar( 'sidebar-1' ) ) : ?>
	<?php dynamic_sidebar( 'sidebar-1' ); ?>
<?php else : ?>
	<!-- 兜底内容：搜索、近期文章、按月归档 -->
<?php endif; ?>

is_active_sidebar() 判断后台是否配置过小工具；dynamic_sidebar() 按 id 输出对应小工具区的全部内容。两者 id 必须严格一致——sidebar-1 是主题内部契约，改名等于让全站模板和小工具配置全部失联。

配套 footer.php 的页脚小工具消费也值得再看一次：三个区全部为空时，整个 .footer-widgets 容器不渲染。这是「零 DOM 噪音」的典范。

26.5 进阶练习骨架：近期文章带缩略图小工具 ​

以下是一个可直接放进主题或插件的骨架，文本域 wp-academy（放主题）或 wp-academy-demo（放插件）。它把本章所有知识点串起来：

php
<?php
/**
 * 近期文章带缩略图小工具（骨架）。
 *
 * 用途：侧栏展示最近 5 篇有缩略图的文章，每篇一行：缩略图 + 标题 + 日期。
 *
 * @package WP_Academy
 */

class WPA_Widget_Recent_Thumbnails extends WP_Widget {

	public function __construct() {
		parent::__construct(
			'wpa_recent_thumbnails',
			__( 'WP Academy：近期文章带缩略图', 'wp-academy' ),
			[
				'description' => __( '展示最近几篇带缩略图的文章卡片。', 'wp-academy' ),
				'classname'   => 'wpa-widget-recent-thumbnails',
			]
		);
	}

	public function widget( $args, $instance ) {
		$instance = wp_parse_args(
			(array) $instance,
			[
				'title'      => __( '近期文章', 'wp-academy' ),
				'number'     => 5,
				'show_date'  => true,
			]
		);

		$title     = sanitize_text_field( $instance['title'] );
		$number    = absint( $instance['number'] );
		$show_date = (bool) $instance['show_date'];

		if ( 1 > $number || 50 < $number ) {
			$number = 5;
		}

		$recent = new WP_Query(
			[
				'post_type'           => 'post',
				'posts_per_page'      => $number,
				'ignore_sticky_posts' => true,
				'no_found_rows'       => true,
				'meta_query'          => [
					[
						'key'     => '_thumbnail_id',
						'compare' => 'EXISTS',
					],
				],
			]
		);

		if ( ! $recent->have_posts() ) {
			wp_reset_postdata();
			return;
		}

		echo $args['before_widget']; // phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped

		if ( '' !== $title ) {
			echo $args['before_title']; // phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped
			echo esc_html( apply_filters( 'widget_title', $title, $instance, $this->id_base ) );
			echo $args['after_title']; // phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped
		}

		echo '<ul class="wpa-recent-thumbnails-list">';
		while ( $recent->have_posts() ) :
			$recent->the_post();
			?>
			<li>
				<a href="<?php the_permalink(); ?>">
					<?php if ( has_post_thumbnail() ) : ?>
						<?php the_post_thumbnail( 'thumbnail', [ 'alt' => esc_attr( get_the_title() ) ] ); ?>
					<?php endif; ?>
					<span class="wpa-recent-title"><?php echo esc_html( get_the_title() ); ?></span>
					<?php if ( $show_date ) : ?>
						<time datetime="<?php echo esc_attr( get_the_date( DATE_W3C ) ); ?>">
							<?php echo esc_html( get_the_date() ); ?>
						</time>
					<?php endif; ?>
				</a>
			</li>
			<?php
		endwhile;
		echo '</ul>';

		wp_reset_postdata();
		echo $args['after_widget']; // phpcs:ignore WordPress.Security.EscapeOutput.OutputNotEscaped
	}

	public function form( $instance ) {
		$instance = wp_parse_args(
			(array) $instance,
			[
				'title'     => __( '近期文章', 'wp-academy' ),
				'number'    => 5,
				'show_date' => true,
			]
		);
		?>
		<p>
			<label for="<?php echo esc_attr( $this->get_field_id( 'title' ) ); ?>">
				<?php esc_html_e( '标题：', 'wp-academy' ); ?>
			</label>
			<input
				class="widefat"
				id="<?php echo esc_attr( $this->get_field_id( 'title' ) ); ?>"
				name="<?php echo esc_attr( $this->get_field_name( 'title' ) ); ?>"
				type="text"
				value="<?php echo esc_attr( $instance['title'] ); ?>"
			>
		</p>
		<p>
			<label for="<?php echo esc_attr( $this->get_field_id( 'number' ) ); ?>">
				<?php esc_html_e( '数量：', 'wp-academy' ); ?>
			</label>
			<input
				class="widefat"
				id="<?php echo esc_attr( $this->get_field_id( 'number' ) ); ?>"
				name="<?php echo esc_attr( $this->get_field_name( 'number' ) ); ?>"
				type="number"
				min="1"
				max="50"
				step="1"
				value="<?php echo esc_attr( (int) $instance['number'] ); ?>"
			>
		</p>
		<p>
			<input
				class="checkbox"
				id="<?php echo esc_attr( $this->get_field_id( 'show_date' ) ); ?>"
				name="<?php echo esc_attr( $this->get_field_name( 'show_date' ) ); ?>"
				type="checkbox"
				<?php checked( $instance['show_date'] ); ?>
			>
			<label for="<?php echo esc_attr( $this->get_field_id( 'show_date' ) ); ?>">
				<?php esc_html_e( '显示日期', 'wp-academy' ); ?>
			</label>
		</p>
		<?php
	}

	public function update( $new_instance, $old_instance ) {
		unset( $old_instance );

		$instance = [
			'title'     => sanitize_text_field( $new_instance['title'] ?? '' ),
			'number'    => absint( $new_instance['number'] ?? 5 ),
			'show_date' => ! empty( $new_instance['show_date'] ),
		];

		if ( 1 > $instance['number'] || 50 < $instance['number'] ) {
			$instance['number'] = 5;
		}

		return $instance;
	}
}

26.6 常见问题（本章汇总） ​

  1. update 不返回 $instance → 配置丢失：这是第一坑。update() 必须 return array，漏了就是空配置；
  2. wp_kses_post 剥掉了我的合法标签：默认允许的 HTML 标签是有限的（含 a/br/strong/em/h1-h6 等）。如果你需要更多标签，用 wp_kses_allowed_html('post') 为基线再追加，或在主题 functions.php 里通过 wp_kses_allowed_html 过滤器扩展；
  3. 区块编辑器里拖不进经典小工具：确认后台「外观 → 小工具」用的是传统界面，或区块编辑器里找「传统小工具」区块；如果用了块主题（如 wp-academy-block），小工具界面被「外观 → 编辑器」取代，经典小工具只能在「传统小工具」区块中使用；
  4. 同一小工具多个实例数据互相覆盖：检查 form() 里的 id/name 是否用了 $this->get_field_id() / $this->get_field_name()，手写固定 id 必中此坑；
  5. widget() 里的 $args['before_widget'] 不输出类名：主题的 register_sidebar 没写 %2$s，或者构造函数里没声明 classname。

动手练习 ​

练-26-01（操作题）｜逐行验证转义

打开配套 class-widget-announcement.php，在 widget() 里故意把 esc_html( apply_filters( 'widget_title', … ) ) 改成直接 echo $title，然后在后台小工具里写入 <script>alert('xss')</script> 作为标题，保存后刷新前台，确认弹窗出现。恢复转义并说明为什么 apply_filters 必须在 esc_html 内部（而不是先过滤再转义）。

练-26-02（操作题）｜新增一个「课程筛选」小工具

以 class-widget-announcement.php 为蓝本，新建 WPA_Widget_Course_Filter（id_base：wpa_course_filter），提供两个字段：课程分类下拉（从 course_category 分类法动态读取）和显示数量（1-20，默认 6）。widget() 中用 WP_Query 查询对应分类的课程，以 <ul> 列表输出标题链接。要求：字段 id/name 用 helper、数量钳制、查询后复位。文本域 wp-academy-demo。

练-26-03（操作题）｜测试多实例隔离

在后台侧栏拖入两个「WP Academy：公告」小工具，分别设不同标题、内容和颜色。保存后前台检查：两个小工具是否独立显示、数据是否互不干扰。若出现数据覆盖，检查 form() 里的 id/name 是否用了 $this->get_field_id()。

练-26-04（思考题）｜颜色白名单 vs sanitize_hex_color

配套小工具在 update() 里用 array_key_exists 做颜色白名单，而不是 sanitize_hex_color()。请分析：① 如果用 sanitize_hex_color，能达到同样的安全效果吗？② 两者在用户体验上有什么区别（非法输入的处理方式）？③ 在什么场景下你会选白名单、什么场景下选 sanitize_hex_color？

练-26-05（思考题）｜从经典到区块

WordPress 6.x 起推荐把经典小工具改写成「区块（Block）」。请对比：① 经典小工具用 PHP 类实现，区块小工具用 React + block.json 注册——两者在开发、部署、主题切换时的行为差异；② 为什么本教程仍然把经典小工具作为主线教学内容？（提示：生态存量、学习曲线、经典主题的兼容性）
