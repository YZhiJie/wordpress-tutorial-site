第 11 章 主题生态系统 ​

🟢 入门难度 ｜ 一句话导览：主题是 WordPress 的「皮肤系统」——它决定站点长什么样，却不应该绑架你的内容。本章先讲透「内容与表现分离」这条总原则，再对比经典主题与区块主题两代技术，带你逛一遍官方主题库与商业市场，给出一份可照抄的选主题检查清单，最后拆穿盗版主题与「换皮丢内容」这两个新手最容易踩的坑。

学习目标 ​

  • 能用一句话说清主题管什么、不管什么，理解「内容与表现分离」原则
  • 会区分经典主题（PHP 模板）与区块主题（theme.json + HTML 区块模板），知道两代主题各自的编辑入口
  • 会在官方主题库 wordpress.org/themes 用特征过滤找主题，理解官方审核机制意味着什么
  • 拿到一个商业主题时，能对照 8 项检查清单做出「买/不买」决策
  • 理解 Twenty 系列默认年度主题的存在价值
  • 能识别盗版（nulled）主题的安全风险，理解为什么「功能型主题」会导致换主题丢内容

11.1 主题是什么：内容与表现分离 ​

11.1.1 原理说明 ​

WordPress 的设计哲学里有一条贯穿始终的线：内容存在数据库里，长什么样由主题决定，能干什么由插件决定。

  • 你的文章、页面、分类、菜单设置，都存在数据库中（见第 05 章的表结构讲解）；
  • 主题（Theme）是一组模板文件 + 样式表 + 配置，负责把数据库里的内容「渲染」成访客看到的页面；
  • 换主题 = 换一套渲染规则，内容本身一个字节都不会动。

这就是为什么你可以上午用 A 主题、下午换 B 主题，文章一篇不少——变的只是外观。这条原则也是后面所有「选主题」判断的出发点：凡是换主题就会丢的东西，本来就不该由主题提供。

分层关系一张图：

mermaid
flowchart TD
    subgraph 数据层[数据库 —— 内容的家]
        D1[文章 / 页面]
        D2[分类 / 标签]
        D3[用户 / 评论]
        D4[设置选项]
    end
    subgraph 功能层[插件 —— 能力的来源]
        P1[自定义文章类型]
        P2[表单 / SEO / 电商]
    end
    subgraph 表现层[主题 —— 外观的皮肤]
        T1[模板文件]
        T2[样式表 / theme.json]
        T3[菜单位置 / 小工具区]
    end
    数据层 --> 功能层 --> 表现层 --> V[访客看到的页面]

三层各司其职：换主题只动表现层，数据层无感；换插件影响功能层，数据层依然无感。这个图值得截图收藏——之后遇到「我换了 XX 会不会丢东西」的问题，先定位它属于哪一层。

一个主题在磁盘上就是 wp-content/themes/ 下的一个目录。最小的合法主题只需要两个文件：

wp-content/themes/my-theme/
├── style.css   ← 文件头注释里声明主题名称等信息（必需）
└── index.php   ← 兜底模板（经典主题必需；区块主题用 templates/index.html 替代）

style.css 开头的头注释（Theme Header）是 WordPress 识别主题的唯一依据，第 15 章讲子主题时会逐字段拆解。

一个真实可用的经典主题，目录结构大致如下（以本教程配套的 wp-academy 为例）：

wp-academy/
├── style.css                ← 主题头注释 + 基础样式
├── functions.php            ← 主题引导文件：注册菜单、挂载钩子、入队资源
├── index.php                ← 兜底模板（模板层级的最后一道）
├── front-page.php           ← 静态首页模板
├── home.php                 ← 文章列表页模板
├── single.php / page.php    ← 单篇文章 / 单个页面模板
├── archive.php / category.php / tag.php / date.php / author.php / search.php / 404.php
├── header.php / footer.php / sidebar.php   ← 共用模板部件
├── template-parts/          ← 内容片段（content.php 等，供 get_template_part() 复用）
├── page-templates/          ← 页面专属模板（在页面编辑器下拉可选）
├── inc/                     ← 按职责拆分的 PHP 模块（setup.php、assets.php……）
└── assets/                  ← CSS / JS / 图片等静态资源

每个模板文件「什么情况下被选中」由**模板层级（Template Hierarchy）**规则决定，本模块不涉及细节，只需先建立一个印象：WordPress 接到一个页面请求后，会按固定顺序在主题目录里找「最匹配的模板文件」，找到即用，找不到就一路回退到 index.php。

区块主题的目录则是另一副面孔（以 wp-academy-block 为例）：

wp-academy-block/
├── style.css          ← 只剩主题头注释，样式几乎全部交给 theme.json
├── theme.json         ← 全局样式与编辑器配置中心（配色、字体、间距、布局）
├── templates/         ← 区块模板（index.html、single.html、404.html……）
└── parts/             ← 模板部件（header.html、footer.html）

注意区块主题里没有 functions.php 也完全可以运行——不写 PHP 是纯区块主题的一大卖点（有需求时仍可加 functions.php 挂钩子）。

11.1.2 主题与插件的边界：一条黄金准则 ​

社区里流传一句话：「外观归主题，功能归插件」。判断标准很简单——问自己一个问题：

如果我明天换主题，这个东西还应该存在吗？

需求换主题后还应该存在？应该放在
首页轮播图的配色、圆角无所谓，可以跟着主题变主题
文章卡片排成两栏还是三栏无所谓主题
自定义文章类型「课程」必须在，否则课程数据无法管理插件（见第 09 章与模块四）
联系表单必须在插件
短代码 [pricing_table]必须在，否则旧文章里全是裸短代码文本插件
SEO 的 meta 描述必须在插件

本教程配套示例严格遵循这条边界：经典父主题 wp-academy 只负责外观与模板；「课程」这类内容结构由插件提供。11.6.2 会用一个真实场景讲透违背这条准则的代价。

11.1.3 操作方法：亲手验证「换主题不丢内容」 ​

这是一次两分钟就能做完的实验，建议每个新手都做一次：

  1. 确认后台已有至少 3 篇文章、1 个页面、若干分类（没有就快速造几条测试内容）；
  2. 进入 外观 → 主题，当前启用主题右侧显示「已启用」；
  3. 把鼠标悬停到另一个已安装主题（如 Twenty Twenty-Five）上，点击 「实时预览」——注意：此时站点并未真正切换，只是预览；
  4. 退出预览，直接点击 「启用」 完成切换；
  5. 打开前台首页和任意一篇文章：内容都在，只是排版、配色、菜单位置变了；
  6. 再切回原主题，一切恢复。

结论：内容安全，变的是「皮肤」。但注意菜单、小工具这类「主题相关配置」是按主题分别保存位置的，切换后可能需要重新指派——第 12 章 12.5 节会专门讲。

这个实验背后对应着 WordPress 内部的存储分工：文章内容在 wp_posts 表，与主题完全无关；而「哪个菜单放在哪个位置」「哪个小工具放进哪个边栏」保存在选项表中，键名里带着主题标识——所以换主题后内容原样、位置配置需要重新认领。理解了这一层，「换主题后菜单不见了」就从惊吓变成了预期行为。

11.2 经典主题与区块主题：两代技术并存 ​

11.2.1 原理说明 ​

WordPress 主题目前有两代技术体系，在 WordPress 7.1 时代同时合法存在：

  • 经典主题（Classic Themes）：沿用至今的传统体系。用 PHP 模板文件（single.php、archive.php……）按模板层级拼装页面，用户通过 自定义器（Customizer） 调整外观。本教程配套示例 wp-academy 就是经典主题。
  • 区块主题（Block Themes）：自 WordPress 5.9 引入、如今已成为官方主推方向的新体系。模板是 templates/ 目录下的 HTML 区块注释文件，全站配色/字体/间距由根目录 theme.json 集中声明，用户通过 站点编辑器（Site Editor，即全站编辑 FSE） 用区块搭整个页面——包括页头页脚。配套示例 wp-academy-block 就是区块主题。

两代主题不是「新旧替换」关系，而是面向不同人群的两种范式：经典主题胜在成熟、生态庞大、PHP 可控性强；区块主题胜在无需写代码即可改全站、样式收敛在一个 JSON 里、与区块编辑器体验一致（区块编辑器本身见第 07 章）。

两代主题渲染同一个请求的链路对比：

mermaid
flowchart LR
    subgraph 经典主题
        A1[请求: 某篇文章] --> B1[模板层级选择<br/>single.php]
        B1 --> C1[PHP 执行模板<br/>the_title / the_content]
        C1 --> D1[输出 HTML]
    end
    subgraph 区块主题
        A2[请求: 某篇文章] --> B2[匹配 templates/single.html]
        B2 --> C2[解析区块注释标记<br/>渲染每个区块]
        C2 --> D2[输出 HTML<br/>样式来自 theme.json]
    end

对站点拥有者来说，链路细节可以不懂，但要记住一个实际后果：你在后台看到的编辑入口完全不同，教程、帖子里的截图很可能和你的后台长得不一样——先确认主题代际，再对号入座找操作路径。

11.2.2 对比表：一眼看清两代主题 ​

维度经典主题区块主题
模板形态PHP 文件（single.php、page.php……），按模板层级选择HTML 文件（templates/*.html），内容是区块注释标记
配置中心无统一配置，样式写在 CSS、选项暴露在自定义器根目录 theme.json：调色板、字体、间距、布局宽度集中声明
用户编辑入口外观 → 自定义（Customizer），左侧选项右侧实时预览外观 → 编辑器（Site Editor），直接用区块编辑整站
页头/页脚修改改 PHP 文件或小工具区，通常需要代码在站点编辑器里可视化编辑「模板部件」（Header/Footer）
菜单编辑自定义器或 外观 → 菜单站点编辑器中的「导航块」（Navigation Block）
小工具支持，外观 → 小工具默认不提供小工具界面（区块取而代之）
样式定制自定义器选项 + 额外 CSS + 子主题站点编辑器「样式（Styles）」面板，改动落回 theme.json 的用户配置
对使用者的代码要求深度定制需 PHP/CSS大部分定制零代码；写区块主题本身需理解区块标记

适用人群需要精细 PHP 控制的开发者、依赖成熟商业主题的用户内容型站点、愿意全可视化操作的运营者、玩新范式的开发者

💡 许多流行主题是「混合型」：本质是经典主题，但额外提供了区块编辑器支持（如自定义区块样式、theme.json 部分配置）。判断归属时看它的模板目录——有 templates/index.html 或 templates/*.html 即区块主题，否则是经典主题。

11.2.3 操作方法：判断当前站点用的是哪代主题 ​

不看代码也能判断，30 秒搞定：

  1. 登录后台，看左侧菜单 「外观」 下的子菜单：
    • 出现 「编辑器」（站点编辑器）→ 当前是区块主题；
    • 出现 「自定义」（自定义器）→ 当前是经典主题；
  2. 进一步确认（可选）：进入 外观 → 主题文件编辑器（经典主题）或检查 wp-content/themes/主题名/ 目录——存在 templates/ 目录且内含 .html 文件即区块主题；
  3. 在 外观 → 主题 列表里，官方主题卡片上通常标注「区块主题」标签。

这条判断路径第 13 章还会用到——两套编辑体系的操作完全不同，先分清自己站在哪一边再动手。

💡 还有一种快捷判断：区块主题的详情页/主题卡片上通常带 full-site-editing 标签；在官方库里可以直接用这个标签做特征过滤，专挑区块主题体验新范式。

图 11-1：左侧为经典主题的「外观」菜单（含「自定义」「小工具」「菜单」），右侧为区块主题（顶部即「编辑器」）

11.3 官方主题库 wordpress.org/themes ​

11.3.1 原理说明：官方审核意味着什么 ​

官方主题库（https://wordpress.org/themes/）收录的主题全部免费，且每个主题上架前必须通过人工 + 自动化的主题审核（Theme Review），检查项包括：

  • 代码安全：输出必须转义（esc_html() 等）、不允许 eval、不允许混淆代码；
  • 无恶意行为：不偷偷外链、不隐藏推广链接、不收集数据；
  • 遵循「外观归主题」边界：不允许把自定义文章类型等功能锁进主题；
  • 许可证：必须 100% GPL 兼容（与 WordPress 本体一致）。

因此，官方库是新手选主题的第一站：上限未必惊艳，下限有保证。后台 外观 → 主题 → 安装主题 直接连通官方库，可一键安装（点击级步骤见第 12 章）。

审核的实际运作方式，了解三点即可：

  1. 作者提交后排人工队列：审核员（志愿者 + 官方团队）会用 Theme Check 类工具自动扫描，再人工抽查模板、转义、许可证，整个周期从数天到数周不等；
  2. 每次更新都要重审：主题上架后不是一劳永逸，每个新版本仍会过检——这是「官方库主题不敢乱来」的制度保障；
  3. 违规会被下架：被举报或抽检发现恶意行为（隐藏链接、暗刷统计等）的主题会被移除，但已安装的副本不会自动消失——所以看到「该主题已被官方库移除」的提示时，要主动换主题。

另外，官方库里也住着大量免费增值（Freemium）主题（Astra、GeneratePress、Kadence 等）：免费版过官方审核上架，Pro 版在作者官网售卖。这类主题既有官方审核兜底，又有付费升级通道，是性价比很高的中间路线。

图 11-2：wordpress.org 官方主题库首页，顶部为搜索框与「特征过滤」按钮，下方为主题卡片网格

11.3.2 操作方法：用特征过滤缩小范围 ​

主题库有上万个主题，直接翻页不现实。用**特征过滤（Feature Filter）**三步定位：

  1. 打开 https://wordpress.org/themes/（或后台 外观 → 主题 → 安装主题 → 特征过滤）；
  2. 按三组条件勾选：
    • 主题（Subject）：博客、电商、教育、作品集……按站点性质选；
    • 特征（Features）：常用有 custom-logo（自定义 logo）、custom-colors、full-site-editing（全站编辑，即区块主题）、translation-ready（可翻译，做中文站必勾）；
    • 布局（Layout）：一栏/两栏/侧边栏位置、网格布局等；
  3. 点击「应用过滤器」，在结果里按 更新日期、活跃安装量、评分 排序挑选。

点进任意主题卡片，重点看四个数据：

数据健康线
最近更新6 个月内有更新；超过 1 年未更新基本可放弃
活跃安装量1 万以上说明经过大量站点验证；新主题可放宽，但要更仔细看代码质量
评分与评论4.5 星以上；顺手翻 1 星差评，看抱怨集中在哪（支持差？升级翻车？）
兼容到的 WordPress 版本声明兼容到 7.x 近期版本

别忘了详情页上的 「预览」按钮——它会用一个官方演示站渲染该主题。预览时建议做三个动作：① 把浏览器窗口拖窄到手机宽度，看导航是否折叠、正文是否溢出（响应式基本功，第 14 章会系统讲）；② 点进一篇文章，看正文字号行高是否适合中文长文阅读；③ 按 F12 打开开发者工具，切到 Console 面板，有红色报错的主题直接淘汰——连演示站都带错上线，代码质量可想而知。

图 11-3：官方主题详情页，右侧栏显示版本、最近更新、活跃安装数、评分与兼容版本声明

11.3.3 官方库的局限 ​

官方库只收免费主题，且审核标准要求主题「功能克制」——所以复杂的企业站、电商站需求往往在官方库找不到成品，这才有了商业主题市场。

此外还有两个结构性限制值得知道：

  • 同质化明显：审核规范对「主题该提供什么」约束较死，导致官方库主题在版式上趋同，想要「一眼惊艳」的设计往往需要付费市场；
  • 不支持即弃：免费主题没有商业契约约束，作者随时可能停更（这也是 11.3.2 强调看更新频率的原因）。

好消息是：对练手站、个人博客、文档型站点，官方库完全够用了。把需求养到「官方库确实满足不了」再去付费市场，预算花得才值。

11.4 商业主题市场与选择标准 ​

11.4.1 原理说明：商业主题卖的是什么 ​

商业（付费）主题常见渠道：

  • 综合市场：ThemeForest（量最大）、TemplateMonster 等；
  • 独立主题商店： GeneratePress、Astra、Kadence、Flatsome（电商向）等品牌官网直销；
  • 订阅制俱乐部：一次付费用全店主题（如 CSSIgniter）。

付费买到的一般是四样东西：更完整的设计成品、配套演示数据、页面构建器深度整合、以及最重要的——售后支持与持续更新承诺。注意「演示数据」是把双刃剑：导入后站点点亮效果和演示站一致，但清理不需要的演示内容也是体力活。

三类渠道的性格差异很大：

渠道类型代表价格模式优点风险点
综合市场ThemeForest单品买断（含 6 个月支持，可续）选择极多、竞争激烈价格低质量方差大，「销量高」≠「代码好」；作者停更即弃坑
独立品牌商店GeneratePress、Astra、Kadence年费订阅（站点数分档）或买断更新稳定、支持专业、代码克制订阅中断则失去更新与支持
主题俱乐部CSSIgniter 等年费畅享全店多站点摊薄成本单个主题打磨深度通常不如头部单品

💡 无论哪种渠道，支持（Support）条款要单独看：多数商店卖的是「单站点授权 + N 个月工单支持」，续费买的主要是支持和更新权，而不是主题本身——GPL 许可下主题代码复制本就自由，你付钱买的是服务与信任。

11.4.2 选择标准清单：8 项打分 ​

买之前，对照下表逐项查证（任何一项亮红灯就要三思）：

#检查项合格标准去哪验证
1更新频率近 6 个月有更新记录，更新日志公开可查商品页 changelog
2兼容性声明明确声明兼容 WordPress 7.1、PHP 8.3商品页「Compatible with」字段
3评分与评论4.5 星以上；读最近的差评看厂商如何回应商品页评论区
4演示站速度用 PageSpeed Insights 测演示站，移动端性能分 ≥ 60 及格https://pagespeed.web.dev 输入演示地址
5是否锁死内容内容是否依赖主题自带短代码/私有页面构建器——换主题后旧文章会不会残留一堆 [shortcode] 文本看演示站文章源码、问售前

11.4.3 免费 vs 付费：怎么决策 ​

不是「付费一定好」，按场景选：

场景建议
个人博客、练手站官方库免费主题（含 Twenty 系列）完全够用

企业官网、对设计有明确要求品牌商店付费主题 + 正规发票，重视第 1、7 项

有 PHP 开发能力免费轻量主题打底 + 自建子主题（见第 15 章），长期可控性最强

11.5 默认年度主题：Twenty 系列的价值 ​

11.5.1 原理说明 ​

WordPress 官方几乎每年发布一款以年份命名的默认主题（Twenty Twenty-Three、Twenty Twenty-Four、Twenty Twenty-Five……），新安装会自带最近的若干款。它们的价值不在「漂亮」，而在：

  1. 风向标：每款年度主题都是当年 WordPress 新能力的官方示范——近年的年度主题全是区块主题，想学 theme.json 和区块模板，直接读它们的源码就是第一手教材；
  2. 排障基准：当站点出现诡异问题时，切换到 Twenty 系列主题能快速判断「是主题的问题还是别的问题」——官方主题代码质量有保障，它都出错，问题多半在插件或环境；这也是本教程反复建议始终保留一个默认主题的原因（第 12 章 12.5 节讲删除主题的兜底逻辑）；
  3. 兜底安全网：当前主题文件损坏时，WordPress 会尝试回退到默认主题，避免前台直接白屏。

近年年度主题一览，可以直观看到官方路线的演进：

默认主题随版本发布技术路线学习价值
Twenty Twenty-OneWP 5.6经典主题末期传统自定义器的成熟形态
Twenty Twenty-TwoWP 5.9首款区块主题默认主题全站编辑的初代范式
Twenty Twenty-ThreeWP 6.1区块主题「一个模板 + 多套风格变体」的极简做法
Twenty Twenty-FourWP 6.4区块主题面向企业/作品集的多场景模板组合
Twenty Twenty-FiveWP 6.7区块主题排版优先的博客范式、pattern 大量使用

11.5.2 操作建议 ​

  • 本地练手站：直接用最新的 Twenty 系列起步，边用边读它的 theme.json；
  • 正式站：Twenty 系列可以胜任极简博客，但多数站点会换更贴合业务的主题；
  • 任何站点：至少保留一款 Twenty 系列主题不删除（占用空间可忽略，排障价值巨大）。

11.6 常见问题 ​

11.6.1 盗版（nulled）主题：省小钱，埋大雷 ​

「nulled 主题」指被破解去除授权验证的付费主题，常在某些论坛、网盘流传。风险是实打实的：

  • 恶意代码注入：安全厂商多次在 nulled 主题中检出后门——隐藏的管理员账号、向访客挂马、SEO 垃圾链接（你的站被注入赌博/色情关键词，搜索引擎排名崩盘）；
  • 无更新渠道：主题出了安全漏洞你永远收不到修复，而漏洞公开后黑客会批量扫描受影响站点；
  • 法律与道德：分发 nulled 主题本身违反 GPL 允许的再分发边界（破解授权验证通常伴随篡改），商业站点使用还有商誉风险。

记住：一个站点的全部内容、用户数据、声誉，不值那几十美元。预算紧就用官方库免费主题，质量下限有保证。

如何识别一个主题是否被篡改过（比如从二手渠道拿到的包）：

  1. 对照官方渠道下载的同版本包，用 diff -r 比较目录差异；
  2. 警惕文件中出现 base64_decode、gzinflate、str_rot13、eval、assert 配合长串乱码——这是混淆后门的典型面孔；
  3. 检查每个 PHP 文件开头有没有多出来的「赠品」文件（如 class.theme-modules.php 这类不在官方包里的文件）；
  4. 拿不准就不要用——这个判断成本远低于事后清马。

⚠️ 顺带一提：GPL 许可本身允许合法再分发主题的 PHP 代码，所以「GPL 俱乐部」站点以极低会费提供原版主题文件处于法律灰色但非恶意地带。它们与 nulled 站的区别在于：GPL 俱乐部不改代码、只去授权回调；nulled 站经常「顺手」加料。即便如此，俱乐部渠道拿不到官方更新与支持，本教程依然不建议生产站使用。

11.6.2 「换主题丢内容」：功能型主题的原罪 ​

典型事故场景：某用户用了内置「作品展示（Portfolio）」功能的主题，发布了 50 个作品；后来换主题，后台「作品」菜单消失、前台作品页 404——用户以为内容丢了。

真相：数据还在数据库里（自定义文章类型的记录不会因换主题被删），丢的是「管理入口和展示模板」——因为文章类型是主题注册的，主题停用，注册代码就没了。

教训与对策：

  1. 买主题前用 11.4.2 清单第 6 项排查：功能列表里出现自定义文章类型、表单、SEO 等，亮红灯；
  2. 已经中招的：把注册文章类型的代码从旧主题里剥出来做成「功能性插件」（或装 CPT UI 类插件重新注册同名类型），数据即刻复活；
  3. 从源头避免：内容结构永远交给插件——本教程配套示例中，「课程」文章类型由插件注册，经典主题 wp-academy 只负责给它提供 archive-course.php、single-course.php 等展示模板（见第 09 章）。

「中招后数据复活」的完整操作顺序：

  1. 先在旧主题的 functions.php 或 inc/ 目录里找到 register_post_type() / register_taxonomy() 调用，记下注册的类型名（slug）；
  2. 装 CPT UI 插件，用完全相同的 slug 注册同名类型（slug 错一个字母都匹配不上已有数据）；
  3. 后台左侧重新出现对应菜单，旧记录全部可见；
  4. 前台展示交给新主题：在新主题（或其子主题）里按模板层级补 archive-{slug}.php、single-{slug}.php；
  5. 长期方案：把这段注册代码做成一个自己的功能插件（模块四会教），从此换主题与内容结构彻底解耦。

同样的逻辑也适用于短代码：旧主题提供的 [button]、[pricing_table] 在换主题后会以纯文本形式残留在文章里。解救办法同样是把短代码注册代码挪进插件；预防办法是选主题时避开「短代码大礼包」。

11.6.3 「主题越多越好」：装满 30 个主题慢慢挑 ​

不用的主题请删掉，理由：

  • 不启用的主题代码仍在磁盘上，其中若有漏洞文件，照样可能被直接请求利用（历史上多个重大漏洞存在于未启用主题中）；
  • 每个已安装主题都会收到更新提示，徒增维护噪音——更新提示多了还会催生「提示疲劳」，真正重要的更新反而被忽略；
  • 备份体积随主题数量膨胀，每次备份/迁移都在为「永远不会再启用的主题」付出时间与存储成本。

保留规则：当前主题 + 它的父主题（若是子主题，见第 15 章）+ 一个 Twenty 系列兜底，其余删除。删除的点击级步骤见第 12 章 12.5 节。

11.6.4 中文站选主题的两个细节 ​

  • translation-ready 标签：确认主题所有前台文案可翻译，否则「Read More」「Search」之类字样得改代码才能中文化；技术上对应代码里使用 __()、_e()、esc_html__() 等国际化函数且加载了文本域——WordPress 会自动去 wordpress.org 的语言包仓库拉取中文翻译，若主题文本域与翻译文件匹配，连手工翻译都不用做；
  • 中文字体回退：主题若硬编码了西文字体栈且不含中文字体，中文会回退到系统默认字体，观感不一。检查方法：把演示站文案换成中文看效果；或读主题 CSS 的 font-family。配套区块主题的 theme.json（wp-academy-block/theme.json）演示了正确做法——字体栈里包含 'PingFang SC'、'Microsoft YaHei' 等中文系统字体。

还有第三个隐性细节：标点与行长。中文排版讲究标点避头尾、行高略大于西文（建议 line-height 不低于 1.7），西文主题默认 line-height: 1.5 配中文会显挤。验收方法同样简单：贴一段 300 字的中文长文进演示站，肉眼感受是否「透不过气」。需要微调时，改法取决于主题代际——经典主题用「额外 CSS」（第 13 章 13.2.7 节），区块主题直接在站点编辑器 Styles 面板调行高（第 13 章 13.3.3 节）。

动手练习 ​

练-11-01（操作题）｜换主题验证内容/表现分离

按 11.1.3 的步骤，在本地练习站上完成一次主题切换与切回。切换前后各截一张同一篇文章的前台截图，回答：① 内容有没有变化？② 哪些东西变化了（至少列 3 项）？③ 菜单是否还在原位置，为什么？

练-11-02（分析题）｜给 3 个主题打代际标签

在官方主题库任选 3 个主题（其中至少 1 个 Twenty 系列），通过 11.2.3 的方法（看外观菜单或下载后看目录结构）判断各属经典主题还是区块主题，并各用一句话说明判断依据。

练-11-03（操作题）｜特征过滤实战

使用官方主题库特征过滤，设定条件：education（教育）+ translation-ready + 一栏布局，把结果按「最近更新」排序。记录前 5 名的名称、活跃安装量、最近更新日期，并按 11.3.2 的健康线标准判断各自是否合格。

练-11-04（调研题）｜商业主题体检报告

从 ThemeForest 或任一独立商店选一个评分不错的商业主题，按 11.4.2 的 8 项清单逐项查证并打分（合格/不合格/查不到），最后给出「买/不买」结论与理由，写成一页体检报告。

练-11-05（思考题）｜功能该放哪

你的客户要在官网上加「讲师」板块：讲师有姓名、简介、照片、所授课程列表，前台要有讲师归档页和详情页。请回答：① 「讲师」这个内容结构应该由主题还是插件提供？为什么？② 如果做成主题功能，两年后客户想换主题会发生什么？③ 画出你建议的主题/插件分工方案。
