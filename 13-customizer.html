第 13 章 自定义器与站点编辑器 ​

🟡 进阶难度 ｜ 一句话导览：经典主题靠「自定义器」调外观，区块主题靠「站点编辑器」改全站。两套体系互不相通，本章逐项拆解经典自定义器的每个面板，解释实时预览的 postMessage/refresh 原理，再带你进入区块主题的站点编辑器看全局样式与 theme.json 的关系，最后讲清两体系并存期如何判断自己该用哪个入口。

学习目标 ​

  • 能在经典主题的自定义器里完成 logo、站点图标、颜色、菜单、小工具、首页设置等操作
  • 理解自定义器实时预览的 postMessage vs refresh 技术区别，知道哪些改动「即时」、哪些要刷新
  • 能在区块主题的站点编辑器里编辑模板、模板部件、导航块，理解 Styles 面板如何映射到 theme.json
  • 会判断当前主题属于哪代体系，知道各自的外观编辑入口在哪
  • 能完整阅读并解释 theme.json 的调色板、字体、间距、布局配置（以 wp-academy-block/theme.json 为例）
  • 遇到自定义器选项缺失、额外 CSS 覆盖无效、站点编辑器改坏样式时，知道排查方向

13.1 经典主题：自定义器逐项拆解 ​

13.1.1 原理说明 ​

自定义器（Customizer） 是 WordPress 为经典主题提供的实时外观调参面板。它的核心架构是三栏：左侧设置面板、中间实时预览窗口、顶部「保存并发布」按钮。所有改动在点「保存」之前只存在于预览沙箱，不会写入数据库；点保存后，配置写入 wp_options 表（以 theme_mod_主题名 为前缀的序列化数据）。

自定义器的底层通信有两种模式——13.1.8 会展开讲——现在只需知道：改颜色、改文字这类视觉参数可以即时看到，改菜单结构、改首页设置需要刷新预览页。

13.1.2 站点身份：Logo、标题、副标题与站点图标 ​

操作方法 ​

  1. 后台 外观 → 自定义（或直接前台点击顶部管理栏的「自定义」链接）；
  2. 左侧面板找到 「站点身份」 并展开；
  3. 站点标题：改文字，实时在预览窗口顶部看到变化；
  4. 站点副标题（Tagline）：输入站点描述，通常显示在标题下方或页脚；
  5. 站点图标（Site Icon）：即浏览器标签页上的 Favicon。点击「选择图片」，上传一张 正方形、至少 512×512 像素 的图片——WordPress 会自动裁切成 16×16、32×32、180×180（Apple Touch Icon）等尺寸。注意：
    • 512px 是 WordPress 官方的推荐最小尺寸，小了在高分辨率设备上会糊；
    • 建议用 PNG 格式，支持透明背景；
    • 不要在图标里塞满文字——16px 下根本看不清；
  6. 站点 Logo：点击「选择 Logo」，上传图片。主题通常提供「logo 宽度」滑块，调整预览中 logo 的显示大小；
  7. 确认满意后，点击左上角 「保存并发布」。

图 13-1：自定义器「站点身份」面板，从上到下依次为站点标题、副标题、logo 与站点图标上传控件

💡 有些主题把「站点身份」拆成多个面板，或把 logo 控制放在「页头选项」里——自定义器的面板结构完全由主题注册决定，不同主题看到的选项不同是正常的。

代码层面对应 ​

自定义器里的设置最终会落到主题模板函数调用中。以 logo 为例：

php
<?php
// 经典主题模板中输出站点 logo 的标准写法
if ( has_custom_logo() ) {
	the_custom_logo();
} else {
	printf(
		'<a href="%s" rel="home">%s</a>',
		esc_url( home_url( '/' ) ),
		esc_html( get_bloginfo( 'name' ) )
	);
}
?>

这就是「自定义器输入 → 数据库存储 → 模板读取 → 前台输出」的完整链路。

13.1.3 颜色 ​

操作方法 ​

  1. 自定义器左侧面板找到 「颜色」；
  2. 常见选项（取决于主题）：
    • 主题主色：影响链接、按钮、高亮背景；
    • 背景色：站点整体背景；
    • 页头背景 / 页脚背景：分区背景色；
    • 文字色：正文默认颜色；
  3. 点击色块弹出取色器，或直接输入十六进制色值（如 #2563eb）；
  4. 预览窗口实时刷新颜色变化；
  5. 保存并发布。

⚠️ 颜色面板的选项完全由主题注册。有些主题只给一个「主色」滑块，有些给 10 个分区色板。如果主题没有注册颜色控制，自定义器里就看不到「颜色」面板——此时只能通过「额外 CSS」或子主题改色。

13.1.4 菜单创建与分配 ​

操作方法 ​

  1. 自定义器左侧面板找到 「菜单」；
  2. 点击 「创建新菜单」 → 输入菜单名称（如「主导航」）；
  3. 勾选菜单要显示的位置（如「Primary Menu」「页脚菜单」——位置名称由主题注册，不同主题叫法不同）；
  4. 点击 「添加项目」 → 在弹出的面板中选择：
    • 页面：勾选已有页面；
    • 文章：勾选单篇文章；
    • 自定义链接：输入外部 URL 与链接文本；
    • 分类：勾选分类归档页；
  5. 拖拽调整顺序，向右拖拽可创建子菜单（二级导航）；
  6. 点击任一菜单项的展开箭头，可修改导航标签（显示文字）与标题属性（鼠标悬停提示）；
  7. 保存并发布。

图 13-2：自定义器菜单面板，左侧为菜单位置选择，中间为菜单项列表，支持拖拽排序与层级缩进

💡 自定义器里的菜单编辑与 外观 → 菜单（独立菜单管理页）是同一套数据，只是入口不同。独立页面更适合大规模调整（批量添加、快速搜索），自定义器更适合边调边看位置效果。

13.1.5 小工具 ​

操作方法 ​

  1. 自定义器左侧面板找到 「小工具」；
  2. 展开后看到主题注册的小工具区域（如「侧边栏」「页脚栏 1」「页脚栏 2」）；
  3. 点击某一区域 → 点击 「添加小工具」 → 从列表中选择（搜索、最新文章、日历、自定义 HTML……）；
  4. 小工具展开后填参数（如「最新文章」要显示几篇、是否显示日期）；
  5. 拖拽调整同一区域内小工具的先后顺序；
  6. 保存并发布。

小工具是经典主题特有的区块化内容区域。区块主题用「模板部件（Template Parts）」和区块（Block）替代了小工具概念，所以区块主题通常不提供小工具面板。

13.1.6 首页设置 ​

操作方法 ​

  1. 自定义器左侧面板找到 「首页设置」；
  2. 二选一：
    • 你的最新文章：首页显示博客式文章列表（按时间倒序）；
    • 一个静态页面：从下拉框选择「首页」和「文章页」；
  3. 若选静态页面，需要先去 页面 → 新建页面 创建这两个页面（通常命名为「首页」和「博客」或「新闻」）；
  4. 保存并发布。

图 13-3：自定义器「首页设置」二选一：最新文章列表 vs 指定静态页面

为什么要有这个设置 ​

WordPress 的模板层级中，front-page.php > home.php > index.php。当选择「最新文章」时，首页走 home.php（或回退到 index.php）；当选择「静态页面」时，首页走 front-page.php（或 page.php）。很多商业主题会在 front-page.php 里放复杂的模块布局，所以「首页设置」直接决定了访客看到的模板和排版。

13.1.7 额外 CSS（Additional CSS） ​

操作方法 ​

  1. 自定义器左侧面板找到 「额外 CSS」；
  2. 在代码框里直接写 CSS，预览窗口实时应用（无需刷新）；
  3. 代码高亮和基础语法提示由 CodeMirror 编辑器提供；
  4. 保存并发布后，CSS 写入数据库，随该主题一起生效（换主题后这段 CSS 会保留在旧主题配置中，新主题不继承）。

定位与局限 ​

额外 CSS 的定位是「快速补丁」——修个小对齐、改个颜色、藏个元素。但它有几个结构性局限：

局限说明
作用域 = 当前主题换主题后这段 CSS 不自动迁移（存在旧主题的 theme_mod 里）
无文件系统持久化数据库损坏或迁移失误时可能丢失；不适合写大量规则
无预处理器不能写 Sass/Less，不能引用外部文件
调试困难没有 Source Map，DevTools 里看到的是内联样式，定位原始行号不便
缓存友好性差若额外 CSS 量大，每页请求都多一次数据库查询（小量可忽略）

💡 因此：少量补丁（< 50 行）走额外 CSS 没问题；大量定制、跨主题复用、或需要版本控制时，请用子主题的 style.css（见第 15 章）。

13.1.8 自定义器实时预览原理：postMessage vs refresh ​

原理说明 ​

自定义器预览窗口是内嵌的 <iframe>，左侧面板与 iframe 之间通过 wp.customize JavaScript API 通信。通信分两种传输策略：

  • postMessage（即时传输）：左侧面板改动通过 window.postMessage 直接推给 iframe 里的 JS，iframe 局部重绘 DOM，无需整页刷新。颜色、文字、logo 尺寸等纯视觉参数通常走这条通道——你滑动滑块，预览窗口毫秒级响应。
  • refresh（整页刷新）：左侧面板改动发送 AJAX 请求到服务器，PHP 重新渲染整个预览页，iframe 完整 reload。菜单结构、首页设置、小工具增删等涉及模板层级或数据库查询改动的操作，通常走这条通道——你会看到预览窗口闪过 loading。

主题开发者在注册自定义器设置时通过 'transport' => 'postMessage' 或 'transport' => 'refresh' 声明策略。作为使用者，你不需要写代码，但了解这个区别有助于理解「为什么改颜色即时生效、改菜单要等刷新」。

mermaid
flowchart LR
    A[左侧面板改动] --> B{transport 策略}
    B -->|postMessage| C[JS 直接推给 iframe<br/>局部 DOM 更新]
    B -->|refresh| D[AJAX 请求服务器<br/>PHP 重渲染整页]
    C --> E[预览即时更新]
    D --> E

💡 若发现某个主题的颜色控件明明是视觉参数却走了 refresh（每次改色都闪一下整页），说明主题作者没写对应的 postMessage JS 回调——这是主题代码质量的一个观察点。

13.2 区块主题：站点编辑器（Site Editor） ​

13.2.1 原理说明 ​

区块主题取消了自定义器（或把它压缩到只剩少数选项），把全站外观编辑统一进 站点编辑器（Site Editor）。进入路径是 外观 → 编辑器。它的核心工作区与文章区块编辑器一致——所见即所得的区块画布——但编辑范围扩展到整站：

  • 模板（Templates）：首页、文章页、页面、归档、404、搜索页……
  • 模板部件（Template Parts）：页头（Header）、页脚（Footer）、侧边栏……可跨模板复用；
  • 样式（Styles）：全局调色板、字体、间距、按钮圆角……对应 theme.json 的 settings 和 styles；
  • 导航（Navigation）：用「导航块」编辑全站菜单，替代了经典主题的「外观 → 菜单」。

13.2.2 操作方法：进入站点编辑器 ​

  1. 确认当前主题为区块主题（判断方法见第 11 章 11.2.3 节）；
  2. 后台 外观 → 编辑器；
  3. 首次进入看到的是当前前台首页的可视化编辑界面——顶部工具栏、左侧导航抽屉、中间画布；
  4. 点击左上角 WordPress 图标（或「返回」按钮）展开导航抽屉，切换到不同区域：
    • 设计 → 模板：管理所有页面模板；
    • 设计 → 模板部件：管理 Header/Footer 等可复用部件；
    • 设计 → 样式：全局样式面板；
    • 设计 → 导航：管理导航菜单块；
    • 设计 → 页面：快速编辑各个页面内容（与「页面」菜单互通）。

图 13-4：区块主题站点编辑器，左侧为导航抽屉，中间为首页画布，右侧为当前选中区块的属性面板

13.2.3 模板与模板部件编辑 ​

操作方法：编辑首页模板 ​

  1. 站点编辑器中，导航抽屉 → 设计 → 模板；
  2. 找到 首页（Home） 或 索引（Index），点击打开；
  3. 画布上显示当前首页的区块结构（如 Query Loop 文章列表、Featured Image 特色图块、Post Title 标题块……）；
  4. 点击任意区块，右侧属性面板出现该区块的专属选项（对齐、间距、颜色、字体大小……）；
  5. 增删区块与文章编辑器完全一致（见第 07 章）；
  6. 修改完成后点击右上角 「保存」 → 弹出保存确认弹窗，勾选要保存的项（模板本身、模板部件、导航块……）→ 确认保存。

⚠️ 保存模板会直接改变全站所有使用该模板的页面——不像文章编辑器只改一篇文章。操作前确认自己在改的是「模板」不是「某个页面的内容」。

操作方法：编辑页头部件 ​

  1. 导航抽屉 → 设计 → 模板部件；
  2. 点击 页头（Header）；
  3. 画布显示页头的区块结构（通常含 Site Logo 块、Site Title 块、Navigation 块）；
  4. 修改导航块：点击 Navigation 块 → 右侧属性面板显示菜单结构，可增删菜单项、调整下拉层级；
  5. 保存后，所有引用该页头部件的模板同步生效。

图 13-5：站点编辑器中选中导航块后的属性面板，显示菜单层级结构与样式选项

13.2.4 Styles 面板：全局样式 ​

操作方法 ​

  1. 站点编辑器画布顶部工具栏，点击 「样式」 图标（画笔形状），或导航抽屉 → 设计 → 样式；
  2. 右侧面板出现全局样式控制：
    • 排版（Typography）：站点默认字体、字体大小、行高、字重；
    • 颜色（Colors）：文字色、背景色、链接色、按钮色——以及 theme.json 中定义的调色板（Palette）；
    • 布局（Layout）：内容宽度（contentSize）、宽对齐宽度（wideSize）、页面边距；
    • 间距（Spacing）：区块间隙（Block Gap）、默认内边距；
    • 边框（Border）：默认边框样式；
  3. 在调色板里点选颜色，所有使用该预设色的区块同步变色；
  4. 点击面板顶部的 「样式手册（Style Book）」 可预览所有核心区块在该主题下的默认样式。

与 theme.json 的关系 ​

站点编辑器里改的每一项，最终都写入数据库的用户配置层；而 theme.json 是主题作者提供的默认配置层。两者的关系是：

  • theme.json 定义了「出厂默认值」和「可选范围」（比如调色板只给 4 个色，用户就只能在这 4 个里选）；
  • 用户在 Styles 面板里的改动，覆盖 theme.json 的对应值，保存在数据库中；
  • 主题更新时 theme.json 可能被覆盖，但用户的 Styles 配置保留在数据库里，不会被主题更新冲掉。

这就形成了「主题作者定框架，用户填内容」的双层模型。

13.3 完整阅读 theme.json：以 wp-academy-block 为例 ​

13.3.1 原理说明 ​

theme.json 是区块主题的「中央配置文件」，用 JSON 语法声明全局样式和编辑器能力。WordPress 读取它后，会自动生成 CSS 自定义属性（CSS Custom Properties）并注入到前台和编辑器中，确保「后台看到什么，前台就输出什么」。

配套示例 wp-academy-block/theme.json 是一份教学级配置文件，下面逐段拆解。

13.3.2 逐段讲解 ​

版本声明与布局 ​

json
{
	"$schema": "https://schemas.wp.org/trunk/theme.json",
	"version": 3,
	"useRootPaddingAwareAlignments": true,
	"settings": {
		"appearanceTools": true,
		"layout": {
			"contentSize": "720px",
			"wideSize": "1200px"
		}
	}
}
  • $schema：IDE 和编辑器用它做语法校验与自动补全；
  • version: 3 → 对应 WordPress 6.5+ 的 theme.json 版本；
  • useRootPaddingAwareAlignments: true → 让「全宽（alignfull）」区块正确计算宽度，避免被根节点 padding 撑出横向滚动条；
  • appearanceTools: true → 一键开启所有外观工具（边框、阴影、间距滑块等），不用逐个字段声明；
  • layout.contentSize / wideSize → 定义内容区默认宽度和「宽对齐」宽度，对应经典主题容器里的 .entry-content 最大宽度。

调色板与渐变 ​

json
"color": {
	"defaultPalette": false,
	"defaultGradients": false,
	"palette": [
		{ "slug": "primary",   "color": "#2563eb", "name": "主色" },
		{ "slug": "secondary", "color": "#0d9488", "name": "辅助色" },
		{ "slug": "dark",      "color": "#1f2937", "name": "深色" },
		{ "slug": "light",     "color": "#f8fafc", "name": "浅色" }
	],
	"gradients": [
		{
			"slug": "primary-diagonal",
			"name": "主色对角渐变",
			"gradient": "linear-gradient(135deg, #2563eb 0%, #0d9488 100%)"
		}
	]
}
  • defaultPalette: false → 禁用 WordPress 默认的 11 色系统调色板，只保留主题自定义色，避免用户在编辑器里看到一堆不搭的默认色；
  • slug → 颜色的机器名，在 CSS 中引用为 var(--wp--preset--color--primary)；
  • name → 编辑器调色板面板中显示的中文名；
  • gradients → 定义渐变预设，用户可在区块背景里直接选用。

字体与字号 ​

json
"typography": {
	"fluid": true,
	"fontFamilies": [
		{
			"slug": "system",
			"name": "系统无衬线",
			"fontFamily": "-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', 'Helvetica Neue', Arial, sans-serif"
		},
		{
			"slug": "serif",
			"name": "系统衬线",
			"fontFamily": "Georgia, 'Times New Roman', 'Songti SC', 'SimSun', serif"
		}
	],
	"fontSizes": [
		{ "slug": "small",  "name": "小",   "size": "0.875rem" },
		{ "slug": "medium", "name": "中",   "size": "1.125rem" },
		{ "slug": "large",  "name": "大",   "size": "1.5rem" },
		{ "slug": "x-large","name": "特大（流式）", "size": "clamp(2rem, 5vw, 3.5rem)" }
	]
}
  • fluid: true → 开启流式排版，字号会根据视口宽度在最小值和最大值之间平滑过渡；
  • fontFamilies → 定义可用字体栈。注意这里把中文字体 'PingFang SC'、'Microsoft YaHei' 放在西文字体之后——这是 CSS font-family 的回退机制：先尝试西文系统字体，中文字符不匹配时自然落到后面的中文字体；
  • fontSizes → 预设字号，其中 x-large 使用 CSS clamp() 实现流式响应，这是现代排版优于固定像素的做法（第 14 章会进一步讲响应式原理）。

间距系统 ​

json
"spacing": {
	"units": [ "px", "rem", "em", "%" ],
	"padding": true,
	"margin": true,
	"blockGap": true
}
  • units → 用户在编辑器间距控件里可使用的单位；
  • padding / margin / blockGap → 开启对应间距工具。blockGap 是区块主题的核心概念，控制相邻区块之间的默认间隙。

全局样式（styles） ​

json
"styles": {
	"color": {
		"background": "var(--wp--preset--color--light)",
		"text": "var(--wp--preset--color--dark)"
	},
	"typography": {
		"fontFamily": "var(--wp--preset--font-family--system)",
		"fontSize": "1.125rem",
		"lineHeight": "1.7"
	},
	"spacing": {
		"blockGap": "1.5rem",
		"padding": { "top": "0", "right": "1.5rem", "bottom": "0", "left": "1.5rem" }
	},
	"elements": {
		"heading": { "typography": { "fontFamily": "var(--wp--preset--font-family--serif)", "fontWeight": "700", "lineHeight": "1.3" } },
		"link": { "color": { "text": "var(--wp--preset--color--primary)" }, ":hover": { "color": { "text": "var(--wp--preset--color--secondary)" } } },
		"button": { "color": { "background": "var(--wp--preset--color--primary)", "text": "var(--wp--preset--color--light)" }, "border": { "radius": "0.5rem" }, ":hover": { "color": { "background": "var(--wp--preset--color--secondary)" } } }
	},
	"blocks": {
		"core/site-title": { "typography": { "fontSize": "1.5rem", "fontWeight": "700" } },
		"core/post-title": { "typography": { "fontSize": "clamp(1.75rem, 4vw, 2.5rem)", "lineHeight": "1.3" } }
	}
}

这段是 theme.json 的「样式层」：

  • 根级 color / typography / spacing → 站点全局默认值；
  • elements → 按 HTML 元素统一设置（所有 <h1>–<h6>、所有 <a>、所有 <button>）；
  • :hover → 伪状态样式，按钮和链接的悬停色都在这里定义；
  • blocks → 按区块类型覆盖（core/site-title 是站点标题块，core/post-title 是文章标题块），优先级高于元素级和根级。

优先级规则（从高到低）：区块级样式 > 元素级样式 > 根级全局样式。这个层叠模型让主题作者既能全局统一，又能对特定区块做精细调整。

模板部件注册 ​

json
"templateParts": [
	{ "name": "header", "title": "页头", "area": "header" },
	{ "name": "footer", "title": "页脚", "area": "footer" }
]

告诉 WordPress：parts/header.html 和 parts/footer.html 是模板部件，分别对应「页头」和「页脚」区域。站点编辑器里会在模板部件管理页正确显示它们。

13.3.3 在 Styles 面板中验证配置 ​

打开 wp-academy-block 主题的站点编辑器 → 样式面板，逐项对照 theme.json：

  • 颜色面板 → 应该只看到 4 个预设色 + 1 个渐变，没有默认 11 色；
  • 字体面板 → 下拉选项为「系统无衬线」和「系统衬线」；
  • 字号面板 → 小/中/大/特大四档，特大显示为流式（随面板宽度变化）；
  • 按钮默认样式 → 圆角、主色背景、悬停变辅助色——全部来自 theme.json 的 elements.button。

如果面板里的选项和 theme.json 对不上，常见原因是浏览器缓存了旧版 CSS 或 theme.json 有语法错误导致解析失败。刷新页面、或把 theme.json 贴到 JSON 校验工具排查。

13.4 两体系并存期的判断与选择 ​

13.4.1 判断方法：我该用自定义器还是站点编辑器？ ​

看后台 「外观」 菜单， unmistakable：

外观菜单内容你的主题代际外观编辑入口
自定义、小工具、菜单、主题文件编辑器……经典主题外观 → 自定义
编辑器（Site Editor）为首，无「自定义」区块主题外观 → 编辑器
两者都有混合型主题优先用主题推荐的入口，或按需求选（改全站结构用编辑器，改 logo/颜色用自定义器）

图 13-6：经典主题（左）与区块主题（右）的外观菜单差异

13.4.2 用户常见困惑 ​

  • 「我按教程找不到自定义器」：因为你用的是区块主题，教程截图是经典主题。先判断代际，再找对应入口；
  • 「区块主题能不能用小工具」：默认没有小工具面板，但可以通过插件或 functions.php 强制开启。更推荐的做法是学会用「模板部件 + 区块」替代小工具；
  • 「经典主题能不能用站点编辑器」：不能。站点编辑器是区块主题的专属能力，经典主题没有 theme.json 和 HTML 模板，编辑器无法工作；
  • 「额外 CSS 在区块主题里去哪了」：区块主题通常把额外 CSS 放在站点编辑器 → 样式 → 额外 CSS 面板里，或干脆不提供（鼓励你改 theme.json 或模板）。

13.5 常见问题 ​

13.5.1 自定义器选项因主题而异 ​

同一个 WordPress 安装，换了主题后自定义器里某些面板消失了——这不是 bug，是主题主动选择暴露哪些选项。主题通过 add_theme_support() 和 add_setting() 注册自定义器控件：

  • add_theme_support( 'custom-logo' ) → 出现「站点身份」里的 logo 上传；
  • add_theme_support( 'customize-selective-refresh-widgets' ) → 小工具支持即时预览；
  • 没注册颜色控制 → 自定义器里没有「颜色」面板。

所以：找不到某个设置时，先确认该主题是否支持这个功能；不支持的话，走「额外 CSS」或子主题。

13.5.2 额外 CSS 与子主题 style.css 的选择 ​

场景推荐方案理由
改 3 行颜色/隐藏一个元素额外 CSS快、不增加文件、不部署
改 50 行以上、涉及多个选择器子主题 style.css可版本控制、跨主题复用、可写注释
需要写媒体查询做响应式子主题 style.css额外 CSS 框太小，写多行体验差
需要引入外部字体文件子主题 + wp_enqueue_style()额外 CSS 不能引用外部资源
团队多人协作子主题 + Git数据库里的额外 CSS 无法 diff/回滚

13.5.3 站点编辑器改坏了如何恢复 ​

修订记录 ​

站点编辑器支持模板修订。点击编辑器顶部工具栏的「撤销」箭头，或进入 设计 → 模板 → 选择模板 → 查看修订（部分版本在保存按钮旁显示「修订」入口），可以看到该模板的历史版本列表，选择旧版恢复即可。

清除用户自定义 ​

如果样式面板里调得太乱，想一键回到主题默认：

  1. 站点编辑器 → 样式面板 → 点击右上角三个点菜单 → 「重置为默认值」；
  2. 这会清除数据库里该主题的所有用户 Styles 配置，回到 theme.json 的出厂设置；
  3. 只清样式，不清内容（文章、页面、菜单都在）。

导出/导入配置 ​

站点编辑器支持把当前 Styles 配置导出为 JSON 文件（样式面板 → 三个点 → 导出），可在另一个同主题站点上导入复现。这是跨环境同步样式的快捷方式。

13.5.4 自定义器保存后前台不生效 ​

排查顺序：

  1. 缓存插件：WP Rocket、W3 Total Cache、LiteSpeed Cache 等页面缓存会拦截前台请求，导致你看到的是旧版缓存。清空缓存或临时禁用缓存插件；
  2. CDN 缓存：如果用了 Cloudflare 等 CDN，可能需要清除 CDN 边缘缓存；
  3. 浏览器缓存：按 Ctrl/Cmd + Shift + R 强制刷新（不走缓存）；
  4. 未真正保存：自定义器左上角显示「已保存」才生效，只改数值不点保存不会写入；
  5. 主题 CSS 优先级更高：你写的额外 CSS 被主题本身的更具体选择器覆盖，加 !important 测试（不推荐长期用），或提高选择器特异性。

13.5.5 区块主题里「找不到菜单编辑」 ​

区块主题的菜单不是「外观 → 菜单」，而是：

  1. 站点编辑器 → 打开任意含导航的模板（如首页）→ 点击 Navigation 块；
  2. 或导航抽屉 → 设计 → 导航 → 直接管理所有导航菜单；
  3. 导航块支持「新建菜单」「从现有菜单导入」「手动添加链接」三种方式。

如果旧站从经典主题迁移到区块主题，之前创建的菜单会出现在「从现有菜单导入」列表里，一键转为导航块即可复用。

本章总结 ​

体系入口核心能力配置存储适用主题
自定义器外观 → 自定义Logo、颜色、菜单、小工具、首页设置、额外 CSSwp_options（theme_mod）经典主题
站点编辑器外观 → 编辑器模板、模板部件、全局样式、导航块、页面布局wp_posts + wp_options（用户样式层）区块主题
theme.json文件系统调色板、字体、间距、布局、元素默认样式、区块样式主题目录（默认层）+ 数据库（用户覆盖层）区块主题

关键记忆点：

  • 自定义器的改动只影响当前主题，换主题后需重配；
  • 站点编辑器的 Styles 改动存在数据库，主题更新不丢失；
  • theme.json 是主题作者的「出厂设置」，用户 Styles 是「覆盖层」，两者叠加；
  • 额外 CSS 适合补丁，子主题适合系统定制；
  • 改坏样式时：自定义器没有内置回滚，靠截图/备份；站点编辑器有修订记录和「重置为默认值」。

动手练习 ​

练-13-01（操作题）｜经典主题自定义器全流程

在启用经典主题（如 wp-academy）的练习站上，完成以下操作并截图：① 上传 logo 与 512px 站点图标；② 修改站点主色；③ 新建一个含子层级的菜单并分配到主导航位置；④ 在侧边栏添加「最新文章」和「自定义 HTML」两个小工具；⑤ 设置静态首页；⑥ 在额外 CSS 里写一条把正文 line-height 改为 1.8 的规则。每步保存后刷新前台确认效果。

练-13-02（操作题）｜区块主题站点编辑器探索

切换到区块主题（如 Twenty Twenty-Five 或 wp-academy-block），完成：① 进入站点编辑器，浏览模板列表与模板部件列表；② 修改页头导航块，添加一个外部链接；③ 在 Styles 面板中把全局链接色改为 #d946ef；④ 打开「样式手册」预览所有核心区块样式；⑤ 查看模板修订历史（若有），尝试回退到上一版。记录哪项改动即时生效、哪项需要保存后才可见。

练-13-03（分析题）｜逐行解释 theme.json

打开 wp-academy-block/theme.json，对其中每一层 JSON 键值写出中文解释：version、settings.color.palette、settings.typography.fontFamilies、styles.color.background、styles.elements.button、styles.blocks 等。用表格形式提交：键路径 | 值示例 | 作用说明 | 在编辑器哪里可见。

练-13-04（故障题）｜排查「改色不生效」

在经典主题自定义器中修改链接颜色后，前台链接色不变。按 13.5.4 的五步排查法独立定位原因，并写出你的排查日志（每一步做了什么、观察到什么、排除了什么假设）。

练-13-05（思考题）｜两代体系的选择决策

你的客户要求：① 站点上线后运营团队能自行改首页 banner 图和文案；② 偶尔需要调整全站主色；③ 未来可能做 A/B 测试（同一页面两种布局）。请回答：你会推荐经典主题 + 页面构建器、还是区块主题？理由是什么？如果客户已经买了经典商业主题，如何在不重写主题的前提下满足需求 ①？
