第 8 章 媒体库高级管理 🟢 ​

一句话导览：图片、视频、PDF 在 WordPress 里究竟是怎么存放的？本章从「附件也是一种 post」讲起，带你掌握上传规范、四字段、多尺寸、响应式图片、图片优化与上传排障。

纯文字的网站在 2026 年已经无法想象。媒体管理看似只是「上传图片」，但替代文本怎么写、图片为什么自动生成了五个尺寸、为什么大图上传报 HTTP error、附件页面有没有 SEO 风险——这些问题的答案都藏在 WordPress 的媒体机制里。本章把媒体库从「图床」提升为「资产库」来管理。

学习目标 ​

  • 理解附件（attachment）在数据库与文件系统中的存储模型，说清「记录」与「文件」的区别。
  • 掌握 WordPress 支持与默认禁止的文件类型及其安全原因，会用三种入口上传。
  • 彻底分清标题、替代文本、图片标题、描述四个字段，并正确设置对齐、链接目标与尺寸。
  • 理解缩略图多尺寸与 srcset 响应式图片原理，会用 add_image_size() 注册自定义尺寸。
  • 建立图片优化工作流：命名、压缩、WebP/AVIF、附件页 SEO、媒体库定期整理。

8.1 媒体在 WordPress 中的本质 ​

原理说明 ​

延续第 6 章的统一内容模型：你上传的每个文件，在数据库里也是一条记录——wp_posts 表中一行 post_type = 'attachment' 的数据，状态为 inherit（跟随它所属的文章/页面）。

  • 文件本身存储在服务器磁盘：wp-content/uploads/2026/10/team-photo.jpg，默认按「年/月」分目录（可在「设置 → 媒体」关闭年月分目录）。
  • 数据库记录存储在两张表：
    • wp_posts：附件标题、上传者、上传时间、描述、MIME 类型、post_parent（从哪篇文章上传的）。
    • wp_postmeta：替代文本、各尺寸文件路径、图片宽高、EXIF 等扩展信息。
  • 数据库里没有图片二进制内容，只有指向文件的引用。这解释了两个现象：直接用 FTP 删掉文件，后台附件记录还在（变成坏图）；直接用 FTP 上传文件到 uploads/，后台媒体库却看不到（没有数据库记录）。

常见问题 ​

  • 问：uploads 目录为什么按年月分？ 答：避免单目录文件过多导致文件系统与备份工具性能下降；多年站点会有上百个 GB 文件，分月目录便于归档与迁移。

8.2 支持的文件格式 ​

原理说明 ​

WordPress 维护一份允许上传的 MIME 类型白名单（由 wp_get_mimes() 提供），不在白名单内的文件会被拒绝。常见格式：

类别默认可上传说明
图片JPG/JPEG、PNG、GIF、WebPWebP 自 WordPress 5.8 起原生支持上传与编辑
图片AVIF自 WordPress 6.5 起支持，要求服务器的 GD 或 Imagick 扩展编译了 AVIF 支持
图片SVG默认禁止。SVG 是 XML 文档，可内嵌 JavaScript，被用于跨站脚本攻击（XSS）；开放需配合净化插件并限制仅管理员上传
文档PDF、DOCX、XLSX、PPTX、TXT、MD、ZIPPDF 最常用，可在「文件」区块中直接下载
音频MP3、WAV、OGG、M4A由前台原生播放器播放
视频MP4、M4V、WEBM、OGV、MOV建议短视频，长视频走视频平台（见 8.11 节）

两个与上传类型相关的配置（写在 wp-config.php）：

php
// 允许「拥有 unfiltered_upload 权限的用户」（默认仅超级管理员）上传任意类型文件。
// 仅限内网/受信站点，普通站点不要开启，风险自负。
define( 'ALLOW_UNFILTERED_UPLOADS', true );

多站点网络的超级管理员还可以在「网络管理 → 设置 → 上传设置」中追加允许的扩展名。安全角度的文件上传校验在第 32 章深入。

操作方法：查看本站点实际支持的媒体能力 ​

  1. 后台点击「工具 → 站点健康」（Tools → Site Health）。
  2. 切换到「信息」（Info）标签，找到「媒体处理」（Media Handling）折叠项。
  3. 查看正在使用的图像扩展（GD 或 Imagick）及其版本、支持的格式列表。
  4. 若上传 AVIF 被拒但站点版本为 6.5 以上，优先在此确认图像扩展是否支持 AVIF——核心版本够、扩展不支持时仍然无法处理。

常见问题 ​

  • 问：我能上传可执行文件（exe、sh）吗？ 答：默认禁止且应该禁止。需要分发软件安装包时，建议打包为 ZIP 并自行做好病毒扫描，或放在对象存储/CDN 上提供下载。
  • 问：为什么有的 GIF 在媒体库里不动？ 答：只有全尺寸原图保持动画；某些主题/插件调用缩略图尺寸时 GIF 会被取成静态首帧。需要动画请插入时选择「全尺寸」，并确认优化插件未把 GIF 转为静态格式。

8.3 上传的三种入口 ​

操作方法一：媒体 → 添加（集中入库） ​

  1. 后台点击「媒体 → 添加新文件」（Media → Add New Media File）。
  2. 把文件从文件夹直接拖入虚线框，或点击选择文件。
  3. 多文件可一次拖入批量上传，进度条逐个完成。
  4. 上传后文件已在媒体库，随时可在文章中引用。

操作方法二：在编辑器内上传/从媒体库插入 ​

  1. 在区块编辑器中插入「图片」区块，点击「上传」可直接选本地文件——上传、插入一步完成。
  2. 也可从电脑桌面直接把图片拖进画布，编辑器自动识别位置并上传。
  3. 点击「媒体库」则从已有附件中选择。

操作方法三：FTP/SFTP 上传（特殊场景） ​

  1. 用 FTP 工具把文件传到 wp-content/uploads/2026/10/。
  2. 此时文件在服务器上，但后台媒体库看不到（无数据库记录），文章里也无法通过媒体库选择。
  3. 需要安装「Add From Server」一类插件，在后台「媒体 → Add From Server」浏览目录并把文件注册入库。
  4. 风险提示：该插件会绕过常规上传校验，请仅由管理员在迁移、批量导入等必要场景使用，完成后可停用；不要开放给普通用户。

常见问题 ​

  • 问：同一文件上传两次会怎样？ 答：WordPress 自动在文件名后追加 -1、-2，得到两条独立附件记录，前台是两张独立图片。整理媒体库时记得去重（见 8.12 节）。

8.4 插入图片完整流程与四个字段 ​

原理说明：四个字段到底有什么区别 ​

点击媒体库中的图片，打开「附件详情」对话框，四个文字字段最容易混淆：

字段中文官方译名存在哪显示位置与用途
Title标题wp_posts.post_title后台媒体库列表、鼠标悬停图片时的 title 提示、附件页标题
Alt Text替代文本postmeta _wp_attachment_image_alt图片加载失败时显示；屏幕阅读器朗读；SEO 与无障碍最重要的字段
Caption图片标题/说明wp_posts.post_excerpt主题支持时显示在图片下方的图注文字
Description描述wp_posts.post_content附件页面（attachment page）上的正文，可放较长说明、版权信息

图 08-2：附件详情对话框，四个字段从上到下为标题、替代文本、图片标题、描述，右侧为图片预览

替代文本（Alt）写作原则：描述图片传达的信息，而不是描述图片本身。装饰性图片可留空；产品图写「云栖科技 2026 款企业主机正面图」而非「IMG_3829」。

图片用途❌ 不合格的 Alt✅ 合格的 Alt

纯装饰分隔花纹堆一长串关键词留空（编辑器中保留空 Alt）
含文字的活动海报海报2026 年 10 月 20 日线上建站沙龙报名海报，二维码直达报名页

操作方法：插入并设置一张图片 ​

  1. 在文章中插入「图片」区块 → 点击「媒体库」→ 选中图片。
  2. 在右侧附件详情中填写：标题「团队合影 2026」、替代文本「云栖科技创始团队在公司前台合影」、图片标题「图：2026 年创始团队」。
  3. 右下角选择「插入图片」。

图 08-3：插入媒体弹层底部的附件详情与显示设置：对齐、链接到、尺寸三个关键选项

  1. 图片插入后，在区块工具栏选择对齐：无对齐（文字不环绕）、左对齐/右对齐（文字环绕）、宽幅/全宽（需主题支持）。
  2. 在区块设置「链接到」（Link to）中选择点击行为：
链接目标效果
无（None）图片不可点击，适合正文配图
媒体文件（Media File）点击打开原图大图，适合需要看细节的图
附件页面（Attachment Page）打开附件详情页（薄内容风险，见 8.8 节）
自定义 URL（Custom URL）跳到任意链接
  1. 在「图片尺寸」中选择输出尺寸：缩略图/中等/大尺寸/全尺寸（原理见 8.5 节）。

常见问题 ​

  • 问：替代文本和图片标题都要写吗？ 答：替代文本是必写项（无障碍与图片 SEO）；图片标题按需，图注只在确实需要向读者解释图片时填写，不要机械地为每张图加图注。
  • 问：改了附件的替代文本，已插入文章的旧图会更新吗？ 答：会。替代文本等信息由前台动态读取，旧文章重新生成页面时输出新值（有缓存时清缓存）。

8.5 自动多尺寸与响应式图片 ​

原理说明 ​

上传一张 3000×2000 的 JPG 后，WordPress 会在原图之外自动生成多个缩小版。默认尺寸（「设置 → 媒体」可改）：

尺寸中文默认长边限制裁剪方式
Thumbnail缩略图150×150默认硬裁剪成正方形
Medium中等最长边 300等比缩放
Large大尺寸最长边 1024等比缩放
Full全尺寸原始尺寸不处理

于是同一张图在 uploads/2026/10/ 里会出现 team-photo.jpg、team-photo-150x150.jpg、team-photo-300x200.jpg、team-photo-1024x683.jpg 等多个文件。

主题还可以注册两类尺寸：

  • set_post_thumbnail_size()：设置特色图片（文章缩略图）的默认尺寸。
  • add_image_size()：注册任意命名尺寸，供模板按位置调用。

代码片段放入主题的 functions.php（更推荐放在子主题或配套教学主题 examples/themes/wp-academy/functions.php 中，避免升级丢失）：

php
/**
 * 注册特色图片与自定义图片尺寸。
 *
 * @package Wp_Academy
 */

/**
 * 设置特色图片默认尺寸：480×320，硬裁剪。
 */
function wp_academy_setup_post_thumbnail() {
	// 声明主题支持特色图片，并设定默认裁剪尺寸。
	add_theme_support( 'post-thumbnails' );
	set_post_thumbnail_size( 480, 320, true );

	// 文章卡片横图：640 宽，按比例缩放（false = 不裁剪）。
	add_image_size( 'wp-academy-card', 640, 0, false );

	// 首页横幅：1600×500，硬裁剪（true = 裁出精确比例）。
	add_image_size( 'wp-academy-banner', 1600, 500, true );
}
add_action( 'after_setup_theme', 'wp_academy_setup_post_thumbnail' );

模板中按名称输出时，所有动态数据必须转义后再显示：

php
// 输出指定尺寸的特色图片，尺寸名对应上面注册的 wp-academy-card。
if ( has_post_thumbnail() ) {
	the_post_thumbnail(
		'wp-academy-card',
		array(
			'alt'   => esc_attr( get_the_title() ),
			'class' => 'wp-academy-card__img',
		)
	);
}

srcset 与 sizes（响应式图片）：现代 WordPress 输出 <img> 时会自动附带 srcset（浏览器可选的多个宽度文件）与 sizes（各布局下图片显示宽度的提示）。手机浏览器会自动下载 300px 的小图，4K 显示器下载大图，无需手写任何代码。自定义尺寸也会被纳入 srcset 候选。前台输出的标签大致长这样：

html
<img
	src="https://example.com/wp-content/uploads/2026/10/team-photo-1024x683.jpg"
	srcset="
		https://example.com/.../team-photo-300x200.jpg   300w,
		https://example.com/.../team-photo-768x512.jpg   768w,
		https://example.com/.../team-photo-1024x683.jpg 1024w,
		https://example.com/.../team-photo.jpg          3000w"
	sizes="(max-width: 768px) 100vw, 640px"
	width="1024" height="683"
	alt="云栖科技创始团队在公司前台合影"
	loading="lazy" decoding="async">
  • 300w、1024w 是候选文件的真实像素宽度；sizes 告诉浏览器「窄屏占满视口、桌面端约 640px」，浏览器据此按屏幕密度与网速自己选文件。
  • loading="lazy"（懒加载）与 decoding="async" 由核心自动添加（第 30 章详解）。
  • 因为有了这套机制，正文里手动插入「全尺寸」并不等于访客一定下载原图——但选择与版面匹配的尺寸仍是最稳妥的做法。

第 30 章「图片优化策略」会深入懒加载、宽高比与现代格式。

操作方法：注册新尺寸后补齐旧图 ​

  1. 在 functions.php 加入上面的 add_image_size() 代码。
  2. 新尺寸只对之后上传的图片自动生成；老图片需要重新生成。
  3. 安装 Regenerate Thumbnails 类插件，在「工具 → 重新生成缩略图」批量重建已有附件的各尺寸文件。

常见问题 ​

  • 问：为什么不上传时就只传小图？ 答：需要保留原图供放大查看、日后改版和多尺寸生成；控制体积应通过压缩与格式（8.10 节），而不是人为传低清图。

8.6 特色图片（Featured Image） ​

特色图片（旧称「文章缩略图」）是代表整篇内容的主图，显示位置完全由主题决定：博客列表卡片、文章页头部、社交分享卡片。

操作方法 ​

  1. 文章编辑界面右侧找到「特色图片」面板（若无，从「偏好设置 → 面板」开启）。
  2. 点击「设置特色图片」，从媒体库选择或新上传一张图。
  3. 确认已填写替代文本，点击「设置特色图片」。
  4. 更新文章，前台列表/文章页（取决于主题）出现主图。
  5. 分享文章到社交平台时，主流 SEO 插件会把特色图作为分享图（Open Graph 图）输出。

8.7 媒体库视图与图片编辑 ​

8.7.1 浏览、筛选与批量管理 ​

「媒体 → 媒体库」提供两种视图：

  • 网格视图（默认）：缩略图瀑布流，悬停出现编辑/删除快捷按钮。
  • 列表视图：表格列出文件、作者、上传到、评论数，便于按作者与日期排查。

顶部可按媒体类型（图片/音频/视频/文档）、按月份筛选，也可关键词搜索（搜标题与文件名）。点击「批量选择」可勾选多个附件一次性删除。

图 08-1：媒体库网格视图，顶部为类型/日期筛选与搜索框，悬停缩略图显示编辑与删除按钮

8.7.2 内置图片编辑器：缩放、裁剪、旋转、翻转 ​

  1. 在媒体库点击图片 →「编辑图像」（Edit Image）。
  2. 工具栏按钮：裁剪（Crop）、逆时针/顺时针旋转、左右/上下翻转、撤销/重做。
  3. 缩放图像（Scale）：按比例缩小到新像素尺寸（只能缩小不能放大，避免模糊）。
  4. 裁剪：在图上拖出选区，可精确输入选区比例与宽高；右侧「缩略图设置」可选择「更改所有尺寸/仅缩略图」。
  5. 保存后系统重建缩略图；原始上传文件会被备份，点击「恢复原始图像」可一键还原。

图 08-4：图片编辑器，标注裁剪、旋转、翻转按钮与缩放尺寸输入框、缩略图应用范围选项

改的是原图还是副本？ 缩放/裁剪作用于全尺寸文件并重建派生尺寸，但 WordPress 保留原始备份（xxx-orig.jpg 一类文件），因此可恢复；选择「仅缩略图」时只替换方形缩略图，不影响正文使用的大图。

常见问题 ​

  • 问：能在媒体库里批量改替代文本吗？ 答：可逐个点开附件详情修改；批量场景用 Enable Media Replace 等替换类插件或 WP-CLI（wp media import/wp post meta update）处理。

8.8 附件页面的 SEO 利弊 ​

原理说明 ​

每张图片默认都有一个附件页面（Attachment Page），它是网站上的一个真实 URL，内容通常只有一张图加几句描述——对搜索引擎而言属于典型的薄内容（Thin Content）：几百上千个「只有一张图」的页面会稀释整站质量评价。

现代主流做法：

  1. 用 SEO 插件（Rank Math、Yoast SEO 等）开启「将附件 URL 重定向到媒体文件本身」或直接重定向到文章，使附件页不再作为独立页面被索引。
  2. 插入图片时「链接到」默认选「无」或「媒体文件」，不要主动链接附件页面。
  3. 确实需要图片落地页（如摄影作品配长说明）时，认真填写描述字段，让附件页有实质内容。

操作方法：关闭附件页索引（以 SEO 插件为例） ​

  1. 确认已安装并完成引导的 SEO 插件（Yoast SEO 或 Rank Math，插件用法见第 20 章）。
  2. Yoast SEO：后台「SEO → 搜索外观（Search Appearance）→ 媒体（Media）」，开启「将媒体与附件 URL 重定向到附件本身」（Redirect attachment URLs to the attachment itself）。
  3. Rank Math：后台「Rank Math → 常规设置（General Settings）→ 链接（Links）」，开启「重定向附件（Redirect Attachments）」类开关（不同版本菜单文字略有差异，以界面为准）。
  4. 保存后，用无痕窗口访问一张图片的附件页 URL，应自动跳转到图片文件或其所属文章。
  5. 未安装 SEO 插件时，最简做法是插入图片一律「链接到：无」，并不在任何位置主动发布附件页链接。

常见问题 ​

  • 问：重定向后图片还能在文章里正常显示吗？ 答：完全不影响。重定向的只是「附件页面」这个 HTML 地址，文章中的 <img> 引用的是图片文件本身。

8.9 文件规范：上传前的 5 条纪律 ​

  1. 文件名小写、连字符、语义化：wordpress-hosting-pricing-table.png，不要 IMG_3829.JPG、最终版2(3).png、中文+空格文件名。语义化文件名本身也是图片 SEO 信号。
  2. 控制像素尺寸：正文配图长边不超过 2560px；全屏横幅可到 1920-2560px；图标、插图按需更小。相机直出 6000px 的图先缩放再传。
  3. 先压缩再上传：用本地工具（Squoosh、ImageOptim 等）压到肉眼无损，照片类 JPG/WebP 单图建议控制在 200-400KB 以内。
  4. 避免 10MB 以上的图：既耗空间又拖慢上传与备份；上传限制与内存报错见 8.13 节。
  5. PDF 同样规范命名：wp-academy-beginner-guide.pdf，正文用「文件」区块做下载卡片，并手写一句文件大小与页数提示。

8.10 图片优化工具链 ​

即使有纪律，批量内容仍建议引入自动化优化。常见商业/免费优化插件有 ShortPixel、Imagify、EWWW Image Optimizer 等（具体套餐价格与额度以官方页面为准，不在这里杜撰），它们通常提供：

  • 上传时自动压缩（有损/无损可选）、历史媒体批量压缩。
  • 生成 WebP / AVIF 现代格式并在前台按浏览器支持自动输出。
  • 保留原图、可一键回退。

格式选择事实：

格式优势局限
JPG兼容性最好，照片色彩好不支持透明，压缩率一般
PNG支持透明与锐利文字/截图照片体积大
GIF动图色彩少、体积大，动图更推荐视频/WebP
WebP同等画质体积约为 JPG/PNG 的六七成，现代浏览器全面支持极旧环境不支持（核心会回退）
AVIF压缩率更高，适合高质量照片编码慢，需服务器图像库支持，老旧浏览器不兼容

AVIF 生成依赖服务器 GD/Imagick 编译支持，虚拟主机不支持时由优化插件在其云端完成转换。完整的懒加载、CDN、Core Web Vitals 内容在第 30 章与第 33 章。

操作方法：上传前本地压缩（零插件方案） ​

  1. 浏览器打开 Squoosh（squoosh.app）或在本地启动 ImageOptim 类工具。
  2. 拖入原图，右侧选择格式：照片选 WebP（或 AVIF），截图/图标对比 PNG 与 WebP 取更小者。
  3. 拖动质量滑块，在「肉眼无差别」前提下尽量压低体积，观察左右对比与体积百分比。
  4. 调整 Resize 选项，把长边限制在 2560px 以内。
  5. 下载处理后的文件，按 8.9 节规范命名后上传。

操作方法：配置一个自动压缩插件 ​

  1. 在「插件 → 安装插件」搜索并安装一款优化插件（ShortPixel、Imagify、EWWW 任选其一，插件安装通用流程见第 17 章）。
  2. 启用后进入其设置向导，按提示注册/填入 API 密钥（多数插件提供免费额度）。
  3. 压缩模式选择「有损（Lossy）」用于绝大多数照片；对要求极高的印刷类图选「无损（Glossy/Lossless）」。
  4. 开启「创建 WebP/AVIF 版本并前台自动输出」；开启「上传时自动压缩」。
  5. 进入「批量优化（Bulk Optimization）」，对历史媒体执行一次批量压缩；运行期间不要关闭浏览器标签（可在后台继续其他工作）。
  6. 抽查文章前台图片，确认格式按浏览器正确切换、清晰度可接受。

常见问题 ​

  • 问：压缩插件会不会把原图删了无法恢复？ 答：主流插件默认保留原图并可在设置中「一键恢复」；开启前仍应先完成整站备份（第 34 章），尤其是第一次批量压缩前。

8.11 音频与视频：上传还是嵌入 ​

原理说明 ​

  • 自托管上传：文件存在你自己的服务器，用音频/视频区块播放。成本是你的存储空间与带宽：一个 5 分钟 1080p 视频就可能上百 MB，一千人观看就是上百 GB 流量，主机套餐可能直接超限，且没有清晰度自适应。
  • 平台嵌入（oEmbed）：在编辑器空段落粘贴 YouTube 等平台的视频 URL，WordPress 通过 oEmbed 协议自动转成播放器，带宽由平台承担。官方白名单内的平台包括 YouTube、Vimeo、Twitter/X、Flickr、 TED 等主流海外服务。
  • B 站等国内平台：不在 oEmbed 白名单中，直接粘 URL 不会变播放器。需要用「自定义 HTML」区块粘贴平台提供的嵌入代码（iframe），或使用支持国内平台的嵌入插件。注意 iframe 嵌入同样可能拖慢页面，建议配合懒加载。
  • 播客：上传 MP3 到媒体库配合音频区块即可开播起步；封面图建议正方形 1400×1400 以上的 JPG/PNG；规模化分发请接入播客托管平台与 RSS Feed 插件。

决策很简单：能嵌入就不自托管，自托管只用于短视频、教程录屏、需要完全控制版权的内容。

操作方法：嵌入 YouTube 等平台视频 ​

  1. 在视频平台打开目标视频，复制浏览器地址栏的完整 URL（不是「嵌入代码」）。
  2. 回到区块编辑器，在空段落里直接粘贴 URL，或插入「嵌入」（Embed）区块后粘贴。
  3. WordPress 自动识别并渲染出播放器预览；在区块设置里可调整是否允许全屏、播放器宽高比。
  4. 更新文章后前台检查：视频不占用你的服务器带宽，播放清晰度由平台自适应。

操作方法：嵌入 B 站视频（自定义 HTML） ​

  1. 在 B 站视频页点击「分享 → 嵌入代码」，复制以 <iframe> 开头的代码片段。
  2. 在编辑器中插入「自定义 HTML」（Custom HTML）区块。
  3. 把 iframe 代码粘贴进去，切换到「预览」模式确认播放器出现。
  4. 在区块外包一个「组」并设置最大宽度（如 800px），避免 iframe 在桌面端撑得过宽。
  5. 更新后前台实测播放；若站点有内容安全策略（CSP），需在安全头中允许对应视频域名（运维内容见第 32 章）。

常见问题 ​

  • 问：粘贴 YouTube 链接没有变成播放器？ 答：确认 URL 是视频页地址且未带多余文字；该平台不在 oEmbed 白名单、或服务器无法发起出站请求（curl 被禁/防火墙拦截）时也会失败，改用 iframe 嵌入。
  • 问：自托管视频如何防止被人盗链直链？ 答：需要在服务器层做 Referer 校验或签名 URL，核心本身不提供视频鉴权；这类需求更适合直接使用视频托管平台。

8.12 文件访问、直链与媒体库整理 ​

访问权限与直链 ​

  • wp-content/uploads/ 下的文件由 Web 服务器直接提供（静态文件），任何拿到完整 URL 的人都可以直接访问，WordPress 的登录限制管不到这些直链。不要把真正保密的文件放进 uploads，需要访问控制请用会员/下载管理类插件（文件经 PHP 鉴权后输出）。
  • 服务器目录权限推荐 755（目录）/644（文件），属主为运行 PHP 的账户，详见第 32 章。

删除媒体的注意事项 ​

删除附件只删除附件记录与文件，不会自动删除文章中的 <img> 引用——老文章里会留下坏图死链。删除前：

  1. 在附件详情查看「上传到」字段，确认它被哪些文章使用。
  2. 用 Media Cleaner 一类插件扫描未引用文件辅助清理（删除前先备份）。
  3. 定期整理流程：补全替代文本 → 删除重复与未引用附件 → 重建缩略图 → 压缩老图。

8.13 常见问题速查 ​

8.13.1 上传报「超过 upload_max_filesize / post_max_size」 ​

报错信息（英文/中文大意）对应限制解决
exceeds the upload_max_filesizePHP upload_max_filesize 太小调大该值
exceeds the post_max_sizePHP post_max_size 太小调大，且应 ≥ upload_max_filesize
页面刷新后什么都没发生也可能是 max_execution_time/max_input_time 过短一并调大

本地环境改 php.ini（XAMPP/MAMP 面板有入口）；虚拟主机在面板的 PHP 设置中调整；推荐生产值见 examples/config/php.runtime.ini：

ini
; 上传与请求体大小，按业务调整，二者保持 post >= upload。
upload_max_filesize = 32M
post_max_size = 64M
max_execution_time = 120
memory_limit = 256M

8.13.2 大图上传中途报「HTTP error」 ​

典型原因：PHP 内存不足，或服务器图像扩展（Imagick）处理大图时不稳定，回退到 GD 后成功。处理顺序：调大 memory_limit（256M 起）；要求主机确认 Imagick 版本与资源限制；先用本地工具把图缩到 2560px 长边再上传，90% 的 HTTP error 因此消失。

8.13.3 SVG 上传被拒绝 ​

这是安全特性不是故障：SVG 是 XML，可内嵌脚本，低权限作者上传恶意 SVG 可导致 XSS。确需使用时：仅对管理员开放，安装可净化 SVG 的安全插件，或在本地导出 SVG 时手工检查不含 <script> 与 on*= 事件属性。

8.13.4 苹果 HEIC/HEIF 照片 ​

iPhone 默认拍摄格式为 HEIC，WordPress 与多数浏览器不支持。解决：iPhone「设置 → 相机 → 格式」选「兼容性最佳」（拍照即为 JPG）；或用本地工具转换后上传；浏览器端转换插件也可辅助。

8.13.5 中文文件名乱码 ​

服务器区域设置（locale）或老旧 FTP 工具可能导致中文文件名在磁盘上乱码，进而产生坏链。根治办法就是 8.9 节的纪律：上传前改为英文连字符文件名；已经乱码的文件重新命名并替换文章引用。

8.13.6 uploads 目录权限不对导致无法上传 ​

典型报错：「无法将文件写入磁盘 / Unable to create directory」。检查目录属主与权限：目录 755、文件 644，属主为 PHP 运行账户；不要为图省事把整个 uploads 设成 777，那等于向所有写入者敞开大门。命令与检查流程见第 32 章。

本章总结 ​

  1. 媒体 = 数据库附件记录（wp_posts + wp_postmeta）+ 磁盘文件（uploads/年/月/），二者分离；FTP 上传不会自动入库，直接删文件会留死链。
  2. 白名单控制可传类型：JPG/PNG/GIF/WebP 默认可用，AVIF 需 6.5+ 与图像库支持，SVG 默认禁止是防 XSS；ALLOW_UNFILTERED_UPLOADS 不应在普通站点开启。
  3. 四字段各司其职：替代文本面向无障碍与 SEO 必写，图片标题是图注，描述用于附件页，标题用于后台与提示；插入时明确对齐、链接目标与尺寸。
  4. 上传即生成多尺寸文件，主题可用 set_post_thumbnail_size()/add_image_size() 扩展，前台自动输出 srcset 响应式图片；旧尺寸用插件重建。
  5. 图片治理靠工作流：语义化英文文件名、2560px 长边、上传前压缩、WebP/AVIF 自动化、附件页重定向、定期清理未引用媒体；视频优先嵌入平台，B 站用自定义 HTML。

动手练习 ​

练-08-01：做一次媒体库大扫除 整理本地站点媒体库：为所有图片补全替代文本（每张至少检查一遍）；找出 2 张重复上传的图片（-1 后缀或肉眼重复）并删除其中无引用的一份；删除一个测试附件后观察原文章中的死链，再恢复或替换；把整个过程写成检查清单。

练-08-02：用测速工具观察未优化图片的代价 插入一张未经处理的相机直出大图（长边 4000px 以上、体积 5MB 左右）到测试文章，用浏览器开发者工具 Network 面板与 PageSpeed Insights 观察首屏体积；再把同图压到 2560px、WebP 后替换，对比传输体积与加载时间，记录两组数据。

练-08-03：注册并输出一个自定义图片尺寸 在配套主题（或子主题）的 functions.php 中按 8.5 节代码注册一个名为 wp-academy-card 的尺寸（640 宽等比），刷新后台确认无报错；上传一张新图后到 uploads/年/月/ 目录确认新尺寸文件生成；再安装重新生成缩略图插件，为一张旧图补齐该尺寸。

练-08-04：为 PDF 制作下载卡片 准备一份 PDF，按规范命名（英文连字符）后上传；在一篇文章中用「文件」区块插入，设置下载按钮文字，手动补充文件大小与页数说明；再尝试把同一份 PDF 改用封面图 + 按钮区块做一张更美观的下载卡片，对比两种方案在前台的呈现差异。
