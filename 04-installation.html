第 4 章 标准安装流程 ​

🟢 入门难度 ｜ 一句话导览：从下载程序、上传文件、创建数据库，到填写 wp-config.php、走完五分钟向导、完成安装后必做设置，本章把 WordPress 最标准的一次安装拆成可照做的点击级步骤，并附上 WP-CLI 自动化装法。

学习目标 ​

  • 能对照安装前检查清单确认环境、域名、HTTPS 与 PHP 扩展是否就绪
  • 会通过下载页获取最新版/中文版程序，了解两种中文化路径的区别
  • 至少掌握一种上传方式（SFTP / 面板文件管理器 / WP-CLI）与一种建库方式（cPanel / phpMyAdmin / SQL）
  • 理解 wp-config.php 每一行的含义，尤其表前缀与 8 个盐值的安全意义
  • 能独立走完图形化安装向导，并完成安装后的 7 项必做设置
  • 会用 WP-CLI 完成无人值守安装，理解自动化部署的基本链路

4.1 安装前检查清单 ​

4.1.1 原理说明 ​

WordPress 安装失败或安装后出怪问题，九成以上源于「环境没备好就开装」。安装向导本身只是把数据库表建好、写入初始数据，它不会替你安装 PHP 扩展或配置 HTTPS。

4.1.2 操作方法：逐项打勾 ​

检查项合格标准不满足时去哪章
Web 服务器 + PHP + 数据库三件套已启动；PHP 8.3（兼容 8.2–8.5）；MySQL 8.0+ 或 MariaDB 10.11+第 02 章本地 / 第 03 章服务器
PHP 扩展mysqli、curl、dom、mbstring、gd/imagick、intl、zip、openssl、exif、fileinfo 等已加载第 03 章 3.5 节

HTTPS 证书正式站已用 certbot 签发或主机商提供证书第 03 章 3.9 节
数据库信息已拿到库名、用户名、密码、主机地址四项；账号对该库有权限本章 4.4 节

4.2 获取 WordPress 程序 ​

4.2.1 原理说明 ​

WordPress 官方同时提供英文最新版与各语言版本。中文用户有两条技术路径，区别只在「语言包什么时候装」，程序内核完全相同：

路径得到什么适合
直接下中文包安装向导即为中文，后台默认简体中文，wp-content/languages 内置中文翻译新手、确定只用中文
下英文包再装语言向导英文起步，安装后在后台「设置 → 常规 → 站点语言」切换，自动下载中文包多语言站、想熟悉英文后台术语

4.2.2 操作方法：下载 ​

  1. 英文最新版：打开 https://wordpress.org/download/，点击大按钮 Download WordPress 7.1.x，得到 wordpress-7.1.x.zip（或 .tar.gz）。
  2. 中文最新版：打开 https://cn.wordpress.org/，点击「获取 WordPress」下载 latest-zh_CN.zip。
  3. 校验完整性（可选但推荐在服务器场景做）：下载页提供压缩包的 SHA-1 校验值，本地计算后与之比对：
bash
# macOS / Linux
shasum -a 1 wordpress-7.1.x.zip
# Windows（PowerShell）
Get-FileHash .\wordpress-7.1.x.zip -Algorithm SHA1

图 04-1：wordpress.org 下载页，蓝色下载按钮与版本号

  1. 解压后得到一个 wordpress 文件夹，里面就是全部程序文件（含 wp-config-sample.php，稍后要复制改名）。

4.2.3 常见问题 ​

  • 问：第三方网站的「中文版 WordPress」能下吗？ 不建议。非官方渠道的安装包可能被篡改植入后门，只从 wordpress.org 或 cn.wordpress.org 获取。
  • 问：本地已有旧版安装包，能直接用吗？ 学习可以，正式安装永远重新下载最新版，避免带着已知漏洞上线。

4.3 上传程序的三种方式 ​

4.3.1 方式一：SFTP 工具上传 ​

原理说明：SFTP 是基于 SSH 的加密文件传输，主机开通 SSH 或提供了 SFTP 账号即可使用，传输过程加密，明文的 FTP 已不推荐。

操作方法（Windows / macOS 通用）：

  1. 下载安装 FTP 客户端：Windows 常用 FileZilla（https://filezilla-project.org/，下载时选免费的 Client）；macOS 常用 Transmit、Cyberduck 或 FileZilla。
  2. 新建站点连接，填写主机商提供的：主机（域名或 IP）、端口（SFTP 通常 22）、协议选 SFTP、用户名、密码（或密钥）。
  3. 点「连接」，首次连接会弹出主机指纹确认，核对后勾选信任。
  4. 左窗格是本地文件，找到解压出的 wordpress 文件夹；右窗格是服务器，进入 Web 根目录（名称因主机而异，见下表）。
  5. 把 wordpress 文件夹内的全部文件（不是文件夹外壳）拖入右窗格，等待传输完成（数千个小文件，需要几分钟）。
环境常见 Web 根目录
cPanel 主机public_html/（主域名）；附加域名多为 public_html/域名/
部分主机商www/、htdocs/、web/
自建 Ubuntu + Nginx/var/www/域名/
XAMPP / MAMPhtdocs/ 下的站点子目录（第 02 章）

熟悉命令行的读者，macOS/Linux 上也可以用 scp/rsync 完成同样的事，rsync 支持断点续传与增量同步，传数千个小文件时体验最好：

bash
# 把本地 wordpress 目录内容同步到服务器 Web 根（注意源路径末尾的 /）
rsync -avz --progress ./wordpress/ user@服务器IP:/var/www/wordpress/
# 单文件/少量文件用 scp 即可
scp wp-config.php user@服务器IP:/var/www/wordpress/

4.3.2 方式二：主机面板文件管理器 ​

  1. 登录 cPanel / 宝塔面板，打开「文件管理器 / Files」（宝塔为「文件」菜单）。
  2. 进入 public_html，点「上传 / Upload」把 zip 包传上去。
  3. 回到文件管理器，右键压缩包选「提取 / Extract」到当前目录。
  4. 若解压出一层 wordpress/ 子目录而你希望站点在根域名访问，全选内层文件移动到 public_html 根下。
  5. 删除服务器上的 zip 包，不留多余文件。

4.3.3 方式三：WP-CLI 直接下载 ​

有 SSH 时最优雅的方式——不用本地下传再上传，WP-CLI 直接在服务器拉取官方程序：

bash
# 进入目标目录后下载中文版程序
wp core download --locale=zh_CN
# 下载英文最新版则省略 --locale
wp core download --version=7.1

WP-CLI 安装方法见 https://wp-cli.org/#installing；完整无人值守流程在 4.9 节。

4.3.4 装在根目录还是子目录 ​

  • 根目录：访问 https://example.com/ 就是网站。绝大多数正式站选这个。
  • 子目录：程序放在 /blog/，网址带前缀。适合主站是别的系统、WordPress 只做博客，或一个主机放多个站。
  • 「网址在根、程序在子目录」的高级玩法（如文件放 /wordpress/ 但访问不带前缀）也支持，第 05 章讲「WordPress 地址与站点地址」的区别时会说明，新手先用默认方式。

4.4 创建数据库 ​

4.4.1 方式一：cPanel「MySQL 数据库向导」 ​

  1. 登录 cPanel，在「数据库」区域找到 MySQL Database Wizard（MySQL 数据库向导），点击进入。
  2. 第 1 步 新建数据库：输入库名（如 wpacademy），cPanel 会自动加用户名前缀，形如 cpaneluser_wpacademy，记下全名。点「下一步」。
  3. 第 2 步 新建用户：输入用户名与强密码（用页面上的密码生成器），同样记下带前缀的全名与密码。点「创建用户」。
  4. 第 3 步 授权：勾选 ALL PRIVILEGES（全部权限），点「下一步」。
  5. 完成。向导结束页会把库名、用户名、主机（通常是 localhost）汇总显示，建议截图存档。

4.4.2 方式二：phpMyAdmin 完整步骤 ​

  1. 在面板中打开 phpMyAdmin（本地 XAMPP 访问 http://localhost/phpmyadmin，MAMP 从 Tools 菜单进入）。

  2. 左侧点击 新建，输入库名 wp_academy，排序规则选 utf8mb4_unicode_ci，点「创建」。

  3. 顶部进入 用户账户 → 添加用户账户：

    • 用户名：wp_academy；主机名：本地填 localhost，容器/远程填对应主机或 %；
    • 密码：生成强密码并保存；
    • 勾选「为用户创建数据库并授予所有权限」（或手动选「创建与用户同名的数据库并授予所有权限」）。

  4. 若手动授权：进入该数据库 → 权限 → 添加用户账户，选中用户后勾选该数据库的「全部权限」，仅对这一个库授权，不授予全局权限。

  5. 核对：左侧能看到新库，用户账户列表里新用户只对 wp_academy.* 有权限。

图 04-2：phpMyAdmin 数据库向导中勾选全部权限并限定到单库

4.4.3 方式三：命令行 SQL ​

服务器有 root 数据库密码时，直接执行教程配套脚本 examples/config/mysql.init.sql（原理与逐行解释见第 03 章 3.7.4 节）：

bash
# 导入建库建用户脚本，执行前把脚本中的密码改为自己的强密码
mysql -u root -p < examples/config/mysql.init.sql

4.4.4 常见问题 ​

  • 主机名填 localhost 还是具体地址？ 数据库与网站在同一台机器通常是 localhost；面板可能显示别的 socket 路径；Docker 等容器网络填服务名（如 db）。以主机商文档为准。
  • 端口要写吗？ 默认 3306 不用写；MAMP 本地是 8889，要写 localhost:8889；非默认端口写作 主机名:端口。

4.5 配置 wp-config.php ​

4.5.1 原理说明 ​

wp-config.php 是 WordPress 与环境之间的「接线图」：数据库凭据、字符集、表前缀、安全盐值、调试开关都在里面。安装向导要求该文件已就绪（向导也会引导你用表单自动生成）。

⚠️ 该文件包含数据库密码与密钥，极其敏感：永远不要提交到 Git 仓库、不要放到可被浏览器直接下载的位置、不要贴进公开的问答社区。配套示例文件 examples/config/wp-config.snippet.php 只放可公开的配置骨架，真实密码通过环境变量或安装时填写注入。

4.5.2 操作方法：逐行配置 ​

  1. 在网站根目录找到 wp-config-sample.php，复制一份并改名为 wp-config.php（保留 sample 不动）。
  2. 用代码编辑器打开 wp-config.php，逐段填写：
php
<?php
/**
 * WordPress 核心配置文件（敏感！勿入库、勿公开）
 * 本片段配合 examples/config/wp-config.snippet.php 学习；
 * 生产环境可通过环境变量读取密码，避免密码落盘到版本库。
 */

// ① 数据库名称（4.4 节创建的库）
define( 'DB_NAME', 'wp_academy' );

// ② 数据库用户名（最小权限业务用户，不用 root）
define( 'DB_USER', 'wp_academy' );

// ③ 数据库密码
define( 'DB_PASSWORD', '这里换成强密码' );

// ④ 数据库主机：本机 localhost；MAMP 本地为 localhost:8889；容器为 db:3306
define( 'DB_HOST', 'localhost' );

// ⑤ 字符集固定 utf8mb4（支持 Emoji 与生僻字，不要改成 utf8）
define( 'DB_CHARSET', 'utf8mb4' );

// ⑥ 排序规则留空，让 WordPress 按字符集自动选择，最不易踩坑
$table_prefix = 'wp9f3a_';   // ⑦ 表前缀：改掉默认 wp_，使用随机字符串
  1. 改掉默认表前缀的安全意义：默认前缀 wp_ 全网皆知，自动化 SQL 注入攻击会直接拼 wp_options、wp_users 等表名。改成随机前缀（如 wp9f3a_）让攻击者无法猜解表名，属于零成本的加固项。注意只能在安装时设定，已有站点改前缀需要改库，第 32 章再讲。
  2. 获取并粘贴 8 个盐值：浏览器打开 https://api.wordpress.org/secret-key/1.1/salt/，页面会生成 8 个随机常量（AUTH_KEY、SECURE_AUTH_KEY、LOGGED_IN_KEY、NONCE_KEY 及对应的 SALT）。整段复制，替换文件中对应的占位段落：
php
// ⑧ 八个盐值：用于加密 Cookie 与签名令牌，每人每站必须不同
// 打开 https://api.wordpress.org/secret-key/1.1/salt/ 整段替换，例如：
define( 'AUTH_KEY',         '粘贴页面生成的随机串' );
define( 'SECURE_AUTH_KEY',  '粘贴页面生成的随机串' );
define( 'LOGGED_IN_KEY',    '粘贴页面生成的随机串' );
define( 'NONCE_KEY',        '粘贴页面生成的随机串' );
define( 'AUTH_SALT',        '粘贴页面生成的随机串' );
define( 'SECURE_AUTH_SALT', '粘贴页面生成的随机串' );
define( 'LOGGED_IN_SALT',   '粘贴页面生成的随机串' );
define( 'NONCE_SALT',       '粘贴页面生成的随机串' );
  1. 开发期可开启调试开关（生产环境保持关闭，第 22 章细讲调试体系）：
php
// 本地/开发：显示错误并写日志，方便排错
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', true );

// 生产：关闭直接显示（日志可保留），避免路径信息暴露给访客
// define( 'WP_DEBUG', false );
  1. 保存文件。中文包/英文包此步骤完全相同。

图 04-3：wp-config.php 填写示意（密码与盐值已打码，表前缀为随机值）

4.5.3 常见问题 ​

  • 问：向导让我自己建 wp-config.php 而不是自动写入，正常吗？ 正常。当服务器上文件不可写（权限安全）时，向导会让你手工创建；按提示把生成的内容原样保存为 wp-config.php 即可。
  • 盐值丢了或怀疑泄露怎么办？ 重新打开 salt 页面整段替换，保存后所有用户登录态失效、需要重新登录（数据不丢），这也是应急「踢掉全部登录」的手段。

4.6 五分钟安装向导 ​

4.6.1 操作方法：逐屏点击 ​

  1. 浏览器访问你的站点地址（如 http://localhost/wordpress 或正式域名），程序检测到未安装会自动进入向导。
  2. 第 1 屏 选择语言：列表中选择「简体中文」，点击「继续 / Continue」。
  3. 第 2 屏 信息预告：提示你准备好数据库四项信息，点「走吧 / Let's go!」。
  4. 第 3 屏 数据库连接表单：填写库名、用户名、密码、主机、表前缀（就是 4.5 节的六项；如果你没手工建配置文件，向导在此收集后会帮你生成）。点击「提交」。

图 04-4：安装向导的数据库连接表单与表前缀字段

  1. 连接成功会出现「好了，运行安装吧！」，点击「运行安装 / Run the installation」。连不上则停在报错页，按 4.10 节排查。

  2. 第 4 屏 站点信息：

    • 站点标题：现在就认真取，之后随时可改；
    • 用户名：千万不要用 admin/administrator/root。用户名会出现在作者归档链接中（默认 /author/用户名/），用 admin 等于把爆破登录的一半答案送给攻击者；用昵称或英文名；
    • 密码：点「生成密码」用强随机密码，存入密码管理器，不要用 123456；
    • 电子邮箱：填能正常收信的邮箱，找回密码、升级通知都靠它；
    • 建议搜索引擎不索引本站点（Discourage search engines）：开发期、本地站勾选；正式上线后记得取消勾选。

4.6.2 常见问题 ​

  • 用户名以后能改吗？ 用户名（登录名）不能在后台直接改，可新建管理员账号后删除旧账号（把内容归属转移给新账号），或用 WP-CLI/数据库处理。所以现在就取好。
  • 站点标题写错了？ 随时在「设置 → 常规」修改，无任何副作用。

4.7 第一次登录与登录态 ​

4.7.1 两个登录入口 ​

  • 后台地址：https://你的域名/wp-admin/
  • 登录表单：https://你的域名/wp-login.php

已登录时访问 wp-admin 直接进入仪表盘；未登录会自动跳到登录页。输入刚创建的用户名与密码，可勾选「记住我 / Remember Me」延长 Cookie 有效期，两周内免登录（不勾则关闭浏览器即失效）。

4.7.2 原理说明：登录态是怎么保持的 ​

登录成功后服务器下发一个加密的身份 Cookie（这正是 4.5 节盐值参与加密的内容），之后每次请求浏览器自动带上它，WordPress 据此认出你。登出 = 服务器作废该 Cookie。因此：在公用电脑上不要勾「记住我」，离开时点头像 →「登出」。

4.8 安装后必做清单 ​

登录后台后，先不要急着发文章，按顺序完成 7 项基础设置（每项的字段详解在第 05 章，这里先照做）：

#设置位置做什么为什么
1设置 → 常规站点标题/副标题核对；语言确认简体中文；时区选 UTC+8 或 Asia/Shanghai时区不对会导致定时发布、评论时间错乱
2设置 → 常规检查 WordPress 地址与站点地址与实际访问地址一致（含 https）不一致会引发重定向循环与样式丢失
3设置 → 固定链接选择「文章名」，自定义结构为 /%postname%/，保存默认 ?p=123 不美观也不利于 SEO；保存动作会生成重写规则
4设置 → 常规日期/时间格式按习惯选择并看预览前台时间显示统一
5文章 → 所有文章打开发表一篇评论并删除默认示例文章「世界，您好！」与「示例页面」「隐私政策草稿」按需保留清除演示数据，避免被搜索引擎收录占位
6评论删除默认评论同上
7设置 → 阅读开发期勾选「建议搜索引擎不索引」；上线前取消勾选防止半成品被收录，也防止上线后忘了开放

操作要点（固定链接为例）：

  1. 左侧菜单点击「设置 → 固定链接」。
  2. 单选框选「文章名 / Post name」。
  3. 滚动到底部点击「保存更改」（页面提示「已保存」）。

4.9 WP-CLI 无人值守安装 ​

4.9.1 原理说明 ​

WP-CLI 是 WordPress 官方命令行工具（https://wp-cli.org/），把后台点击变成可重复执行的命令。批量建站、CI/CD 自动部署、服务器无图形界面时，它是唯一靠谱的方式。教程配套初始化脚本 examples/bin/setup.sh 就是这套命令的封装。

4.9.2 操作方法：四步等价安装 ​

bash
# 第 1 步：下载程序（--locale 指定中文版）
wp core download --locale=zh_CN --path=/var/www/wordpress

cd /var/www/wordpress

# 第 2 步：根据数据库信息生成 wp-config.php
# --dbprefix 使用随机前缀；--skip-check 可在数据库稍后就绪时使用
wp config create \
  --dbname=wp_academy \
  --dbuser=wp_academy \
  --dbpass='强密码' \
  --dbhost=localhost \
  --dbcharset=utf8mb4 \
  --dbprefix="wp$(head -c 4 /dev/urandom | od -An -tx1 | tr -d ' \n')_" \
  --force

# 第 3 步：创建数据库（账号有建库权限时；库已存在可跳过）
wp db create

# 第 4 步：执行安装，等价于向导最后两屏
wp core install \
  --url="https://example.com" \
  --title="我的 WordPress 站点" \
  --admin_user="不用admin的名字" \
  --admin_password="强密码" \
  --admin_email="you@example.com" \
  --skip-email

安装后常用收尾命令（对应 4.8 节必做清单）：

bash
wp option update blog_public 0                    # 开发期：阻止搜索引擎索引（上线改回 1）
wp rewrite structure '/%postname%/' --hard       # 设置文章名固定链接并刷新重写规则
wp option update timezone_string 'Asia/Shanghai' # 时区
wp option update default_comment_status 'open'   # 评论默认值等更多选项见第 05、10 章
wp post delete 1 2 --force                       # 删除默认文章(id=1)与示例页面(id=2)
wp plugin list                                   # 查看已装插件
wp core version                                  # 查看当前版本

在教程 Docker 环境中，以上命令通过 docker compose run --rm wpcli ... 在容器内执行；直接运行 ./bin/setup.sh 会自动完成「建配置 → 安装 → 设置固定链接/时区 → 激活教学主题与插件」全过程。

4.9.3 常见问题 ​

  • wp 命令找不到：未安装 WP-CLI 或不在 PATH；Docker 用户改用 docker compose run --rm wpcli。
  • 远程执行提示语言包下载失败：服务器无法访问 wordpress.org，检查出网防火墙；企业内网需配置代理。

4.10 常见问题速查 ​

4.10.1 「建立数据库连接时出错」（Error establishing a database connection） ​

原理说明：wp-config.php 里的四项信息无法让 PHP 连上数据库，或连上了但库/权限不对。按下面四步顺序排查，覆盖 99% 的情况：

  1. 查凭据：打开 wp-config.php，逐项核对 DB_NAME、DB_USER、DB_PASSWORD，注意复制时带没带空格、密码大小写；命令行用同凭据测试：
bash
# 能登录说明凭据正确；连不上报错会说明是密码错还是账号不存在
mysql -u wp_academy -p -h localhost wp_academy
  1. 查主机地址与端口：DB_HOST 是否应为 localhost、127.0.0.1、localhost:8889（MAMP）或 db:3306（容器）；注意 localhost 在部分驱动下走 socket，而 127.0.0.1 走 TCP，二者可能表现不同。
  2. 查用户权限：用户是否被授权访问该库（cPanel 向导的第 3 步、phpMyAdmin 的授权页）；用第 3 章 SQL 复查 GRANT。
  3. 查数据库服务：服务是否启动？XAMPP/MAMP 面板灯是否绿色？Linux 执行 sudo systemctl status mysql；Docker 执行 docker compose ps 看 db 容器是否 healthy。

4.10.2 安装页/后台样式丢失、重定向循环 ​

  • 站点 URL 与实际地址不一致：wp-config.php 或数据库里的地址是 http:// 而实际用 https://，或域名带不带 www 不一致。核对「WordPress 地址（WP_HOME/WP_SITEURL）」与浏览器实际地址，两处必须一致。
  • 反向代理端口错位：站点在 8080/8443 等非标准端口、经 Nginx 反代到标准端口时，WordPress 可能用内部端口拼链接。在反代配置中透传 X-Forwarded-Proto 与 X-Forwarded-Port，并在 wp-config.php 告知信任代理（第 32 章给片段）。
  • 临时核对/修正命令：
bash
wp option get siteurl
wp option get home
# 改成实际地址（正式迁移的搜索替换不能用简单 SQL，见第 36 章）
wp option update siteurl 'https://example.com'
wp option update home 'https://example.com'

4.10.3 后台要求填写 FTP 凭据 ​

在线安装主题/插件时弹出「主机名/用户名/密码」FTP 表单，原因是 PHP 运行用户对 wp-content 没有写权限，WordPress 退回到 FTP 方式写文件。两种解法：

  1. 正解（生产推荐）：把目录属主改为 PHP 运行用户（如 www-data）并设 755/644：
bash
sudo chown -R www-data:www-data /var/www/wordpress
find /var/www/wordpress -type d -exec chmod 755 {} \;
find /var/www/wordpress -type f -exec chmod 644 {} \;
  1. 本地/可信环境：在 wp-config.php 加 define( 'FS_METHOD', 'direct' ); 强制直接写文件。生产环境慎用——它掩盖了权限配置问题，必须确保目录权限本身正确。

4.10.4 内存耗尽白屏 ​

报错形如 PHP Fatal error: Allowed memory size of ... bytes exhausted：按第 03 章把 FPM 的 memory_limit 提到 256M/512M 并重启 FPM；临时也可在 wp-config.php 加 define( 'WP_MEMORY_LIMIT', '256M' );（不能超过系统硬限）。

4.10.5 HTTP/HTTPS 混合内容导致样式丢失 ​

站点切到 HTTPS 后，数据库里旧文章的图片地址仍是 http://，浏览器拦截「混合内容」，表现为图片不显示、样式部分丢失。修正要对数据库中序列化数据做安全替换，不能直接 SQL replace——第 36 章专门讲解，工具是 WP-CLI：

bash
# 预告：第 36 章详讲序列化数据为什么不能用裸 SQL 替换
wp search-replace 'http://example.com' 'https://example.com' --dry-run
